# Prompt structure — explained

## The intuition
A chat request is a small document with roles: `system` holds the rules, `user` holds data, earlier `assistant` turns are examples the model imitates.

`prompt_structure.py` sends one review three ways; the output tightens from a chatty sentence to a bare label to the exact casing of the examples.

Analogy: briefing a contractor. A: a hallway chat. B: a written spec. C: a spec plus two finished samples and a clearly labelled box "the material to work on".
Where the analogy breaks: a model mostly pattern-matches, so wrong examples are copied just as faithfully.

```
A: [user]                              ─▶ sentence
B: [system][user]                      ─▶ label
C: [system][user][asst][user][asst][user:<review>] ─▶ LABEL
```

The one thing to remember: rules go in `system`, format is taught by examples, and data goes inside delimiters.

## Walkthrough: what actually happens when you run it
1. **You run** `python prompt_structure.py`.
   **What happens inside:** the fake counts sentiment words; with a `system` message it returns only the label, upper-cased if the last example is.
   **What you see:**
   ```
   [A user-only] -> Sure! Reading the review carefully, I would say the overall sentiment is negative. Let me know if you want a more detailed analysis.
   [B system+user] -> negative
   [C few-shot+delimiters] -> NEGATIVE
   ```
   **What it means:** A is correct but unparseable; B is parseable; C matches a format you chose. Expected (not run here): with `qwen2.5:1.5b` A is a sentence, B usually one word, C usually `NEGATIVE` — small models do not always comply, so run 2–3 times.

2. **You run** `python -m unittest -v test_try_it_03`.
   **What happens inside:** test 1 lower-cases the example answers; test 2 deletes the system message from C.
   **What you see:**
   ```
   observed: negative
   observed: Hello from fake-model! You said: '<review>The battery died after two days and support never answered my emails.</r'
   ```
   **What it means / what would look wrong:** examples define format. Without the system message the task word "sentiment" is gone, so the fake falls to its echo rule (cut at 80 characters). A real model would guess a task from the examples — and might look right by accident.

## Common confusions
**Q:** Few-shot examples teach the model the task. — **A:** Here they teach the *format*; removing the system message (try-it 2) loses the task entirely.

**Q:** Delimiters make prompt injection impossible. — **A:** They mark data as data, which helps; lesson 16 shows they are not a security boundary.

**Q:** B's `negative` is safe to parse blindly. — **A:** Validate in code (lesson 4); real models add punctuation.
