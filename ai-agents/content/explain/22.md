# An incident-triage agent — explained

## The intuition
The capstone is not a new idea; it is every earlier lesson wired into one pipeline, each doing the one job it is good at. Facts come through read-only MCP tools (lesson 10). Runbooks come from retrieval with checked citations (7). The model writes a *proposal* — cause, runbook, severity, actions — through a retrying, falling-back client (14), validated by schema and action allow-list (8, 20). `policy.decide()` sets severity and actions from metrics alone (20). Rollbacks wait for the incident lead, with a 4 h deadline (18). Effects carry `incident:action` idempotency keys (15). Every step is a span (13), and an eval gate guards decisions in CI (12).

Analogy: an on-call runbook executed by a careful junior: reads dashboards, finds the runbook page, suggests what to do — and the escalation matrix, not the junior, decides who gets paged.
Where the analogy breaks: this junior may follow instructions planted in a log line, so its suggestion is never an input to the decision.

```
alert ─▶ facts (MCP: metrics, logs, deploy) ─▶ retrieve runbooks (top-2)
      ─▶ propose (model; fallback; validated) ─▶ decide (policy.py, metrics only)
      ─▶ approval? (rollback, ≤ 4 h) ─▶ effects (key incident:action) ─▶ history row + span
```

The one thing to remember: the model's proposal can be wrong, hostile or missing, and the decision is still correct.

5. **You run** `python -m unittest -v test_try_it_22`.
   **What you see:**
   ```
   observed: executed ['page_oncall', 'rollback_deploy'], effects 2, rollbacks_without_approval 0
   observed: approval rejected, executed ['page_oncall', 'rollback_deploy'], rollbacks_without_approval 1, pass False
   ```
   **What it means / what would look wrong:** when the lead approves, the rollback runs — a human decision. Remove `rollback_deploy` from `NEEDS_APPROVAL` and a *rejected* rollback executes; the scorecard turns `pass False`.

Expected (not run here): with a real model and embedding model, `model_disagreed` and template use will be higher and runbook choices noisier; the rubric rows that must not move are severity_by_policy 8, duplicate_effects 0, rollbacks_without_approval 0.

## Common confusions
**Q:** The model triages the incident. — **A:** It proposes; `policy.decide()` triages. INC-7 had no model.

**Q:** Grounded citations make the proposal trustworthy. — **A:** INC-6 cited a real runbook *and* proposed `delete_cluster`.

**Q:** Approval is a UI feature. — **A:** It is a workflow step with a deadline; try-it 2 shows what breaks without it.
