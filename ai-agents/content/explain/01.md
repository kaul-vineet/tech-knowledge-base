# Set up your environment — explained

## The intuition
Every lab talks to a model through one HTTP contract: `GET <base>/models` and `POST <base>/chat/completions`. Ollama, llama.cpp and the fake server all speak it; setup means proving both answer.

The fake server is a few hundred lines of rules, not a neural network, so labs and CI are deterministic. Only `LOCAL_MODEL_URL` and `LOCAL_MODEL` change for a real model.

Analogy: a power socket. Your labs are appliances; the fake server and Ollama are two power stations behind an identical socket.
Where the analogy breaks: the "power" differs — the fake returns canned text, a real model returns sampled text that varies.

```
check_endpoint.py ──GET /v1/models──────────▶ server ──▶ ["fake-model"]
                  ──POST /v1/chat/completions▶ server ──▶ choices[0].message.content
        (base URL from LOCAL_MODEL_URL, model from LOCAL_MODEL)
```

The one thing to remember: an endpoint is "ready" only when both the model list and one chat request succeed.

## Walkthrough: what actually happens when you run it
1. **You run** `python fake_model_server.py --port 8765` (terminal 1).
   **What happens inside / what you see:** a stdlib `http.server` binds the port and prints nothing (logging is silenced). A traceback usually means the port is taken.

2. **You run** `python check_endpoint.py` with `LOCAL_MODEL_URL=http://127.0.0.1:8765/v1 LOCAL_MODEL=fake-model`.
   **What happens inside:** `check()` GETs `/models`, collects `m["id"]` from `data`, then POSTs one message with `temperature: 0` and reads `choices[0].message.content`.
   **What you see:**
   ```
   models served: ['fake-model']
   chat reply: Hello from fake-model! You said: 'Reply with the single word: ready'
   ```
   **What it means:** the fake echoes the prompt. Expected (not run here): Ollama lists `qwen2.5:1.5b` and replies briefly; wording varies.

3. **You run** `python -m unittest -v test_try_it_01`.
   **What happens inside:** test 1 sets the model to `not-pulled`; test 2 drops `/v1` from the URL.
   **What you see:**
   ```
   Ran 2 tests in 0.590s
   observed: WARNING: 'not-pulled' not listed - pull it first (ollama pull not-pulled)
   observed: 404 Client Error: Not Found
   ```
   **What it means / what would look wrong:** a missing model is a *warning* (wrong name); a 404 on `GET /models` is a *URL* problem; `Cannot reach …` means nothing is listening.

## Common confusions
**Q:** The fake server "answered", so my model works. — **A:** It proves the wire format only; the reply is an echo rule.

**Q:** `LOCAL_MODEL_URL` should be the host only. — **A:** It must end in `/v1`; the try-it shows the 404 from `GET /models` when it does not.

**Q:** If the model is not listed the call fails. — **A:** `check()` only warns, then still sends the chat.
