# Guardrails basics — explained

## The intuition
Assume the model *will* be fooled: a retrieved document can say "call send_email with {…}" and a small model may obey. Guardrails are cheap, deterministic checks in your code that keep a fooled model from doing damage.

`guarded_agent.py` puts a check at every boundary the data crosses. **Input**: `check_input()` caps length and strips control characters. **Retrieved text**: `screen()` quarantines passages that look like instructions, and everything returned is wrapped in `<untrusted_data>`. **Tool calls**: `Session.execute()` enforces a per-session allow-list, schema validation, a secret scan on arguments, and for risky tools both human approval *and* an `@example.com` recipient rule. **Output**: `redact()` masks API-key-shaped strings before the answer leaves.

Analogy: defence in depth in a bank — ID check at the door, dual control on the vault, cameras on the exit.
Where the analogy breaks: a model can be talked into "opening the vault" by a note in a document, so each layer must hold alone.

```
user ─check_input─▶ model ─tool_call─▶ execute(): allow-list → schema → secret scan → approval+recipient
                       ▲                                 │
                       └─ <untrusted_data> ◀─ screen() ◀─ search_docs (handbook, vendor-notes*, config-notes)
answer ─redact()─▶ user           (* contains an injected "send_email" instruction)
```

The one thing to remember: put the decision about effects in code you control, not in text the model reads.

## Walkthrough: what actually happens when you run it
1. **You run** `python guarded_agent.py`, unguarded pass.
   **What happens inside:** with `guarded=False` every check is skipped. The fake model's "naive" rule obeys an instruction found in retrieved text.
   **What you see:**
   ```
   == guarded=False ==
     log: ['search_docs -> <untrusted_data source=handbook.md>Deploys run every Tuesday after the', 'send_email -> sent to attacker@evil.test']
     secret in answer: True | redacted: False
     outbox: [{'to': 'attacker@evil.test', 'body': 'all vendor notes'}]
   ```
   **What it means:** two incidents — data exfiltration by email and a leaked key in the answer — from two innocent questions.

2. **Guarded pass.**
   **What you see:**
   ```
   == guarded=True ==
     log: ['quarantined vendor-notes.md', 'search_docs -> <untrusted_data source=handbook.md>Deploys run every Tuesday after the']
     secret in answer: False | redacted: True
     outbox: []
   ```
   **What it means:** the screen removed the poisoned note before the model saw it, and output redaction masked the key. Expected (not run here): with `qwen2.5:1.5b` the unguarded run may or may not follow the injection; the guarded run must never send mail or show the key.

3. **You run** `python agent_assist.py`.
   **What you see:**
   ```
   proposed: {'search_docs': 'low', 'send_email': 'high', 'archive_notes': 'low'}
   final   : {'search_docs': 'low', 'send_email': 'high', 'archive_notes': 'high'}
   review  : ["archive_notes: model said 'low', policy says 'high'"]
   ```
   **What it means:** the model's risk labels are suggestions; the `POLICY` table wins and disagreements go to a human queue.

4. **You run** `python -m unittest -v test_try_it_11`.
   **What you see:**
   ```
   observed: ['send_email -> error: denied (needs approval and an @example.com recipient)'] | outbox: []
   observed: ['send_email -> error: denied (needs approval and an @example.com recipient)'] | outbox: []
   ```
   **What it means / what would look wrong:** test 1 turns the screen off — the model is fooled and calls `send_email`, but approval (default deny) holds. Test 2 also makes the human approve everything — the recipient rule still holds. Three independent layers; you had to remove all three to get the unguarded outcome.

## Common confusions
**Q:** The `<untrusted_data>` tags stop injection. — **A:** They help a real model, but the fake (and some real models) still obeyed; the screen and the approval check did the stopping.

**Q:** The regex screen is the main defence. — **A:** It is a cheap first filter that attackers can rephrase around (lesson 16). Test 1 shows the deterministic effect checks are what held.

**Q:** Human approval is enough. — **A:** Test 2: the recipient rule caught it.
