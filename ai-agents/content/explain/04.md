# Structured output — explained

## The intuition
Your program wants a dictionary; a model emits text. The bridge has three layers: *ask* (schema in the prompt), *constrain* (`response_format: json_schema` restricts the server's tokens), *check* (your `validate()`). Only the third is a guarantee.

On failure, `extract_person()` appends the bad reply plus the exact error and asks again, at most `max_attempts` times.

Analogy: a web form — placeholder, input mask, server-side validation.
Where the analogy breaks: a form never invents a value; a model can return a perfectly valid shape with a wrong age.

```
prompt ─▶ model ─▶ json.loads ─▶ validate() ──ok──▶ (obj, attempt)
            ▲                        │errors
            └──── "Invalid: …" ◀─────┘  (max_attempts, then ValueError)
```

The one thing to remember: model JSON is untrusted input until your validator returns an empty error list.

## Walkthrough: what actually happens when you run it
1. **You run** `python structured_output.py` (prompt-only mode first).
   **What happens inside:** the fake first wraps the JSON in prose and a fence; `json.loads` fails; the error goes back; reply 2 is bare JSON.
   **What you see:**
   ```
   prompt-only (parse + validate + retry):
     attempt 1: ['not valid JSON (Expecting value)']
     attempt 2: OK
     result: ({'name': 'Maria', 'age': 34, 'city': 'Lisbon'}, 2)
   ```
   **What it means:** strict parsing plus one retry recovered a common real failure (chatty fences).

2. **Same run**, second mode with `response_format`.
   **What you see:**
   ```
   with response_format json_schema:
     attempt 1: OK
     result: ({'name': 'Maria', 'age': 34, 'city': 'Lisbon'}, 1)
   ```
   **What it means:** constraining saved a round trip. Expected (not run here): Ollama documents `response_format` on `/v1`; expect 1 attempt there, 1–2 prompt-only.

3. **You run** `python -m unittest -v test_try_it_04`.
   **What you see:**
   ```
   observed: ValueError: no valid JSON after 1 attempts
   observed: attempt 1: ['not valid JSON (Expecting value)'] | attempt 2: ['age must be an integer 0-150'] | attempt 3: ['age must be an integer 0-150']
   ```
   **What it means / what would look wrong:** one attempt repairs nothing. Without the age the fake returns `"age": null`; retrying cannot add missing information, so the loop ends in `ValueError` instead of a made-up number — desired. A real model might *invent* an age and pass validation.

## Common confusions
**Q:** With `response_format` I can drop `validate()`. — **A:** No; it guarantees shape, not truth.

**Q:** More retries always help. — **A:** Try-it 2 shows attempts 2 and 3 failing identically; the input lacks the data.

**Q:** A failed parse means wrong data. — **A:** Attempt 1 was correct JSON inside a fence.
