# Call a model over HTTP — explained

## The intuition
A chat model behind `/v1/chat/completions` is a stateless function: JSON in, JSON out. You send the *whole* conversation as a list of `{"role", "content"}` messages; it returns one new assistant message plus metadata (`finish_reason`, `usage`). Nothing is remembered between calls — if you want history, you resend it.

So `call_model.py` needs no SDK: one `requests.post`, one `raise_for_status()`, one lookup of `choices[0].message.content`.

Analogy: a stateless REST endpoint like a tax calculator — same inputs, (roughly) same output, no session.
Where the analogy breaks: with `temperature > 0` a real model samples, so identical inputs can give different text.

```
messages[] ──▶ POST /v1/chat/completions {model, messages, temperature, max_tokens}
                         │
                         ▼
   {"choices":[{"message":{"content":…},"finish_reason":"stop"}], "usage":{…}}
```

The one thing to remember: the conversation lives in your `messages` list, not in the model.

## Walkthrough: what actually happens when you run it
1. **You run** `python call_model.py` (fake server on 8765).
   **What happens inside:** `chat()` builds `{"model", "messages", "temperature": 0.0, "max_tokens": 200}` and POSTs it. The fake's `_reply()` finds no special rule and echoes; it counts words as "tokens".
   **What you see:**
   ```
   reply        : Hello from fake-model! You said: 'Say hello in one short sentence.'
   finish_reason: stop
   usage        : {"prompt_tokens": 6, "completion_tokens": 11, "total_tokens": 17}
   top-level keys: ['choices', 'created', 'id', 'model', 'object', 'usage']
   ```
   **What it means:** `stop` = the reply ended naturally (`length` would mean `max_tokens` cut it). 6 prompt "tokens" are the 6 words of the prompt. Expected (not run here): Ollama returns real tokenizer counts and different wording, but the same keys and `finish_reason: stop`.

2. **You run** `python call_model_urllib.py` — the stdlib-only version prints the identical `reply:` line: the protocol is just JSON over HTTP.

3. **You run** `python -m unittest -v test_try_it_02`.
   **What happens inside:** test 1 sends one question alone, then again after a `Hi` turn and its reply; test 2 turns the only message into `system`.
   **What you see:**
   ```
   observed: alone prompt_tokens=5, with history prompt_tokens=12 (3 messages)
   observed: HTTP 400 - at least one 'user' message is required
   ```
   **What it means / what would look wrong:** prompt tokens grew from 5 to 12 because history is re-sent — cost grows with conversation length. The 400 comes from the fake's `_validate()`; real servers vary in strictness.

## Common confusions
**Q:** The server remembers my previous question. — **A:** No; the 5 → 12 jump shows you pay for re-sending history every call.

**Q:** `usage` counts words. — **A:** Only in the fake. Real `prompt_tokens` come from the model's tokenizer and usually exceed the word count.

**Q:** HTTP 200 means complete. — **A:** Check `finish_reason`; `length` means truncated.
