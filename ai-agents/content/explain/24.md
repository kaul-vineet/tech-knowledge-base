# Foundations II: statistics for evaluating agents — explained

## The big picture
"Evaluating agents with a golden set" gated merges on a pass rate over 20 cases; "Governance and evaluation in production" compared a candidate model against a pinned one; "Cost, latency and model choice" accepted a cheaper route because it scored 20/20. Every one of those decisions treats a score on a *finite sample* as if it were the truth. This lesson asks how much a score of 19/20 actually tells you, how many cases you need to see a real drop, how to compare two versions run on the same cases, and why checking many categories at once produces false alarms. `eval_stats.py` uses only the standard library and checks each claim exactly or by simulation.

### T1 Binomial pass rate and the Wilson score interval
**In plain words.** A pass rate from n cases is a noisy estimate; the Wilson interval is an honest range for the true rate, and it never claims certainty from a perfect score.

**Why it is true (intuition).** Each case is a coin flip with unknown bias p. Instead of plugging the estimate into the noise formula (Wald), Wilson asks: "which values of p would make what I saw unsurprising?" — and solves for them.
1. X ~ Binomial(n, p), so p̂ = X/n has mean p and variance p(1−p)/n.
2. Keep every p with |p̂ − p| ≤ z·√(p(1−p)/n) (the score test does not reject).
3. Square both sides: a quadratic in p.
4. Its two roots are centre ± half: centre = (p̂ + z²/2n)/(1 + z²/n), pulled towards ½; the half-width stays positive even at p̂ = 1.

**See it in numbers.** `python eval_stats.py check T1`:
```
20/20: Wilson [0.8389, 1.0000]  bisection [0.8389, 1.0000]  Wald [1.0000, 1.0000]  agree to 1e-9: True
exact coverage of nominal 95 %: n= 20 p=0.95  Wald 0.6389  Wilson 0.9245
```
A perfect 20/20 is consistent with a true rate as low as 0.8389; Wald claims [1, 1]. Root-finding by bisection agrees with the formula. At n = 20 and p = 0.95 — exactly lesson 12's setting — a "95%" Wald interval covers the truth only 64% of the time; Wilson 92%.

**Where it shows up.** "Evaluating agents with a golden set": v1's 20/20 does not prove the true pass rate is above 95%.

### T2 Sample size to detect a regression
**In plain words.** To reliably notice a drop of δ, you need roughly 1/δ² cases: halving the drop you want to see quadruples the suite.

**Why it is true.**
1. Under the null the pass count is centred at np₀ with spread √(np₀q₀); under the drop, at np₁.
2. Reject below a cut-off placed z₁₋α spreads under np₀ (controls false alarms).
3. Require that cut-off to be z₁₋β spreads above np₁ (gives power).
4. Equate and solve for n: n ≥ ((z₁₋α√(p₀q₀) + z₁₋β√(p₁q₁)) / (p₀ − p₁))².
5. Counts are integers, so the exact test's size and power land slightly below the targets.

**See it in numbers.** `check T2`:
```
detect 0.95 -> 0.90 (alpha 0.05 one-sided, power 0.80): n = 150; exact test rejects if passes <= 137: size 0.0385, power 0.7455
lesson 12 golden set n=20, 0.95 -> 0.90: reject if passes <= 16; size 0.0159; power 0.1330
n needed scales with 1/delta^2: n(0.90->0.85) / n(0.90->0.80) = 3.67
```
150 cases to see 95% → 90% with 80% power; lesson 12's 20 cases would notice that drop only 13% of the time.

**Where it shows up.** Lesson 12's gate caught v2 because the regression was total in one category — a per-case rule, not statistical power.

### T3 McNemar's exact test for paired pass/fail results
**In plain words.** When two versions run on the *same* cases, only the cases where they disagree carry evidence.

**Why it is true.**
1. Classify each case: both pass, both fail, A-only (b), B-only (c).
2. Concordant cases look the same under any difference in versions — they drop out.
3. If the versions are equally good, each discordant case is equally likely to be b or c: b ~ Binomial(b + c, ½).
4. The p-value is twice the binomial tail at min(b, c); for large b + c, (|b − c| − 1)²/(b + c) is approximately χ²₁.

**See it in numbers.** `check T3`:
```
paired suite n=200: old 170, new 160, b=15, c=5: exact p 0.0414; chi2 (cc) 4.050, p 0.0442
same counts, unpaired two-proportion z-test: p 0.1882 (pairing ignored)
2000 simulated H0 suites (20 discordant): rejection rate 0.0465
```
Same data: paired p = 0.0414 (significant), unpaired p = 0.1882 (not) — ignoring pairing throws away the information that cases differ in difficulty. Under H0 the test rejects 4.65% of the time, at or below the 5% target.

**Where it shows up.** "Governance and evaluation in production": `fake-model:v2` vs the pinned model on the same golden set.

### T4 Multiple comparisons: Boole's inequality and Bonferroni
**In plain words.** Run 20 tests at 5% each and you will usually get a false alarm; dividing α by the number of tests fixes that, whatever the dependence.

**Why it is true.** The probability of a union is at most the sum of probabilities (each overlap is counted at least once), so m tests at α/m have total false-alarm probability ≤ α.

**See it in numbers.** `check T4`:
```
m=20 independent tests at 0.05: FWER = 0.6415; Bonferroni 0.05/m: FWER = 0.0488
2000 simulated releases with 20 null categories at 0.05 each: P(at least one false alarm) = 0.6475
```

**Where it shows up.** The per-category gate in lesson 12's build task, and the drift checks in lesson 21: many categories means many chances to alarm by chance.

## Worked problems
**l24-p1: 47/50 passes — Wilson and Wald 95% intervals.**
1. *Estimate:* p̂ = 0.94, z = 1.96 (why: 95% two-sided).
2. *Wald:* 0.94 ± 1.96·√(0.94·0.06/50) → [0.8742, 1.0058] (why show it: it is what most people compute).
3. *Notice the upper end exceeds 1* — an impossible rate; Wald breaks near the boundary where agent pass rates live.
4. *Wilson* (T1 formula): [0.8378, 0.9794] — my run of `eval_stats.wilson(47, 50)` printed exactly this.
5. *Report Wilson:* it stays in [0, 1] and has near-nominal coverage (check T1).

**l24-p4: same 300 cases, 12 old-only passes, 4 new-only.**
1. *Keep only discordant pairs* (why: T3): b = 12, c = 4, m = 16.
2. *Exact p:* 2·P(Bin(16, ½) ≤ 4) = 0.0768.
3. *Chi-square with continuity correction:* (|12 − 4| − 1)²/16 = 3.0625, p = 0.0801.
4. *Contrast with the wrong unpaired test* on 250 vs 242 passes: p = 0.3953 (why: it ignores that 284 cases agree).
5. *Interpret:* not significant at 5%, but far closer than the unpaired test suggests. Practically: read the 12 regressions — if they share a cause, fix it rather than wait for significance.

## Common confusions
**Q:** Overlapping confidence intervals mean "no difference". — **A:** For paired runs use McNemar; the T3 check shows a significant paired difference that an unpaired view misses.

**Q:** 20/20 proves ≥ 95%. — **A:** Wilson lower bound 0.8389.

**Q:** More category checks make the gate safer. — **A:** Uncorrected, 20 checks false-alarm 64% of releases.
