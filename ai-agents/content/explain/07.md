# Retrieval-augmented answers — explained

## The intuition
A model only knows what was in its training data plus what you put in the prompt. Retrieval-augmented generation (RAG) is the discipline of choosing *which* few passages of your own documents to put in the prompt, then checking that the answer actually used them.

`rag.py` has four moves: **chunk** (paragraphs, long ones into overlapping 40-word windows), **embed** (unit-length vectors, so a dot product is cosine similarity), **search** (`vectors @ q`, keep top `k=2`), **ask and verify** (hits go in the prompt with ids; code checks each cited id was retrieved).

Analogy: an open-book exam where you must quote page numbers and the examiner checks you opened those pages.
Where the analogy breaks: the index ranks by similarity, not truth — and it always returns pages, even irrelevant ones.

```
docs/*.md ─chunk()─▶ 6 chunks ─embed()─▶ (6,64) unit vectors
question ─embed()─▶ q ─▶ scores = vectors @ q ─▶ top-2 (id, text, score)
          ─▶ prompt "[id] text … Question" ─▶ model ─▶ answer "[id]"
          ─▶ grounded = cited ⊆ retrieved
```

The one thing to remember: retrieval always returns *something*; only a threshold and a citation check tell you whether it is relevant.

## Walkthrough: what actually happens when you run it
1. **You run** `python rag.py`.
   **What happens inside:** `load_chunks()` skips headings and makes 6 chunks from 3 files. `embed()` POSTs them to `/v1/embeddings`; the fake returns 64-dimensional hashed bags of words (each word adds ±1 to one slot).
   **What you see:**
   ```
   6 chunks, vectors (6, 64)
   ```
   **What it means:** 6 rows, one per chunk. Expected (not run here): with `embeddinggemma` in Ollama the second number is the model's vector length (Ollama's docs say typically 384–1024).

2. **Same run**, first question.
   **What happens inside:** `search()` scores all 6 chunks and sorts descending; `ask()` builds the prompt with ids; the fake's RAG rule picks the best-overlapping line and cites it; `grounded` is computed by set inclusion.
   **What you see:**
   ```
   Q: How many tokens does Ollama use for the context window by default?
     hits: [('context-windows#0', 0.53), ('context-windows#1', 0.077)]
     A: Ollama uses a 4096-token context window by default and the OLLAMA_CONTEXT_LENGTH variable changes it. [context-windows#0]  grounded=True
   ```
   **What it means:** 0.53 is a clear winner; 0.077 is noise that still made the top 2 because `k=2` always returns two.

3. **Same run**, second question.
   **What you see:**
   ```
     hits: [('tool-safety#1', 0.387), ('tool-safety#0', 0.313)]
     A: Tools that send, delete or pay need a human approval step. [tool-safety#1]  grounded=True
   ```
   **What it means:** the cited id is in the retrieved set. Expected (not run here): a real model may omit the bracket — then `grounded=False`, the check doing its job.

4. **You run** `python -m unittest -v test_try_it_07`.
   **What you see:**
   ```
   observed: chunk sizes [20, 20, 10, 20, 14]
   observed: [('embeddings#1', 0.183), ('context-windows#1', 0.154)] -> I don't know based on the provided context. grounded = False
   ```
   **What it means / what would look wrong:** smaller windows give 5 chunks instead of 2, each repeating 5 words of the previous (the overlap). The France question still "retrieved" two chunks — search never says "nothing found". Only the missing citation flagged it.

5. **You run** `python -m unittest -v test_build_task` (the `min_score=0.2` build task).
   **What you see:** `Ran 2 tests in 0.931s` … `OK`.
   **What it means:** with a threshold, the France question (best 0.183) is refused *without calling the chat model*, while the approval question (0.387) is still answered.

## Common confusions
**Q:** A high rank means relevant. — **A:** Rank is relative: the France question's top hit (0.183) was irrelevant.

**Q:** `grounded=True` means correct. — **A:** Only that every cited id was retrieved.

**Q:** The 0.2 threshold transfers to a real embedding model. — **A:** No; re-measure on known good and bad questions.
