# Your first tool call — explained

## The intuition
A model cannot run code or read a clock. What it *can* do is reply with a structured request: "please call `get_time` with `{}`". Your program decides whether to honour it, runs the real function, and sends the result back. The model then writes its answer using that result.

So a tool call is two requests: the first carries `tools` and returns `tool_calls`; the second carries the assistant turn plus a matching `role: "tool"` result.

Analogy: a manager (model) who cannot leave the office emails an assistant (your code): "fetch the time". The assistant does it and replies in the same thread.
Where the analogy breaks: the "manager" may also just guess the time without asking — models can skip tools.

```
ask() ─▶ POST {messages:[user], tools:[get_time]}
      ◀─ {tool_calls:[{id:"call_…", function:{name:"get_time", arguments:"{}"}}]}
      run_tool(): LOCAL_FUNCTIONS["get_time"]() ─▶ "2026-…+00:00"
      ─▶ POST {messages:[user, assistant(tool_calls), tool(tool_call_id, result)]}
      ◀─ final text
```

The one thing to remember: the model only *requests* a tool; your allow-list decides what actually runs.

## Walkthrough: what actually happens when you run it
1. **You run** `python first_tool_call.py`.
   **What happens inside:** the fake's `_plan()` sees `get_time` declared and "time" asked, so it returns a `tool_calls` entry. `run_tool()` checks `LOCAL_FUNCTIONS`, parses `arguments`, runs `get_time()`.
   **What you see:**
   ```
   model requested: get_time({})
   tool result    : 2026-11-02T12:42:34+00:00
   final answer   : Final answer: get_time() = 2026-11-02T12:42:34+00:00
   ```
   **What it means:** the timestamp is your machine's UTC clock, so it differs from the README's. Expected (not run here): with `qwen2.5:1.5b` the first two lines look the same; the final sentence is phrased by the model.

2. **You run** `python -m unittest -v test_try_it_05`.
   **What happens inside:** test 1 asks a question that needs no tool; test 2 deletes `messages.append(reply)`.
   **What you see:**
   ```
   observed: Hello from fake-model! You said: 'What is the capital of France?' | tool lines printed: 0
   observed: HTTP 400 - tool message has unknown or missing 'tool_call_id'
   ```
   **What it means / what would look wrong:** offering a tool does not force its use. The 400 proves a `tool` message must reference a `tool_calls` id that appears *earlier*; a 400 on the second request means check ordering first.

## Common confusions
**Q:** The model executed `get_time`. — **A:** Your `run_tool()` did; the model emitted a name and arguments.

**Q:** `arguments` is a dict. — **A:** On `/v1` it is a JSON string; `run_tool()` handles both forms.

**Q:** A declared tool will be called. — **A:** Try-it 1 printed 0 tool lines.
