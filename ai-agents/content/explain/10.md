# Build an MCP server and client — explained

## The intuition
In lesson 8 the tools lived inside the agent's process. The Model Context Protocol (MCP) moves them into a *separate process* with a standard wire format, so any MCP-speaking host can discover and call them. Over stdio that format is deliberately boring: the client launches the server as a subprocess and they exchange JSON-RPC 2.0 messages, one per line, on stdin/stdout.

Two methods matter: `tools/list` (name, description, `inputSchema` — lesson 8's JSON Schema) and `tools/call`. The server is "dual-era": modern 2026-07-28 is stateless (version and capabilities in every request's `_meta`); legacy 2025-11-25 needs an `initialize` handshake. The client probes modern, then falls back.

Two kinds of error: a **protocol error** (JSON-RPC `error`, e.g. `-32602 Unknown tool`) is for the host; a **tool execution error** (`result.isError: true`) is for the model, which can fix its arguments.

Analogy: USB for tools — one plug shape; the host enumerates devices.
Where the analogy breaks: an MCP server is arbitrary code running with your permissions.

```
client ─spawn─▶ mcp_server.py   (stdout = protocol only; logs → stderr)
  ─▶ server/discover ◀─ ok | -32022 | error/timeout ─▶ initialize (legacy)
  ─▶ tools/list ◀─ [add, word_count]
  ─▶ tools/call add {a:"two"} ◀─ isError=true (model)
  ─▶ tools/call rm_rf         ◀─ error -32602 (host)
```

The one thing to remember: stdout belongs to the protocol — one stray `print` and the client cannot parse anything.

## Walkthrough: what actually happens when you run it
1. **You run** `python mcp_client.py` (no model server needed).
   **What happens inside:** `StdioClient` spawns the server, starts a reader thread that queues stdout lines, and calls `connect()`. Then `list_tools()`, two `call_tool("add", …)` and one unknown tool.
   **What you see:**
   ```
   mcp_server.py: era=modern version=2026-07-28
     tools: ['add', 'word_count']
     add(2, 3): 5
     add('two', 3): isError = True | error: invalid arguments: $.a: expected number, got str
     rm_rf: protocol error -32602 Unknown tool: rm_rf
   mcp_server.py --legacy-only: era=legacy version=2025-11-25
     …
   ```
   **What it means:** same verdicts in both eras; the bad `add` fails lesson 8's `schema_check` *inside* the result.

2. **What would look wrong — observed here.** On this sandbox's slow storage the first two runs failed in the legacy pass: server start-up took about 19.7 s, beyond the client's 10 s timeout. Attempt 1 ended in `_queue.Empty`; attempt 2 printed `RuntimeError: {'code': -32601, 'message': 'Method not found: server/discover'}` — the late reply to the timed-out probe was read as the `initialize` answer, because this client does not match replies by `id`. The third run was clean.

3. **You run** the raw probe: `echo '{…"protocolVersion":"1900-01-01"…}' | python mcp_server.py`.
   **What you see:**
   ```
   {"jsonrpc": "2.0", "id": 1, "error": {"code": -32022, "message": "Unsupported protocol version", "data": {"supported": ["2026-07-28"], "requested": "1900-01-01"}}}
   ```
   **What it means:** a modern server tells you which versions it accepts; the "ready" banner went to stderr, keeping stdout clean.

4. **You run** `python -m unittest -v test_try_it_10`.
   **What you see:**
   ```
   observed: first stdout line 'server starting...' -> JSONDecodeError: Expecting value
   observed: {'code': -32022, 'message': 'Unsupported protocol version', 'data': {'supported': ['2026-07-28'], 'requested': '2025-06-18'}}
   ```
   **What it means:** one debug `print` to stdout breaks the protocol. An old pinned version gets a structured error to recover from. Expected (not run here): the official MCP Python SDK client should interoperate with this server (`test_sdk_equivalent`, needs `pip install mcp`).

## Common confusions
**Q:** A failed tool should return a JSON-RPC error. — **A:** No; `add('two', 3)` returns `isError = True` so the model sees it. Only unknown tools/methods are protocol errors.

**Q:** MCP adds a model to the server. — **A:** No model is involved here; MCP standardises tool discovery and calls.

**Q:** Timeouts are just a nuisance. — **A:** In step 2 a timeout plus no `id` matching produced a wrong answer.
