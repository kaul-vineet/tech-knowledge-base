# Documenting architecture: C4 diagrams as text and an ADR — explained

## The intuition
Diagrams rot in drawing tools nobody opens. Here they are text in `doc/arch/` (two Mermaid C4 files, a Structurizr DSL workspace, one ADR), so they can be diffed and linted. `check_docs.py` is the lint: relationships must point at defined elements, brackets balance, ADRs have Nygard's sections in order and a legal status.

In the agent assist a model *drafts* ADR 2; code decides if the draft is usable.

**Analogy:** a clerk checking that every pipe on a plan ends at a fixture that exists.
Where the analogy breaks: consistency is not truth — a well-formed diagram can still be wrong.

```
doc/arch/*.mmd  *.dsl  adr-*.md ─> check_docs.main() ─> OK/FAIL per file ─> exit 0/1
agent_assist: fake model ─> draft ─> validate_draft() ─> REJECTED ─> retry with findings ─> OK
                                                          check_boundaries.py ─> authoritative
```

**The one thing to remember:** docs-as-code means the docs are checked by CI like code.

## Walkthrough: what actually happens when you run it
1. **You run** `python check_docs.py`.
   **What happens inside:** `MERMAID_ELEMENT` collects ids (`member`, `librarian`, `loans`, `email`); `MERMAID_REL` checks both ends of each `Rel`.
   **What you see:** four `OK` lines (`adr-001…`, `c4-container.mmd`, `c4-context.mmd`, `workspace.dsl`).

2. **You run** `python -m unittest -v` → `Ran 16 tests in 6.769s` … `OK`.

3. **You break** `Rel(loans, email,` → `Rel(loans, mail,` (I ran it on a copy).
   **What you see:**
   ```
   FAIL c4-context.mmd
        - Rel uses undefined id 'mail'
   exit=1
   ```

4. **You run** `python try_it.py`.
   **What you see:**
   ```
   [1] ADR status 'Reversed.' -> exit 1: FAIL adr-001-sqlite-behind-repository.md | - status must start with one of ('Proposed', 'Accepted', 'Deprecated', 'Superseded')
   [1] ADR status 'Superseded by ADR 2.' -> exit 0: (all OK)
   [2] DSL 'api -> cache' -> exit 1: FAIL workspace.dsl | - relationship uses undefined id 'cache'
   ```

5. **You run** `python agent_assist.py`.
   **What you see:**
   ```
   next ADR number from doc/arch/: 2
   attempt 1: REJECTED
     - agent drafts must have status 'Proposed' (a human accepts ADRs), got 'Accepted'
   attempt 2: OK
   …
   fitness function (authoritative): checked 7 files: 0 boundary violation(s) (exit 0)
   ```
   **What it means:** the checker's findings go back into the prompt; the draft is printed, never saved.

6. **Optional render** with mermaid-cli or Structurizr — Expected (not run here): an SVG with 4 elements and 4 arrows, or the viewer on port 8080.

## Common confusions
**Q:** The lint validates Mermaid syntax. — **A:** It checks structure only; real rendering runs in CI.

**Q:** A reversed ADR gets edited. — **A:** It is marked Superseded (try_it [1]).

**Q:** The agent can accept its own ADR. — **A:** `validate_draft` rejects any status but `Proposed`.
