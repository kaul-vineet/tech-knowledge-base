# API-first with OpenAPI 3.1 — explained

## The intuition
API-first means the contract (`openapi.json`) is written before the server, and the server is then checked against it. `contract_check.check()` asks of one real response: path and method in the spec? status declared? required fields present? types and enums right? Any "no" is drift.

**Analogy:** a building plan approved before construction; the inspector compares the house with the plan, not with the builder's memory.
Where the analogy breaks: the lab's inspector is shallow — it checks top-level fields only, not nested schemas or formats.

```
openapi.json ──load_spec()──┐
                            ▼
client ─HTTP─> server.py ─> (status, body) ─> check(spec, method, path, status, body) ─> [] or [problems]
```

**The one thing to remember:** an empty list from `check()` means "matches the contract"; everything else is drift.

## Walkthrough: what actually happens when you run it
1. **You run** `python -m unittest -v`.
   **What happens inside:** the tests serve the API in a thread and pass every response through `check()`; `test_every_declared_response_is_exercised` ensures no declared status goes untested.
   **What you see:** `Ran 4 tests in 12.251s` … `OK`.

2. **You run** `python server.py 18765` and, in a second terminal, `python client_demo.py 18765`.
   **What happens inside:** `find_operation` turns `/loans/{loanId}` into the regex `^/loans/[^/]+$` to match `/loans/1`.
   **What you see:**
   ```
   GET  /health   -> 200 {'status': 'ok'}  contract: OK
   POST /loans    -> 201 {'id': 1, 'bookId': 'b1', 'memberId': 'm1', 'status': 'active'}  contract: OK
   POST /loans    -> 409 {'error': 'book b1 is already on loan'}  contract: OK
   GET  /loans/1  -> 200 {'id': 1, 'bookId': 'b1', 'memberId': 'm1', 'status': 'active'}  contract: OK
   ```

3. **You run** `python try_it.py` (drift in a scratch copy of `server.py`).
   **What you see:**
   ```
   [1] memberId renamed to member -> exit 1; FAILED (failures=2)
       AssertionError: Lists differ: ["POST /loans 201: missing required field 'memberId'"] != []
       AssertionError: Lists differ: ["GET /loans/{loanId} 200: missing required field 'memberId'"] != []
   [2] POST /loans answered 500 -> ['POST /loans: status 500 not declared']
   [2] POST /loans answered 409 -> []
   ```
   **What it means:** one rename breaks two operations because both return the `Loan` schema. An undeclared 500 is drift too: clients cannot plan for a status the contract hides.

## Common confusions
**Q:** Generating the spec from code later is the same. — **A:** Then the spec describes the drift too; here the spec is the judge.

**Q:** A 500 is fine, every server has bugs. — **A:** try_it [2]: `check()` reports it as undeclared; declare an `Error` response or fix the bug.

**Q:** `contract: OK` means fully valid OpenAPI. — **A:** The checker says "Not a full validator"; use a real one in CI.

## Check your understanding

<details><summary>Answer</summary>No problems: the response matches the contract.</details>

3. Why would a `bool` fail an `integer` field?
<details><summary>Answer</summary>In Python `bool` is a subclass of `int`; the checker excludes it explicitly.</details>
