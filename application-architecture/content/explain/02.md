# Layered structure: presentation, service, repository — explained

## The intuition
The lab splits one small loans API into three files with one job each: `handler.py` speaks HTTP, `service.py` holds the rules ("one active loan per book", "max 3 per member"), `repository.py` stores loans. Calls only go downward, and the service never imports `http.server` or `sqlite3`. So `app.py` swaps memory for SQLite in one line.

**Analogy:** a restaurant: waiter (handler), chef (service), pantry (repository). The chef does not care whether the pantry is a fridge or a cellar.
Where the analogy breaks: in code nothing stops `import sqlite3` in the service except a test.

```
HTTP ─> handler.py ──calls──> service.py ──calls──> repository.py ─> dict | SQLite
          maps errors            raises                add/get/active/
          to 201/409/404         BookAlreadyOnLoan     mark_returned
```

**The one thing to remember:** dependencies point down, and errors are translated to HTTP in exactly one place (`ERROR_STATUS`).

## Walkthrough: what actually happens when you run it
1. **You run** `python app.py --storage memory`.
   **What happens inside:** `build_service` picks `InMemoryLoanRepository`; the second borrow reaches `service.borrow`, which scans `repo.active()`, finds `b1`, raises `BookAlreadyOnLoan`; the handler maps it to 409.
   **What you see:**
   ```
   borrow b1 by m1 -> 201 {'id': 1, 'bookId': 'b1', 'memberId': 'm1', 'status': 'active'}
   borrow b1 by m2 -> 409 {'error': 'book b1 is already on loan'}
   return loan 1   -> 200 {'id': 1, 'bookId': 'b1', 'memberId': 'm1', 'status': 'returned'}
   get loan 99     -> 404 {'error': 'loan 99 not found'}
   ```

2. **You run** `python app.py --storage sqlite`.
   **What you see:** the same four lines, byte for byte — the service cannot tell the difference.

3. **You run** `python -m unittest -v`.
   **What happens inside:** the same 5 rule tests run against both repositories, plus one HTTP test and `test_service_has_no_infrastructure_imports`, which parses `service.py`'s imports.
   **What you see:** `Ran 12 tests in 0.591s` … `OK`.

4. **You run** `python try_it.py`.
   **What you see:**
   ```
   [1] HTTP    borrow b2 by m1 -> 409 {'error': 'member m1 already has 1 loans'}
   [2] InMemoryLoanRepository   after returning loan 2, b4 gets loan id 4
   [2] SqliteLoanRepository     after returning loan 2, b4 gets loan id 4
   ```
   **What it means:** a limit of 1 changes behaviour without touching the handler. Both repositories number the fourth loan 4 because returning keeps the row; if one said 2, the repositories would disagree and the shared tests should catch it.

## Common confusions
**Q:** 409 is decided in the service. — **A:** The service raises `LoanLimitReached`; only `ERROR_STATUS` in `handler.py` knows 409.

**Q:** Layers mean three deployables. — **A:** One process; layers are a code rule.

**Q:** Swapping storage needs changes everywhere. — **A:** Only the `repo = …` line in `build_service`.
