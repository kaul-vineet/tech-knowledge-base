# Modular monolith boundaries with a fitness function — explained

## The intuition
One deployable, two modules: `library/catalog` and `library/loans`. Each module has a public face (its `__init__.py`) and a private back room (`internal/`). Loans may call `catalog.is_available()` but must never touch `catalog.internal.store.BOOKS`. Python cannot enforce privacy, so `check_boundaries.py` does: it parses every file with `ast`, resolves each import to a dotted name, and fails if a module reaches into another module's `internal`.

**Analogy:** apartments in one building: you knock on the front door, you do not climb through the neighbour's kitchen window.
Where the analogy breaks: the building has no locks — the check is a guard who only notices doors he knows about (see try_it [2]).

```
library/loans/internal/rules.py
   from library import catalog   ── allowed (public __init__)
   catalog.is_available(...)
library/loans/shortcut.py
   from ..catalog.internal import store ── ast → library.catalog.internal ── VIOLATION, exit 1
```

**The one thing to remember:** a boundary is only real if a check fails the build when it is crossed.

## Walkthrough: what actually happens when you run it
1. **You run** `python check_boundaries.py`.
   **What happens inside:** `scan()` rglobs `library/*.py`; `package_of()` turns `library/loans/internal/rules.py` into `library.loans.internal`, so the owner is `loans`; `violations()` flags targets shaped `library.<other>.internal…`.
   **What you see:** `checked 7 files: 0 boundary violation(s)` (exit 0).

2. **You run** `python -m unittest -v`.
   **What you see:** `Ran 8 tests in 0.028s` … `OK`. (My first attempt here died with a `FileNotFoundError` from the slow storage mount before any test ran; the re-run passed.)

3. **You run** `python try_it.py` (it adds `shortcut.py` to a scratch copy, so your lab stays clean).
   **What happens inside:** experiment 1 writes a *relative* import; `imported_targets()` uses `node.level` to climb from `library.loans` to `library`, producing `library.catalog.internal`.
   **What you see:**
   ```
   [1] check_boundaries.py -> exit 1
       VIOLATION library/loans/shortcut.py:1 'loans' imports internals of 'catalog' (library.catalog.internal)
       checked 8 files: 1 boundary violation(s)
   [1] python -m unittest -> exit 1; FAILED (failures=1)
   [2] importlib.import_module(...) -> exit 0; checked 8 files: 0 boundary violation(s)
   ```
   **What it means:** relative imports do not hide the shortcut. But [2] shows the limit: a string passed to `importlib` is invisible to a static check. That is a known gap, not a pass.

4. **Fix it:** delete the shortcut; the count returns to 7 files, 0 violations.

## Common confusions
**Q:** Exit 0 proves no module touches another's internals. — **A:** It proves no *static import* does; try_it [2] slipped through with exit 0.

**Q:** Paths break on Windows. — **A:** `package_of` uses `Path.parts` and reports use `as_posix()`, so output is identical.

**Q:** A modular monolith is several services. — **A:** It is one process; the boundary is in code and CI.
