# Foundations I: modularity theory – information hiding, dependency graphs and Martin's metrics — explained

## The big picture
Three earlier labs made claims about structure without proving them. "Layered structure: presentation, service, repository" said calls only go downward. "Hexagonal architecture: ports and adapters" said the domain depends only on ports. "Modular monolith boundaries with a fitness function" failed the build when one module reached into another's internals. This lesson explains why: a code base is a **directed graph** (module → module it imports), and three facts about it justify those rules. `check_modularity.py` builds the real lab graphs with `ast` and checks each theorem numerically.

### T23.1 Strict layering ⇔ acyclic dependency graph
**In plain words:** if you can number your modules so that every import points to a strictly lower number, there are no import cycles — and if there are no cycles, such a numbering always exists.

**Why it is true (intuition):** walking along imports the number drops at every step, so you can never return to the start. Conversely, without cycles "how far down can I still walk from here?" is finite, and larger for a module than for anything it imports.

Proof skeleton:
1. (⇒) Suppose a cycle v₀ → … → v_k = v₀ exists.
2. Each edge strictly lowers the layer, so ℓ(v₀) > … > ℓ(v_k) = ℓ(v₀): contradiction.
3. (⇐) In a finite acyclic graph paths cannot repeat a vertex, so the longest path from v is finite; call its length ℓ(v).
4. For an edge u → v, put u in front of v's longest path; u is not already on it (that would be a cycle), so ℓ(u) ≥ ℓ(v) + 1.

**See it in numbers:** `python check_modularity.py`
```
  [OK] 2000/2000 random strictly layered graphs are acyclic
      (same-layer edges allowed: 1659/2000 graphs have a cycle - strictness matters)
  [OK] converse: longest-path layering of 2000 random DAGs has 0 violations
  [OK] layered (L100 #2): 4 edges, acyclic, layers {0: ['repository', 'service'], 1: ['handler'], 2: ['app']}
  [OK] hexagonal (L200 #7): 10 edges, acyclic, layers {0: ['ports'], 1: ['domain'], 2: ['driven_memory', 'driven_sqlite', 'driving_cli', 'driving_http'], 3: ['app']}
```
2000/2000 is ⇒; 0 violations is ⇐. 1659/2000 is the corollary: allow same-layer imports and cycles return. The last two lines are ℓ for the real labs: `service` sits at 0 beside `repository` because it receives the repository instead of importing it.

**Where it shows up in practice:** lesson 2's `test_service_has_no_infrastructure_imports` and lesson 7's domain-imports test each guard one edge of this numbering.

### T23.2 The condensation of any dependency graph is acyclic
**In plain words:** group modules that can reach each other (strongly connected components, SCCs); the graph *between* groups never has a cycle, so groups can always be layered.

**Why it is true (intuition):** if group A reached B and B reached A, every module in A could reach every module in B and back — one group, not two.

Proof skeleton:
1. Assume a cycle C₀ → C₁ → … → C₀ between distinct SCCs.
2. Inside an SCC everyone reaches everyone; an edge Cᵢ → Cᵢ₊₁ therefore lets every node of Cᵢ reach every node of Cᵢ₊₁.
3. Chain around the cycle: C₀ and C₁ reach each other.
4. Then C₀ ∪ C₁ is strongly connected, contradicting that C₀ was maximal.

**See it in numbers:**
```
  [OK] 2000/2000 condensations acyclic (1634 of the inputs had cycles)
  [OK] hexagonal lab read WITH its __main__ blocks: cycle component [['app', 'driving_cli']] (driving_cli's entry block imports app, app imports driving_cli)
  [OK] seeded edge domain -> driving_http creates the cycle component [['domain', 'driving_http']]
```
1634 inputs had cycles; every condensation was acyclic. Read with `__main__` blocks, `app` and `driving_cli` form one SCC.

**Where it shows up in practice:** lesson 3's `check_boundaries.py` forbids one kind of edge; an SCC report shows which modules have *already* fused.

### T23.3 Martin's metrics and the distance to the main sequence
**In plain words:** instability I = Ce / (Ca + Ce) (outgoing vs incoming dependencies); abstractness A = abstract / all classes. Healthy modules sit near A + I = 1: stable means abstract. Dn = |A + I − 1| measures the miss; the geometric distance is Dn / √2.

**Why it is true (intuition):** both ratios are "part over whole"; the point-to-line distance for A + I − 1 = 0 divides by the normal's length, √2.

Proof skeleton:
1. 0 ≤ Ce ≤ Ca + Ce and 0 ≤ Na ≤ Nc give I, A ∈ [0, 1].
2. Point-to-line distance: |ax₀ + by₀ + c| / √(a² + b²).
3. Substitute a = b = 1, c = −1: |I + A − 1| / √2.
4. On the unit square |I + A − 1| ≤ 1, reached only at (0, 0) "zone of pain" and (1, 1) "zone of uselessness".

**See it in numbers:**
```
      domain          5  1  0.167  0.00  0.833     0.5893
      ports           1  0  0.000  1.00  0.000     0.0000
  [OK] max |numeric distance - Dn/sqrt(2)| = 4.7e-12 (< 1e-5)
      mean Dn = 0.405; furthest from the main sequence: domain (stable and concrete: the 'zone of pain' corner)
```
`domain`: Ca 5, Ce 1 → I = 1/6 = 0.167; nothing abstract → Dn = 0.833 = 0.5893 × √2. `ports`: stable and fully abstract, on the line. 4.7e-12 confirms the √2 form by brute force.

**Where it shows up in practice:** lesson 7's domain is *meant* to be stable; the metric says it is also concrete, so changes there are expensive.

## Worked problems
**P23-3.** Ca = 3, Ce = 1, 4 classes, 1 abstract.
1. I = Ce / (Ca + Ce) = 1 / 4 = 0.25. *Why:* outgoing share of all dependencies.
2. A = 1 / 4 = 0.25. *Why:* abstract share of classes.
3. Dn = |0.25 + 0.25 − 1| = 0.50. *Why:* normalised miss from the main sequence.
4. A + I = 0.5 < 1, so it lies below the line, towards (0, 0): stable-ish and concrete — the zone of pain. `l500_checks.py` recomputes it: `OK  P23-3: I = 0.25, A = 0.25, Dn = 0.50`.

**P23-4.** Move the four exception classes from `domain` to `ports`.
1. Who imports `domain` now? Only `app`, `driven_memory`, `driven_sqlite` → Ca = 3; it still imports `ports` → Ce = 1; I = 0.25. *Why:* the driving adapters now import `ports` instead.
2. `domain` keeps `Loan` and `LoanService`, both concrete → A = 0, Dn = |0 + 0.25 − 1| = 0.75.
3. `ports`: 6 classes, 2 abstract → A = 1/3; Ca = 3, Ce = 0 → I = 0; Dn = 2/3 ≈ 0.67.
4. Mean Dn over 7 modules rises from 0.405 to 0.488 (`OK  P23-4: … mean Dn 0.405 -> 0.488`). *Why it matters:* the tidier-looking refactor drags `ports` off the main sequence; a separate stable "errors" contract would be better.

## Common confusions
**Q:** "Depend only on your own layer or lower" prevents cycles. — **A:** 1659/2000 such graphs had a cycle; the proof needs *strictly* lower.

**Q:** Dn is the distance to the main sequence. — **A:** It is the normalised version; the Euclidean distance is Dn / √2 (0.833 → 0.5893).

**Q:** The `__main__` cycle does not count. — **A:** It never runs at import time, but static tools and readers see it.
