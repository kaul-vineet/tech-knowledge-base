# Set up your environment — explained

## The intuition
Every later lab assumes Python 3.12+ with a complete standard library. `check_env.py` turns that assumption into a one-second check whose exit code says "ready" (0) or "fix this first" (1). It is the course's first fitness function. Optional tools (Node, Podman, Ollama) are reported but never fail it; only lesson 6 uses them.

**Analogy:** a pilot's pre-flight checklist: mandatory items must pass before taxiing.
Where the analogy breaks: CI reads the exit code, not the wording of the lines.

```
check_python()    ─┐
missing_modules() ─┼─> main() returns 0 / 1 ──> CI green / red
shutil.which(...) ─┘   (optional tools: printed only, never change the code)
```

**The one thing to remember:** the exit code, not the printed text, is the contract with CI.

## Walkthrough: what actually happens when you run it
1. **You run** `python check_env.py`.
   **What happens inside:** `check_python()` compares `sys.version_info[:2]` with `MIN_PYTHON = (3, 12)`; `missing_modules()` imports the 7 `REQUIRED_MODULES`; `shutil.which` searches `PATH`.
   **What you see:**
   ```
   platform Linux x86_64
   python   3.12.15    OK
   stdlib   7 modules  OK
   sqlite   3.44.0     OK
   optional npx        not found (ok) - runs mermaid-cli without a global install
   …
   ```
   **What it means:** ready. Your Mac prints `Darwin arm64`. `MISSING sqlite3` would mean an incomplete distro Python.

2. **You run** `python -m unittest -v`.
   **What happens inside:** `test_old_python_is_rejected` calls `check_python((3, 11))` directly, so the failure branch is tested without an old interpreter.
   **What you see:** `Ran 6 tests in 1.966s` … `OK`.

3. **You run** `python run_all_labs.py`.
   **What happens inside:** one `python -m unittest discover -q` subprocess per `NN-*` folder, each with that folder as working directory.
   **What you see:** six `OK` lines, then `ALL LABS PASSED`.

4. **You run** `python try_it.py`.
   **What you see:**
   ```
   [1] test file renamed to checks_env_test.py -> exit 5: NO TESTS RAN
   [2] MIN_PYTHON=(3, 99) -> main() returns 1; python line: python   3.12.15    TOO OLD (need 3.12+)
   ```
   **What it means:** exit 5 is unittest's "nothing found" code; CI catches it only because it is non-zero. The message still says "need 3.12+" because the text is hard-coded — another reason to trust the code, not the words.

## Common confusions
**Q:** "not found (ok)" for podman means my setup is broken. — **A:** No; only `ok and not missing` feeds the return value.

**Q:** Any test file name works. — **A:** Discovery matches `test*.py`; try_it [1] shows `NO TESTS RAN`.

**Q:** The message tells me the required version. — **A:** It is a fixed string; read `MIN_PYTHON`.
