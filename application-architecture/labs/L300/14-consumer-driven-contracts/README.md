# Lab 14 – Consumer-driven contract testing

Library Loans (**consumer**, `consumer.py`) reads `title` and `available` from the catalogue (**provider**, `provider.py`). The consumer's tests run the real `CatalogueClient` against a mock provider and write a **contract** to `contracts/loans-service--catalogue-service.json`. The contract is versioned in the repo and records `consumerVersion`. The provider's build replays every contract against the real provider, after setting a **provider state**. `contract.py` is a stdlib mini-Pact with the same flow but its own file format. The base verifier only compares status codes; you make it compare the body.

## Files
| File | Purpose |
|---|---|
| `contract.py` | `like()`, `ContractBuilder` (mock provider, `write()`), `verify_provider()` (lesson code) |
| `consumer.py` | `CatalogueClient.book()` and `loan_receipt()` |
| `provider.py` | Catalogue HTTP server on 127.0.0.1 (`title_field` lets the failure lab rename the field; `states=True` adds the test-only state hook) |
| `contracts/loans-service--catalogue-service.json` | The contract (generated by `test_consumer.py`, committed) |
| `test_consumer.py` | Consumer unit test (stub) + contract test (writes the file) |
| `test_provider.py` | Provider unit test + verification of every file in `contracts/` |
| `failure_lab.py` | The rename `title` → `name`, checked by every test both teams have |
| `test_build_task.py` / `solution/contract.py` | Build task check / solution |
| `pact/test_pact_contract.py`, `requirements-ci.txt` | Same flow with pact-python 4.2.0 (CI only, pending-ci) |
| `try_it.py` | The two tryIt experiments |

## Run
```bash
cd labs/L300/14-consumer-driven-contracts
python -m unittest -v test_consumer     # consumer build: writes contracts/...json
```

## Build task (the hardening change)
Make `verify_provider()` compare the response **body**. Keys the consumer declared must exist, `like` fields must keep their JSON type, other values must be equal, and extra keys are allowed (tolerant reader).

- Solution: `solution/contract.py` (`body_problems()`).
- Check (solution by default; YOUR file with `CHECK_MINE=1`):
```
CHECK_MINE=1 python -m unittest -v test_build_task          # Mac mini (zsh)
$env:CHECK_MINE = "1"; python -m unittest -v test_build_task   # Windows (PowerShell)
Remove-Item Env:\CHECK_MINE                                     # Windows: switch back
```
Fail before / pass after (observed 2026-10-28):
```
$ CHECK_MINE=1 python -m unittest test_build_task      # unchanged contract.py
FAIL: test_renamed_field_fails
FAIL: test_retyped_field_fails_and_extra_field_passes
FAILED (failures=2)
$ python -m unittest test_build_task                   # solution
OK
```

## Mac mini and Windows
Servers bind 127.0.0.1 on port 0 (any free port). `provider.py 8081` is only for manual runs (Bruno exercise). The contract is written with `encoding="utf-8"` and sorted keys, so the file is byte-identical on both machines and in Git. The tryIt scratch folder `.tryit-work/` is deleted after the run.

## Troubleshooting
| Symptom | Action |
|---|---|
| `mock provider: unexpected [...] never called [...]` | The client sent a request the contract does not declare, or skipped one; fix the test or the client. |
| `no contracts in contracts/` | Run the consumer tests first (they write the file) or fetch the contracts from your broker. |
| Every harmless provider change breaks verification | Use `like()` for values the consumer does not branch on. |
