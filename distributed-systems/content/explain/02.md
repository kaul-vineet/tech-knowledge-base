# Two services talking over HTTP — explained

## The intuition
In one process, `get_price("pear")` cannot half-happen. Once the price lives in service B, the call becomes two messages: A writes a request onto a socket, B answers with a response. So a remote call has three outcomes: success (2xx), an error answer (4xx/5xx), or no answer at all.

**Analogy:** ordering by phone: "here you go", "we don't sell that", or the line goes dead.
Where the analogy breaks: on a network, silence and slowness look the same until a timeout decides.

```
A: call_b()                         B: ServiceB.do_GET()
 t0 = perf_counter()
 ── GET /price?item=pear ────────▶  PRICES["pear"]
 ◀── 200 {"item":"pear","price":4}  reply(200, ...)
 latency = perf_counter() - t0
```

The one thing to remember: a remote call is a request and a response, and the response may never come.

## Walkthrough: what actually happens when you run it
1. **You run** `python two_services.py`
   **What happens inside:** `start_b()` serves on an OS-picked port. `call_b()` records `t0`, opens the URL with `timeout=2.0`, and `json.load` decodes the body. For `kiwi`, `urllib` raises `HTTPError`, which `main()` handles as an outcome.
   **What you see:**
   ```
   service B listening on http://127.0.0.1:41303
   A -> B  GET /price?item=apple -> 200 {'item': 'apple', 'price': 3}  (7.0 ms)
   A -> B  GET /price?item=pear  -> 200 {'item': 'pear', 'price': 4}  (2.3 ms)
   …
   A -> B  GET /price?item=kiwi  -> 404 {'error': "unknown item 'kiwi'"}
   latency ms: min=2.0 median=2.3 max=7.0
   ```
   **What it means:** the first call is slowest (cold start); the median ignores it. README numbers differ per machine.

2. **You run** `python try_it.py`
   **What happens inside:** tryIt 1 calls a port where nothing listens. tryIt 2 makes B sleep 50 ms and calls it three times in a row.
   **What you see:**
   ```
   tryIt 1: URLError -> ConnectionRefusedError: Connection refused
   tryIt 2: every call >= 50 ms: True; 3 sequential calls >= 150 ms: True (total 156 ms)
   ```
   **What it means:** "B is down" is an exception, not a status; sequential latencies add.

3. **You run** `python -m unittest`
   **What you see:**
   ```
   Ran 2 tests in 0.581s
   OK
   ```
   **What it means:** plum returns its price within the bound, and kiwi raises a 404.

## Common confusions
**Q:** A 404 is a failure, so retry it. — **A:** The kiwi 404 is a definite answer; asking again gives the same answer.

**Q:** `time.time()` is fine for latency. — **A:** It can jump when the clock is adjusted; `perf_counter()` only moves forward.

**Q:** Localhost numbers predict production. — **A:** Loopback has no real network; expect a longer tail.
