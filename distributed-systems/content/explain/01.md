# Set up your environment: a local multi-node lab — explained

## The intuition
A distributed system is programs that cannot see each other's memory and talk only over a network. Three Python processes on one laptop already have that: separate memory, separate ports, separate lives. `lab.py` spawns `node.py` processes, asks each one `GET /health` until it answers, and later stops them by PID.

**Analogy:** three shops in a mall, each with its own phone number; you only know a shop is open when someone picks up.
Where the analogy breaks: real networks lose packets and machines drift clocks; localhost almost never fails by itself.

```
lab.py ──Popen──▶ node1 :18001 ◀── GET /health ──▶ 200 {"node":"node1",...}
       ──Popen──▶ node2 :18002
       ──Popen──▶ node3 :18003      stop(): terminate() + wait() per PID
```

The one thing to remember: a node is a process with its own port, and you learn it is alive only by asking it.

## Walkthrough: what actually happens when you run it
1. **You run** `LAB_BASE_PORT=18001 python lab.py demo 3`
   **What happens inside:** `start()` runs `subprocess.Popen([sys.executable, "node.py", ...])` per node, then polls `health(port)` until each answers or a 15 s deadline passes; `stop()` terminates and reaps each process.
   **What you see:**
   ```
   node1 up on port 18001 -> /health OK
   node2 up on port 18002 -> /health OK
   node3 up on port 18003 -> /health OK
   stopped 3 nodes
   ```
   **What it means:** three independent interpreters were listening.

2. **You run** `python try_it.py`
   **What happens inside:** tryIt 1 starts a second node on node1's port, so `server_bind` fails; tryIt 2 starts three nodes and stops only node2.
   **What you see:**
   ```
   tryIt 1: second node exit code 1: OSError: [Errno 98] Address already in use
            node1 still healthy: True
   tryIt 2: node1=OK, node2=ConnectionRefusedError, node3=OK
   ```
   **What it means:** port = address; failures are per process. "Refused" = nobody listens.

3. **You run** `python -m unittest -v`
   **What you see:**
   ```
   Ran 4 tests in 22.348s
   OK
   ```
   **What it means:** an earlier run here, under heavy load, hit `RuntimeError: node1 did not start` — the readiness deadline is itself a timeout. Raise `wait_s`; do not add sleeps.

## Common confusions
**Q:** Threads would do the same. — **A:** Threads share memory and die together; separate PIDs let tryIt 2 kill node2 alone.

**Q:** Sleeping a second after start is fine. — **A:** Start-up time varies (see the flaky tests); poll `/health` with a deadline.

**Q:** Binding `0.0.0.0` is simpler. — **A:** It exposes an unauthenticated server to your network; `node.py` defaults to `127.0.0.1`.

## Check your understanding

2. Why does `stop()` call `wait()` after `terminate()`?
<details><summary>Answer</summary>To reap the process so its port is free when `stop()` returns.</details>

<details><summary>Answer</summary>Polling waits exactly as long as needed and detects a node that never starts.</details>
