# Timeouts: fail fast instead of hanging — explained

## The intuition
When B is slow, A's thread sits blocked holding a socket and a worker slot. Enough slow calls and A stops serving anyone. A timeout says "I wait this long, then free myself". Two catches: giving up does not cancel B's work, and the value matters — the lab picks it from data by accepting a false-timeout rate and reading that latency percentile.

**Analogy:** a kitchen timer set before calling a busy shop; when it rings you hang up.
Where the analogy breaks: hanging up a phone ends the call for both sides; B never learns that A left.

```
A.call(timeout=0.5) ──▶ SlowB sleeps 2.0 s
      │ 0.5 s: read raises TimeoutError → A's thread is free
      ▼                    B still finishes; its reply hits a closed socket
latency samples ─▶ quantiles ─▶ p99.9 = timeout for 0.1% false timeouts
```

The one thing to remember: every remote call needs a limit chosen from the dependency's measured latency.

## Walkthrough: what actually happens when you run it
1. **You run** `python timeouts.py`
   **What happens inside:** `call(url, None)` sets no timeout, so the socket blocks until B answers. `call(url, 0.5)` makes the read raise `TimeoutError`. `choose_timeout()` draws seeded lognormal samples around 40 ms and reads `statistics.quantiles(n=1000)`.
   **What you see:**
   ```
   B takes 2.0 s to answer.
   A timeout=None -> 200 ok               after 2.0 s
   A timeout=0.5  -> FAILED TimeoutError  after 0.5 s
   B latency: p50=40 ms  p99=88 ms  p99.9=116 ms
   suggested timeout for A->B: 0.116 s
   ```
   **What it means:** without a timeout, A waits as long as B. p99.9 cuts off 1 in 1000 healthy calls. Same as the README.

2. **You run** `python -c "import timeouts; print(timeouts.choose_timeout(false_timeout_rate=0.01))"`
   **What you see:**
   ```
   0.088
   ```
   **What it means:** p99: a shorter wait, paid for by cutting ~1% of healthy calls.

3. **You run** `python try_it.py`
   **What happens inside:** tryIt 2 passes `deadline - time.monotonic()` as each hop's timeout.
   **What you see:**
   ```
   tryIt 1: delay=0.05 timeout=0.1 -> 200 ok
   tryIt 1: delay=0.2  timeout=0.1 -> FAILED TimeoutError
   tryIt 2: call 1 timeout=0.5 s -> 200 ok after 0.3 s
   tryIt 2: call 2 timeout=0.2 s -> FAILED TimeoutError after 0.2 s
   ```
   **What it means:** a shared deadline keeps the whole operation inside its budget.

## Common confusions
**Q:** The timeout stopped B. — **A:** `SlowB.do_GET` keeps sleeping and its reply hits `OSError`; side effects may still happen.

**Q:** `timeout=0.5` caps the whole call. — **A:** It caps each blocking socket operation; enforce a total deadline yourself (tryIt 2).

**Q:** Shorter is safer. — **A:** `0.088` cuts ~1% of healthy calls.
