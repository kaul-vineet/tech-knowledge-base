# Ordering events with Lamport clocks — explained

## The intuition
Merge logs from three machines and sort by timestamp: the warehouse "received" an order before the shop "sent" it. Only the warehouse clock is wrong — machines disagree by more than the gap between related events.

A Lamport clock is a counter carried on messages: count your events, stamp what you send, jump past any stamp you receive. A cause then always has a smaller number than its effect.

**Analogy:** a relay baton with a number on it; every runner writes a number bigger than the one handed over.
Where the analogy breaks: runners on different tracks can write the same number; equal stamps mean "unrelated".

```
A: L1 Buy ─ L2 send m1 ───────────────────────── L8 recv m3 ─ L9 receipt
B:            L3 recv m1 ─ L4 ─ L5 send m2             ▲
C:                              L6 recv m2 ─ L7 send m3 ┘ ─ L8 audit
```

The one thing to remember: if a happened before b then L(a) < L(b), but not the other way round.

## Walkthrough: what actually happens when you run it
1. **You run** `python lamport.py`
   **What happens inside:** `local()` and `send()` do `clock += 1`; `on_receive()` does `clock = max(clock, msg["ts"]) + 1`. `record()` also stores a skewed simulated wall time (B 80 ms slow).
   **What you see:**
   ```
   --- sorted by wall clock: 2 causality violation(s) ---
     L=3  wall=-0.050s  B: recv 'create order' from A
     …
     L=2  wall=+0.020s  A: send 'create order' to B
   --- sorted by (Lamport, node): 0 causality violation(s) ---
     …
     L=8  wall=+0.080s  A: recv 'payment ok' from C
     L=8  wall=+0.130s  C: write audit log
   ```
   **What it means:** B's slow clock sorts its receive first; Lamport order fixes it. The two L=8 events are concurrent; node id breaks the tie.

2. **You run** `python try_it.py`
   **What you see:**
   ```
   tryIt 1: without max(): m1 send L=2, recv L=1; (Lamport, node) order has 2 violation(s)
   tryIt 2: B  5 ms slow -> wall-clock order 0 violation(s), (Lamport, node) order 0
   tryIt 2: B 15 ms slow -> wall-clock order 1 violation(s), (Lamport, node) order 0
   ```
   **What it means:** `max()` is the whole trick. Skew only hurts once it exceeds the 10 ms gap between related events.

## Common confusions
**Q:** L(a) < L(b) means a caused b. — **A:** C's audit log (L=8) is smaller than A's receipt (L=9) but did not cause it; only the forward direction holds.

**Q:** NTP fixes this. — **A:** tryIt 2: 15 ms skew already breaks order.

**Q:** Lamport time says when things happened. — **A:** It has no units; use wall time for durations on one node.
