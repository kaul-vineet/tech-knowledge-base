## Failure lab: break it, then harden it
**Fault (seeded):** the wrappers accept a truncated AES-GCM tag (any length >= 4 bytes) and 'fix' signatures: trailing bytes are ignored and S >= L is reduced mod L. The derived vectors (deterministic, from Wycheproof tcIds 10 and 1) exercise exactly these paths.

**Symptom:** see the output above (`derived_vectors.json   1/5 pass` with FAIL lines for tcIds 9001, 9002, 9101, 9102).

**Fix = build task:** write strict `aead_open` (exactly 16-byte tag and 12-byte IV, high-level `AESGCM`) and `sig_verify` (exactly 64 bytes, S < L, then verify).

Hints: Reject on size before calling the library; raise ValueError or return False. · `int.from_bytes(sig[32:], 'little') >= L` detects a non-canonical S.

## Vendored vectors and licence
`vectors/aes_gcm_subset.json` (5 tests) and `vectors/ed25519_subset.json` (11 tests) keep Wycheproof's field names (`testGroups`, `tcId`, `result`, `flags`, ...). They are Apache-2.0 (`vectors/LICENSE-APACHE-2.0.txt`). `vectors/derived_vectors.json` is **not** Wycheproof: it is generated by this lab and marked so.

**Provenance (read this before trusting the subsets).** The 16 cases were *not* copied from upstream C2SP/wycheproof: the upstream raw files could not be fetched from the authoring sandbox. They come from downstream copies, read as search-result text:
- AES-GCM tcId 1, 10-13: the Wycheproof 0.4-format `aes_gcm_test.json` shipped in pycryptodome 3.7.2, seen through a third-party package mirror (gemfury.com).
- Ed25519 tcId 1-6: BoringSSL's copy of `ed25519_test.json`; tcId 10-14 (`flags: ["v0"]`): BoringSSL's copy of the older `eddsa_test.json`.

Every value was checked against cryptography 50.0.2. That proves the valid cases are valid, not that upstream labels the invalid ones the same way. Full table: `vectors/NOTICE.md`; open item: KNOWN-GAPS 47.

**Check the provenance yourself.** `upstream_diff.py` looks up every vendored case **by content** (inputs plus expected result, not tcId) in an upstream `testvectors_v1/` folder. It exits 1 if a case is missing or disagrees. Offline it only prints the subsets' SHA-256:
```
vendored aes_gcm_subset.json  sha256 08ce9236634e72d90ce93f792865cc87cf58e2ea44697cd9d7cf4c24e7060cd8
vendored ed25519_subset.json  sha256 b1dc8bbcd28aad3b4525bccca70d02649d02fd3f26755a2224f3ae9beddf5632
offline: no upstream folder given, nothing compared (see README: 'Check the provenance yourself')
```
With a checkout (needs git and network; not run here). Commands:
- macOS (zsh): `git clone --depth 1 https://github.com/C2SP/wycheproof.git ../wycheproof-upstream && python upstream_diff.py --upstream ../wycheproof-upstream/testvectors_v1 --ref "$(git -C ../wycheproof-upstream log -1 --format='%H %cs')"`
- Windows (PowerShell): `git clone --depth 1 https://github.com/C2SP/wycheproof.git ..\wycheproof-upstream; python upstream_diff.py --upstream ..\wycheproof-upstream\testvectors_v1 --ref "$(git -C ..\wycheproof-upstream log -1 --format='%H %cs')"`

CI runs the same check on every push in the separate `wycheproof-upstream` job, which prints the upstream commit and date. A `match (upstream tcId N)` line means upstream renumbered the case; `MISSING upstream` means the copy differs from upstream. In that case, re-vendor from upstream and record the commit in `vendored`. `test_upstream_diff.py` tests the checker offline, against a fake upstream folder.

For the full suite: `git submodule add https://github.com/C2SP/wycheproof.git` and point `load()` at `wycheproof/testvectors_v1/` (current files use the v1 schemas; not run here).

## Timing demo (statistical, honest about noise)
```
naive loop           wrong at byte 0:    398 ns | wrong at byte 31:   1023 ns | ratio 2.57
hmac.compare_digest  wrong at byte 0:    119 ns | wrong at byte 31:    119 ns | ratio 1.00
A ratio well above 1 means time reveals how many leading bytes were right.
```
Seeded inputs, 7 interleaved rounds × 2,000 calls, medians. The ratio is the signal; absolute ns depend on the CPU (Apple silicon vs x64) and load. The unit test only asserts ratio > 1.3 for the naive loop and makes no timing claim for `compare_digest` (CI runners are noisy).

## If it fails
| Symptom | Action |
|---|---|
| Timing test fails on a busy CI runner | Rerun; the assertion is deliberately loose (ratio > 1.3). Never turn a timing test into a security proof. |
| `ValueError: min_tag_length must be >= 4` | pyca/cryptography refuses tags shorter than 4 bytes even in the low-level API. |
| A real Wycheproof file fails to load | Use the v1 files and their schema; group keys differ between files (e.g. `publicKey` for EdDSA). |
| `upstream_diff.py` prints `MISSING upstream` | The vendored copy differs from upstream (or upstream changed the case). Do not edit the expected result by hand: copy the case from the upstream file and record the commit. |
