# Set up your crypto workbench — explained

## The intuition
A crypto library is a black box: wrong output looks as random as right output. So the workbench first proves three things: you run the version you pinned, the engine underneath (OpenSSL bundled inside the `cryptography` wheel) is present, and each building block reproduces a *published* answer.

That last part is a **known-answer test (KAT)**: input from a standard in, the standard's printed output expected. An import proves loading; a KAT proves correct computation.

**Analogy:** calibrating a scale with a 1 kg reference weight. Where the analogy breaks: scales drift; a crypto bug is all-or-nothing, so one exact match suffices.

```
sanity_check.py
  ├─ __version__ == PINNED ("50.0.2")   -> cryptography_pinned
  ├─ backend.openssl_version_text()     -> openssl (bundled)
  ├─ sha256(b"abc") == NIST_ABC         -> sha256_known_answer
  ├─ AESGCM encrypt -> decrypt          -> aesgcm_roundtrip
  └─ Argon2id(...).derive(b"x")         -> argon2id_available
all booleans True ? "WORKBENCH OK" : "WORKBENCH NOT READY" (exit 1)
```

**The one thing to remember:** trust a crypto stack only after it reproduces a published answer.

## Walkthrough: what actually happens when you run it
1. **You run** `python sanity_check.py`. **What happens inside:** `run_checks()` builds a dict; booleans are gates, strings are information. `argon2id_available()` does a tiny real derive, because the import succeeds even when the backend is too old. **What you see:**
   ```
   cryptography           50.0.2
   cryptography_pinned    True
   openssl                OpenSSL 4.0.3 29 Sep 2026
   sha256_known_answer    True
   …
   WORKBENCH OK
   ```
   **What it means:** the OpenSSL line is the wheel's copy — this sandbox has no `openssl` CLI (`openssl: command not found`). Any `False` means fix before lesson 2.
2. **You run** `python -m unittest -v`. **What you see:** `Ran 3 tests in 0.009s`, `OK`. **What would look wrong:** `test_pinned_version` failing means another `cryptography` is first on `sys.path`.
3. **You run** `python try_it.py`. **What happens inside:** sets `lab.PINNED = "49.0.0"`, re-runs the checks, then hashes `abc\n`. **What you see:**
   ```
   1) PINNED=49.0.0 -> cryptography_pinned: False | WORKBENCH NOT READY
   2) sha256('abc\n') = edeaaff3…0efd18cb | matches NIST 'abc': False
   ```
   **What it means:** one failed gate flips the verdict; one extra newline byte changes the whole digest.
4. **You run** `printf abc | sha256sum`. **What you see:** `ba7816bf…f20015ad  -`, equal to `NIST_ABC`: an independent tool agrees.

## Common confusions
- **Q:** "`import cryptography` worked, so I'm set up." — **A:** Argon2id needs the backend; hence the real derive.
- **Q:** "My Mac's `openssl version` is what Python uses." — **A:** No; the `openssl` line is the bundled copy.
- **Q:** "`echo abc | shasum` should match NIST." — **A:** `echo` adds `\n`; try_it line 2 shows the mismatch.
