# Foundations I: number theory for public-key cryptography — explained

## The big picture
In L100–L400 you used public-key cryptography through a library. This lesson opens the box one level: arithmetic modulo n. Bézout gives inverses (RSA's d *is* one). Euler says exponentiation wraps around, so encryption and decryption can cancel. The CRT computes mod n via mod p and mod q — why RSA decryption is fast. Together they prove RSA *correct*. Labs explained: **Key exchange and hybrid encryption (X25519 + HKDF + AEAD)** (toy DH is its ancestor), **A local certificate authority** (certificate signatures rest on this algebra) and **Post-quantum cryptography in practice: ML-KEM, ML-DSA and hybrids** (why it all falls to a quantum computer). Lab code: `nt_toys.py`, cross-checked against pyca keys.

### Bézout's identity and the extended Euclidean algorithm
**In plain words.** Euclid finds gcd(a, b); two extra bookkeeping columns also give x, y with ax + by = gcd. If gcd = 1, x is a's inverse mod b.

**Why it is true (intuition).** Every remainder Euclid produces is a combination of a and b, because you only ever subtract multiples of one valid equation from another. Skeleton: (1) start with a = a·1 + b·0 and b = a·0 + b·1; (2) each step forms r' = old_r − q·r and updates the coefficients the same way; (3) common divisors survive the step, so the gcd never changes; (4) remainders shrink to 0, leaving gcd = a·x + b·y.

**See it in numbers.** `python theorem_checks.py`:
```
a*x + b*y = gcd(a, b) = math.gcd(a, b): 5000/5000 random 256-bit pairs
inverse exists exactly when gcd = 1 (and a*inv = 1 mod b): 5000/5000
egcd(240, 46) = (2, -9, 47) | modinv(17, 3120) = 2753
```
5000/5000 checks cryptographic-size numbers; the last line is problem 23-P1: 240·(−9) + 46·47 = 2.

**Where it shows up in practice.** RSA's `d` and pyca's `iqmp` are inverses; ECDSA (the P-256 CA in **A local certificate authority**) inverts a nonce.

### Euler's theorem (Fermat's little theorem as a corollary)
**In plain words.** If a shares no factor with n, raising a to the power φ(n) — the count of numbers below n coprime to n — gives 1 mod n.

**Why it is true (intuition).** Multiplying all units mod n by a just shuffles them. Skeleton: (1) list the φ(n) units r₁…r_φ; (2) a·rᵢ are again units, all different (a is invertible), so they are the same list reordered; (3) multiply both lists: a^φ · ∏rᵢ ≡ ∏rᵢ; (4) cancel ∏rᵢ (a unit).

**See it in numbers.**
```
exhaustive n = 2..400: 48677/48677 coprime pairs satisfy it
Fermat a^(p-1) = 1 (mod p), 303 primes < 2000, bases 2,3,5,7: 1208/1208
phi(3233) = 3120 = (61-1)*(53-1) = 3120; 2^560 mod 561 = 1 (561 is composite)
```
1208 = 303 × 4 bases minus 4 cases where base = prime. 561 passes Fermat yet is 3·11·17 — hence Miller–Rabin.

**Where it shows up in practice.** RSA correctness and primality testing in key generation.

### Chinese remainder theorem
**In plain words.** For coprime moduli, x mod 3, 5 and 7 pin down x mod 105, and arithmetic works part by part.

**Why it is true (intuition).** Build a "selector" for each modulus that is 1 there and 0 elsewhere. Skeleton: (1) Nᵢ = N/mᵢ is coprime to mᵢ, so it has an inverse yᵢ (Bézout); (2) Nᵢyᵢ ≡ 1 mod mᵢ and ≡ 0 mod the others; (3) x = Σ rᵢNᵢyᵢ hits every residue; (4) two solutions differ by a multiple of every mᵢ, hence of N — unique.

**See it in numbers.**
```
x -> (x mod 3, x mod 5, x mod 7) on 0..104: 105 distinct images (bijection onto 3*5*7 = 105)
pyca 2048-bit key: CRT decryption = plain decryption = m for 20/20 random m
pyca CRT parameters match ours: dmp1 = True | dmq1 = True | iqmp = True
```
105 distinct images: a bijection. OpenSSL stores exactly the CRT parameters the theorem needs.

**Where it shows up in practice.** RSA private-key operations run two half-size exponentiations — about 4× faster (23-P8).

### Correctness of RSA
**In plain words.** With n = pq and e·d ≡ 1 mod λ(n), raising to e and then to d returns every m — even the rare m sharing a factor with n.

**Why it is true (intuition).** Check the claim separately mod p and mod q, then glue with the CRT. Skeleton: (1) ed = 1 + t(p−1); (2) if p | m both sides are 0 mod p; (3) otherwise Fermat turns m^(ed) into m·1^t mod p; (4) same mod q; (5) CRT: equal mod p and mod q ⇒ equal mod n.

**See it in numbers.**
```
n = 3233 (61*53), e = 17, d = 2753: 3233/3233 messages round-trip, incl. 113 with gcd(m, n) > 1
pyca 2048-bit key (e = 65537): 45/45 round-trip (40 random + p, 5q, 0, 1, n-1)
```
113 = 61 + 53 − 1 multiples of p or q (0 counted once) — the cases Euler alone cannot handle. **Correct is not secure:**
```
Enc(65) = 2790; attacker sends c * 2^e mod n = 3017; Dec = 130 (= 2 * 65)
```

**Where it shows up in practice.** Malleability is why real systems use OAEP or a KEM — and the labs use X25519 and ML-KEM.

## Worked problems
**23-P5 (textbook RSA, p = 61, q = 53, e = 17).**
1. n = 61·53 = 3233. *Why:* the public modulus.
2. φ(n) = 60·52 = 3120. *Why:* units mod pq; d must invert e mod φ (or λ).
3. d = 17⁻¹ mod 3120 = 2753 by extended Euclid. *Why:* ed ≡ 1 is what RSA correctness needs; check 17·2753 = 15·3120 + 1.
4. c = 65¹⁷ mod 3233 = 2790. *Why:* encryption; the check prints `Enc(65) = 2790`.
5. c' = 2790·2¹⁷ mod 3233 = 3017. *Why:* (2m)^e = 2^e·m^e — the attacker needs only the public key.
6. Dec(c') = 130 = 2·65. *Why:* decryption undoes e. The problem: a keyless attacker changed the plaintext predictably.

**23-P2 (x ≡ 2 mod 3, x ≡ 3 mod 5, x ≡ 2 mod 7).**
1. N = 105; N₁ = 35, N₂ = 21, N₃ = 15. *Why:* each Nᵢ vanishes mod the others.
2. y₁ = 35⁻¹ mod 3 = 2 (35 ≡ 2, 2·2 = 4 ≡ 1); y₂ = 21⁻¹ mod 5 = 1; y₃ = 15⁻¹ mod 7 = 1. *Why:* make each selector ≡ 1 at its own modulus.
3. x = 2·35·2 + 3·21·1 + 2·15·1 = 140 + 63 + 30 = 233. *Why:* sum of residue × selector.
4. 233 mod 105 = 23. *Why:* the answer is unique mod N; check: 23 = 7·3+2 = 4·5+3 = 3·7+2, matching `crt([2, 3, 2], [3, 5, 7]) = 23`.

## Common confusions
- **Q:** "If a^(n−1) ≡ 1 mod n, n is prime." — **A:** `2^560 mod 561 = 1` with 561 composite.
- **Q:** "RSA only works for m coprime to n." — **A:** `incl. 113 with gcd(m, n) > 1` round-trip too.
- **Q:** "Correct RSA is secure RSA." — **A:** `Dec = 130 (= 2 * 65)`: textbook RSA is malleable and deterministic.
