# A local certificate authority — explained

## The intuition
Lesson 7 ended with an open question: how do you know a public key really belongs to `localhost` (or `bank.example`)? A **certificate** is the answer: a small document that says "this public key belongs to these names, valid between these dates", signed by a **certificate authority (CA)**. Clients accept the key if a CA in their trust store signed it, the name matches and the dates are right.

A local CA is the same machinery on your laptop: one self-signed root (issuer == subject) you add to your own trust store, which then issues short-lived server certificates. Code shows which fields the verifier reads: **SAN** (not the Common Name), `BasicConstraints`, key usages, and validity.

**Analogy:** a passport. The issuing country (CA) vouches for name and photo (public key) with an expiry date; border control (the client) trusts only a list of countries. Where the analogy breaks: the verifier never "phones home" by default — revocation is a separate problem (lesson 13).

```
make_root(): EC P-256 key ─ self-signs ─▶ root (CA:True, path_length=0, keyCertSign)
issue_server(ca_key, root): new key ─▶ leaf (SAN localhost,127.0.0.1; CA:False; EKU serverAuth; 30 d)
verify(leaf, roots=[root], "localhost", at=NOW)
   PolicyBuilder().store(Store(roots)).time(at).build_server_verifier(DNSName)
   ─▶ chain [leaf, root]  |  VerificationError(reason)
```

**The one thing to remember:** a certificate is a CA's signed statement binding names and dates to a public key — and the client must check all three.

## Walkthrough: what actually happens when you run it
1. **You run** `python local_ca.py`. **What happens inside:** `make_root` self-signs a CA; `issue_server` makes a key pair and the root signs a leaf. **What you see:**
   ```
   root: CN=KB Local Root CA | CA: True
   leaf SAN: ['localhost', '127.0.0.1']
   leaf valid: 2026-11-02 -> 2026-12-02
   ```
2. **Verify, then fail three ways.** `verify` uses pyca's Rust path validator (RFC 5280 plus the web-PKI profile). **What you see:**
   ```
   localhost              OK, chain length 2
   wrong host             FAIL: validation failed: leaf certificate has no matching subjectAltName
   31 days later          FAIL: validation failed: cert is not valid at validation time
   untrusted root         FAIL: validation failed: candidates exhausted: all candidates exhausted with no interior errors
   ```
   **What it means:** chain length 2 = leaf + root. "Candidates exhausted" is the verifier's way of saying no trusted issuer was found.
3. **You run** `python local_ca.py --out pki` (here written to a scratch folder). **What you see:** `wrote ca.pem, server.pem, server-key.pem` — the inputs for lesson 10.
4. **You run** `python try_it.py`. **What you see:**
   ```
   1) ask localhost       FAIL: validation failed: leaf certificate has no matching subjectAltName
   1) ask ip-only.test    OK, chain length 2
   2) DER 422 B, PEM 627 B, ratio 1.49; DER->cert == PEM->cert: True
   ```
   **What it means:** only SAN entries count; PEM is base64 of DER plus header lines.
5. **You run** `python agent_assist.py`. **What happens inside:** `diagnose()` derives a category from public fields (issuer signature, then not-before, not-after, SAN); the fake model proposes one; code compares. **What you see:**
   ```
   clock skew    verifier=FAIL  code says NOT_YET_VALID     agent says EXPIRED           REJECTED
   VERDICTS come from the verifier; categories from diagnose(); the agent only explains.
   ```
   **What it means:** a cert not valid *yet* (server clock behind) looks like "expired" to a model; the code catches the misreading.
6. `python -m unittest` → `Ran 13 tests in 1.433s`, `OK`.

## Common confusions
- **Q:** "The CN is the hostname." — **A:** Clients match SAN only; try_it 1 fails on a name absent from SAN.
- **Q:** "Self-signed means insecure." — **A:** Every root is self-signed; what matters is whether *you* chose to trust it.
- **Q:** "Expired and not-yet-valid are the same error." — **A:** Same verifier message, different fix (renew vs. fix the clock); `diagnose()` separates them.
