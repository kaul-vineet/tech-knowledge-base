# Hashing and integrity: SHA-256 and HMAC — explained

## The intuition
SHA-256 turns any input — three letters or a 1 MB release — into a 32-byte fingerprint. Same input, same fingerprint; change one byte and about half the output bits flip. Perfect for "is this the file that was published?"

But a plain hash has no secret: whoever swaps the file can recompute it. **HMAC** mixes a secret key into the hash, so only key holders can produce a valid tag.

**Analogy:** a hash is a fingerprint; an HMAC is a wax seal from your signet ring. Where the analogy breaks: everyone holding the same (shared) key can seal, so HMAC cannot prove *which* holder did.

```
release.bin --sha256_file (64 KiB chunks)--> digest --vs published--> MATCH / MISMATCH
msg + key --hmac.new(key, msg, sha256)--> tag --compare_digest--> True / False
```

**The one thing to remember:** a hash detects change; only a keyed MAC detects *forgery*.

## Walkthrough: what actually happens when you run it
1. **You run** `python hash_and_hmac.py`. **What happens inside:** `sha256_text` encodes UTF-8, hashes, compares with NIST vectors. **What you see:**
   ```
   sha256('abc')        ba7816bf…f20015ad True
   sha256('')           e3b0c442…7852b855 True
   ```
2. **File section.** `sha256_file` streams chunks; `os_sha256` runs the first OS tool on PATH and regex-extracts 64 hex chars. **What you see:**
   ```
   file (python)        e23c0cda…48e5898d
   file (OS tool)       e23c0cda…48e5898d via sha256sum
   stdlib file_digest   e23c0cda…48e5898d
   ```
   **What would look wrong:** `None via None` — no OS tool found.
3. **Tamper.** Opens the file `r+b`, seeks to byte 500000, writes `B`. **What you see:** `after 1-byte tamper  64ae272a… MISMATCH -> tampered`.
4. **HMAC.** **What you see:**
   ```
   HMAC RFC4231 TC2     5bdcc146…64ec3843 True
   verify good msg      True
   verify edited msg    False
   verify wrong key     False
   ```
   **What it means:** `verify_hmac` recomputes and uses `hmac.compare_digest`, which never exits early on the first differing character.
5. **You run** `python try_it.py`. **What you see:**
   ```
   1) chunk sizes [7, 4096, 65536] -> distinct digests: 1 | …
   2) jefe tag: f5886a2776d40a67... | verifies against Jefe tag: False | bits differing: 136 of 256
   ```
   **What it means:** chunking is invisible to the hash; a one-letter key change flips about half the bits.
6. `python -m unittest` → `Ran 4 tests`, `OK`.

## Common confusions
- **Q:** "A SHA-256 next to the download stops attackers." — **A:** Only if the digest travels on a channel they cannot edit.
- **Q:** "`tag == expected` is fine." — **A:** `==` can return early; use `compare_digest`.
- **Q:** "Bigger chunks hash differently." — **A:** try_it line 1: `distinct digests: 1`.
