# Authenticated encryption: AES-256-GCM and ChaCha20-Poly1305 — explained

## The intuition
Plain encryption hides data but does not stop silent *changes*. **AEAD** adds a 16-byte tag over the ciphertext plus unencrypted context (the AAD, e.g. `user_id=42`). Decryption is all-or-nothing: plaintext, or `InvalidTag`.

Each message needs a fresh 12-byte **nonce**: public, but never repeated under one key.

**Analogy:** a tamper-evident envelope with the address printed outside: readable, but changing it or the contents breaks the seal. Where the analogy breaks: reusing a nonce does not just weaken the seal — it leaks the XOR of two plaintexts.

```
seal:  nonce = os.urandom(12)
       blob  = nonce || encrypt(key, nonce, pt, aad)   # ct || 16-byte tag
open_: decrypt(key, blob[:12], blob[12:], aad) -> pt  | InvalidTag
```

**The one thing to remember:** never use encryption without authentication, and never reuse a nonce under one key.

## Walkthrough: what actually happens when you run it
1. **You run** `python aead_demo.py`. **What happens inside:** published vectors are encrypted and compared. **What you see:**
   ```
   RFC 8439 2.8.2 ChaCha20-Poly1305 vector: True
   GCM spec TC14 AES-256-GCM vector:        True
   ```
2. **Round trip and tampering** (same run, both ciphers). `seal()` prefixes the nonce; the script flips a ciphertext bit, then changes the AAD. **What you see:**
   ```
   --- AES-256-GCM (blob 42 bytes = 12 nonce + 14 ct + 16 tag)
     decrypt ok         card=4111-1111
     1 bit flipped      InvalidTag (rejected)
     AAD changed        InvalidTag (rejected)
   ```
   ChaCha20-Poly1305 prints the same three lines. **What it means:** the AAD was never encrypted, yet changing it is detected.
3. **Nonce reuse.** Two messages under the same key and nonce. **What you see:**
   ```
   nonce reuse leaks p1^p2: True
   attacker who knows p1 recovers p2: b'retreat at dusk!'
   ```
   **What it means:** same nonce, same keystream; XOR cancels it.
4. **You run** `python try_it.py`. **What you see:**
   ```
   1) nonce bit flipped -> InvalidTag (rejected)
   2) plaintext    0 B -> blob   28 B (overhead 28 B)
   2) plaintext 1000 B -> blob 1028 B (overhead 28 B)
   ```
   **What it means:** the nonce is authenticated too; overhead is constant 28 bytes (12 nonce + 16 tag).
5. `python -m unittest` → `Ran 5 tests`, `OK`.

## Common confusions
- **Q:** "The nonce is secret like the key." — **A:** It sits in clear in `blob[:12]`; uniqueness matters, not secrecy.
- **Q:** "AAD is encrypted." — **A:** Authenticated only; `AAD changed` fails, but anyone can read it.
- **Q:** "On `InvalidTag` I can still use the partial plaintext." — **A:** The API returns none; treat the blob as hostile.

## Check your understanding

2. What is the size of a sealed 14-byte message?
<details><summary>Answer</summary>42 bytes: 12 + 14 + 16.</details>
3. When is ChaCha20-Poly1305 preferred over AES-GCM?
<details><summary>Answer</summary>On CPUs without AES hardware instructions, where it is faster and constant-time in software.</details>
