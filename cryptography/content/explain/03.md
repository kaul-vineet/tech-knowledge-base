# Secure randomness: secrets vs random — explained

## The intuition
Keys, tokens and nonces are only secret if nobody can *predict* them. Python's `random` (Mersenne Twister) is deterministic: same seed, same numbers forever. Seed it with the clock and an attacker who knows roughly *when* you generated a token can simply try every second.

`secrets` uses the OS's cryptographically secure generator (CSPRNG): no guessable seed.

**Analogy:** `random.Random(clock)` is a combination lock whose code is today's date — "random-looking", trivially guessable once you know the rule. Where the analogy breaks: a CSPRNG has no learnable rule at all.

```
issued_at (unix seconds) --random.Random(seed)--> getrandbits(128) --> reset token (leaked)
attacker: for t in now-3600 .. now+3600: insecure_reset_token(t) == token ?  -> seed -> mint more
secrets.token_hex(16) <-- os CSPRNG          (scan finds None)
```

**The one thing to remember:** if a value guards anything, generate it with `secrets`, never with `random`.

## Walkthrough: what actually happens when you run it
1. **You run** `python randomness.py`. **What happens inside:** `secure_material()` calls `token_urlsafe(32)`, `token_hex(16)`, `token_bytes(32)` and `token_bytes(12)`. **What you see** (values differ every run):
   ```
   api_token_urlsafe  fZY7qc_gJ8QoEeO_ZIq1VycPIj0kKriQIHq2uEO44a8
   aes256_key         40aa9a48…f9f9ecc7
   gcm_nonce          8aee0593f6782e2e50409142
   ```
   **What it means:** 43 URL-safe characters = 32 bytes; the key is 64 hex chars (32 bytes); the nonce 24 hex chars (12 bytes). Hex length is double the byte length.
2. **The attack.** `issued_at` is set 1234 s in the past, the token is minted from `random.Random(issued_at)`, then `attacker_recovers` replays 7,201 candidate seeds. **What you see:**
   ```
   attacker found seed  1793621970 == issued_at: True (0.095s)
   attacker can mint    True
   ```
   **What it means:** under a tenth of a second to recover the seed — and with it the ability to mint any future token.
3. **Determinism check.** **What you see:** `same seed same token True`, `secrets differs      True`.
4. **You run** `python try_it.py`. **What you see:**
   ```
   1) token issued 2 h ago, window +/-1 h -> attacker finds: None
      same token, window +/-3 h       -> attacker finds seed == issued_at: True
   2) secrets.token_hex(16) scanned over 7,201 seeds -> attacker finds: None
   ```
   **What it means:** a narrow window only delays the attacker; against `secrets` no window helps.
5. `python -m unittest` → `Ran 3 tests`, `OK`.

## Common confusions
- **Q:** "Seeding with `time.time_ns()` fixes it." — **A:** It enlarges the search, not the principle; the seed is still guessable.
- **Q:** "The token *looks* random, so it is." — **A:** Line 2 of the run printed a random-looking token that was recovered.
- **Q:** "`token_bytes(32)` gives 32 bits." — **A:** 32 *bytes* = 256 bits; see the 64-hex-char key.
