# Encoding vs hashing vs encryption — explained

## The intuition
Three tools make bytes look like gibberish. **Encoding** (base64, hex) only changes the alphabet — anyone can reverse it. **Hashing** (SHA-256) is a one-way, deterministic fingerprint. **Encryption** (AES-GCM) is reversible *only* with a key, and randomised.

**Analogy:** encoding is Morse code; hashing a shredder leaving a unique confetti pattern; encryption a safe. Where the analogy breaks: identical pages give identical confetti, so low-entropy inputs can be guessed.

```
SECRET ──base64/hex──▶ reversible by anyone        (no key)
       ──sha256──────▶ one-way, deterministic       (no key)
       ──AES-GCM(key, fresh nonce)──▶ reversible only with key, randomised
review_me.txt ──misuse_lint (AST)──▶ findings ──judge──▶ agent claims: CONFIRMED / MISSED / REJECTED
```

**The one thing to remember:** base64 is not protection; if there is no key, there is no secret.

## Walkthrough: what actually happens when you run it
1. **You run** `python compare.py`. **What happens inside:** `encode`, `hash_`, `encrypt` run on the same secret. **What you see:**
   ```
   encoding/base64  none    yes, by anyone  ZGJfcGFzc3dvcmQ9U3VwM3JTM2NyZXQ=
   hash/SHA-256     none    no (one-way)    df1e2c750bcd…
   encrypt/AES-GCM  secret  only with key   9EazfX7xtCFX…
   decrypt with wrong key -> InvalidTag
   hash is deterministic  -> True
   encryption randomised  -> True
   ```
2. **You run** `echo ZGJfcGFzc3dvcmQ9U3VwM3JTM2NyZXQ= | python -m base64 -d`. **What you see:** `db_password=Sup3rS3cret`.
3. **You run** `python misuse_lint.py`. **What happens inside:** it parses `review_me.txt` with `ast`, never executing it. **What you see:**
   ```
   CRY001 line 9: random.choice() is a predictable PRNG
   CRY002 line 21: AEAD nonce is a constant (reused per key)
   CRY003 line 13: hashlib.md5() used on a password
   ```
4. **You run** `python agent_assist.py`. **What happens inside:** `find_secrets` blocks key-like snippets; the fake model answers; `judge` compares claims with the linter. **What you see:**
   ```
   CONFIRMED CRY001 line 9 …
   MISSED    CRY002 line 21 …
   REJECTED  CRY003 line 17  agent claim not backed by the linter …
   VERDICT (from linter, not agent): FAIL - 3 misuse(s)
   ```
   **What it means:** the agent flagged `file_id` (SHA-256 of file data — fine) and missed the constant nonce. Code, not the model, decides.
5. **You run** `python try_it.py`. **What you see:** `2) base64 chars changed: 1 of 32 | sha256 hex chars changed: 56 of 64`. Encoding is local; hashing avalanches.
6. `python -m unittest` → `Ran 12 tests`, `OK`.

## Common confusions
- **Q:** "Kubernetes Secrets are base64, so they are encrypted." — **A:** Step 2 decodes one with no key.
- **Q:** "Hashing a password is encrypting it." — **A:** No key and no way back; and fast hashes are CRY003.
- **Q:** "The agent's review is the verdict." — **A:** The VERDICT line says "from linter, not agent".
