# Post-quantum cryptography in practice: ML-KEM, ML-DSA and hybrids — explained

## The intuition
A large quantum computer would break the discrete logs behind X25519 and Ed25519. None exists yet, but an attacker can **record traffic now and decrypt it later**. For data secret for ten years, the key exchange must resist that future attacker today. Signatures are less urgent: a 2035 forgery cannot change a 2026 handshake.

NIST's answers are **ML-KEM** (FIPS 203) and **ML-DSA** (FIPS 204), lattice-based, newer and much bigger than curves. So production runs a **hybrid**: X25519 *and* ML-KEM-768 into one KDF, safe while *either* holds. But only if the client is strict: accept a classical-only answer and an on-path attacker strips the post-quantum part — the injected fault.

**Analogy:** a door with two different locks from two manufacturers; a burglar must pick both. Where the analogy breaks: with a door you can see both locks; in a handshake the attacker can swap the door for a one-lock version in transit, and only a length check tells the client.

```
client_hello: share = ML-KEM-768 pk (1184 B) ‖ X25519 pub (32 B) = 1216 B ───────────▶
server_respond: (ct, ss_pq) = encapsulate(pk); ss_x = X25519 ──▶ share = ct (1088) ‖ x_pub (32) = 1120 B
client_finish(st, server_share):
   len == 1120 ─▶ ss_pq = decapsulate(ct); ss_x = exchange(...) ─▶ key = HKDF(ss_pq ‖ ss_x, transcript)
   BUG: else  ─▶ X25519 only ("fallback")       FIX: else ─▶ handshake_abort, illegal_parameter
```

**The one thing to remember:** a hybrid protects you only if a malformed or shortened share aborts the handshake instead of falling back.

## Walkthrough: what actually happens when you run it
1. **You run** `python pq_hybrid.py`. **What happens inside:** `sizes()` generates real keys with pyca/cryptography 50.0.2 and measures each share. **What you see:**
   ```
   {"kem": "X25519", "client_share": 32, "server_share": 32, "secret": 32, "on_wire": 64}
   {"kem": "ML-KEM-768", "client_share": 1184, "server_share": 1088, "secret": 32, "on_wire": 2272}
   {"kem": "X25519MLKEM768", "client_share": 1216, "server_share": 1120, "secret": 64, "on_wire": 2336}
   1) hybrid handshake: client share 1216 B, server share 1120 B, keys match: True, mode: X25519MLKEM768
   2) quantum attacker with X25519 broken recovers the key: False
   ```
   **What it means:** 2336 vs 64 bytes on the wire. Line 2 is `harvest_then_break`: computing X25519 secrets still leaves `ss_pq` unknown. `derive()` hashes both shares into HKDF's `info`, binding the key to the transcript.
2. **The fault.** **What you see:**
   ```
   --- fault: an on-path attacker rewrites the server share to its X25519 part only (downgrade)
   client accepted a 32-byte server share | mode: X25519 (fallback) | quantum attacker recovers key: True
   ```
   **What happens inside:** if `len != MLKEM_CT + X_LEN`, `client_finish` takes the last 32 bytes as an X25519 key: silently classical.
3. **You run** `python try_it.py`. **What you see:**
   ```
   1) SecP384r1MLKEM1024: client share 1665 B, server share 1665 B, on wire 3330 B (X25519MLKEM768: 2336 B)
   2) root+leaf certificates + CertificateVerify: Ed25519 478 B, ML-DSA-65 14106 B (30x)
   ```
   **What it means:** the higher-security hybrid is 1.4× larger; post-quantum *certificates* are 30× larger — why the ADR delays them.

## The decision
**Options measured** (`python pq_measure.py`; timings are medians here and vary):
```
{"option": "X25519", "on_wire_bytes": 64, "handshake_us": 144.8, "safe_if_CRQC_exists": false, "safe_if_lattice_break": true}
{"option": "ML-KEM-768", "on_wire_bytes": 2272, "handshake_us": 187.8, "safe_if_CRQC_exists": true, "safe_if_lattice_break": false}
{"option": "X25519MLKEM768", "on_wire_bytes": 2336, "handshake_us": 431.5, "safe_if_CRQC_exists": true, "safe_if_lattice_break": true}
{"signature": "ML-DSA-65", "public_key_bytes": 1952, "signature_bytes": 3309, "sign_us": 1156.0, "verify_us": 202.3}
```
- **A, X25519 only:** smallest and fast, but `safe_if_CRQC_exists: false` fails the 10-year constraint.
- **B, ML-KEM-768 only:** quantum-safe, but `safe_if_lattice_break: false` — one young scheme is a single point of failure.
- **C, hybrid:** the only row with both `true`; 2336 B fits the 2,400 B budget; about 3× the X25519 time (431.5 vs 144.8 µs here; README 390.5 vs 140.7).

ADR-0018 chose **C** with a strict client, HPKE `MLKEM768_X25519` for stored data, and ADR-0017 dual signatures instead of ML-DSA certificates for now.

### Failure lab: silent classical fallback
- **Inject:** the attacker cuts the server share to 32 bytes (or 33; `random.Random(18)` picks).
- **Symptom:** `mode: X25519 (fallback) | quantum attacker recovers key: True` in step 2.
- **Diagnose:** the client let the *size of the message* choose the algorithm — the same mistake as `alg:none` in lesson 11.
- **Fix:** accept exactly 1,120 bytes, otherwise log and raise (RFC 10024 §4.2: abort with illegal_parameter). **You run** `python solution_strict.py`. **What you see:**
  ```
  normal: X25519MLKEM768 | keys match: True
  {"event": "handshake_abort", "alert": "illegal_parameter", "share_bytes": 32}
  downgraded 32-byte share: refused (illegal_parameter: X25519MLKEM768 server share must be 1120 bytes, got 32)
  ```
  and the same refusal for 33 bytes.
- **Proof:** `BUILD_TARGET=mine python -m unittest -v test_build_task` before the fix: `FAIL: test_downgraded_share_is_refused`, `FAIL: test_one_extra_byte_is_refused`, `FAILED (failures=2)`; the solution: `Ran 3 tests in 0.058s`, `OK`.

**Fitness function.** `test_fitness_pq_policy.py` reads `pq_policy.json` and fails if a classical-only group appears, if key shares exceed 2,400 B, or if the deployed client accepts a downgraded share. Full suite: `Ran 15 tests in 0.011s`, `OK (skipped=2)` — liboqs-python is missing, and the TLS probe needs Python 3.15+ with OpenSSL 3.5+. Expected (not run here): `oqs_crosscheck.py` shows liboqs and pyca agreeing on ML-KEM-768 secrets in both directions; `pq_tls_probe.py` reports a real TLS 1.3 handshake negotiating X25519MLKEM768.

## Common confusions
- **Q:** "Post-quantum means replacing X25519." — **A:** The hybrid keeps it; option B's `safe_if_lattice_break: false` is why.
- **Q:** "Signatures need migrating first." — **A:** Recorded traffic threatens key exchange now; the ADR keeps classical certificates (478 B vs 14106 B).
- **Q:** "A 33-byte share is just a corrupt packet, so retry classically." — **A:** Any length other than 1120 aborts; retrying classically is exactly the downgrade.
