# Misuse you can test: Wycheproof vectors, timing and nonce reuse — explained

## The intuition
The primitives are well tested; the thin wrappers around them are not: a helper accepting shorter tags "for compatibility", a signature check trimming extra bytes, a compare written as a loop, a nonce counter that restarts. Each passes normal unit tests.

Project Wycheproof collects the strange inputs instead: vectors labelled `valid` or `invalid`, with flags saying why (`TruncatedTag`, `NonCanonicalS`…). Running your wrapper over them turns "is my crypto code strict?" into a pass/fail number. The lab adds two more testable misuses: **timing** (an early-exit compare leaks how many leading bytes were right) and **nonce reuse** (two AES-GCM messages under one key and nonce leak the XOR of their plaintexts).

**Analogy:** a bouncer trained on real IDs, then shown fakes — a half-cut hologram, an extra digit. Where the analogy breaks: a bouncer who "repairs" a damaged card in his head is being kind; a verifier that reduces `S mod L` creates a second valid signature the signer never made.

```
vectors/*.json (tests{tcId, result, flags}) ─▶ run(aead_open, sig_verify) ─▶ wrapper verdict vs "result"
   lenient aead_open: modes.GCM(iv, tag, min_tag_length=max(4, len(tag)))   ← 4-byte tags pass
   lenient sig_verify: s % L, bytes after 64 ignored                          ← "repairs" bad sigs
timing_demo: naive loop (early exit) vs hmac.compare_digest
nonce_guard: GuardedAESGCM tripwire (in-process) + scan_for_reuse (offline, across restarts)
```

**The one thing to remember:** crypto wrappers must reject anything not exactly well-formed — and vectors, not happy-path tests, prove it.

## Walkthrough: what actually happens when you run it
1. **You run** `python wycheproof_check.py`. **What happens inside:** `aead_cases()` and `eddsa_cases()` load the vendored subsets plus `derived_vectors.json` (generated by the lab, not Wycheproof); `run()` calls the lenient wrappers. **What you see:**
   ```
   aes_gcm_subset.json    5/5 pass
   derived_vectors.json   1/5 pass
   ed25519_subset.json    11/11 pass
     FAIL tcId 9001 ['TruncatedTag']: expected invalid, wrapper said valid
     …
     FAIL tcId 9102 ['NonCanonicalS']: expected invalid, wrapper said valid
   ```
   **What it means:** the subsets never reach the lenient branches; the derived vectors do. "Said valid wrongly" is the dangerous direction.
2. **You run** `python try_it.py`. **What you see:**
   ```
   1) 4-byte tag accepted by lenient wrapper: True | forgery odds per try: 1 in 4,294,967,296 (16-byte tag: 1 in 2**128)
   2) naive loop, wrong at byte 0/8/16/31: 558 ns < 727 ns < 895 ns < 1178 ns | increasing: True
   ```
   **What it means:** 2³² guesses is feasible online. Loop time grows with the matching prefix (README: 567/730/897/1187 ns; values vary, the trend does not).
3. **You run** `python timing_demo.py`. **What you see:**
   ```
   naive loop           wrong at byte 0:    403 ns | wrong at byte 31:   1035 ns | ratio 2.57
   hmac.compare_digest  wrong at byte 0:    123 ns | wrong at byte 31:    123 ns | ratio 1.00
   ```
   Medians of 7 rounds × 2,000 calls; README had 398/1023 and 119 ns with the same ratios.
4. **You run** `python nonce_guard.py`. **What you see:**
   ```
   in-process tripwire: NonceReuseError on the 2nd seal with the same nonce
   buggy seeded nonces  2 restarts x 2 messages: tripwire silent, offline scan finds 2 reused [[0, 2], [1, 3]]
   attacker knows run-1 message 0, recovers run-2 message 0: b'pay mal 9999'
   ```
   **What it means:** an in-memory set cannot see across restarts; a scan of stored ciphertexts can.

### Failure lab: lenient wrappers
- **Inject:** the shipped `aead_open` accepts tags ≥ 4 bytes; `sig_verify` uses `sig[32:64] % L` and ignores trailing bytes.
- **Symptom:** step 1's `derived_vectors.json   1/5 pass` with FAIL lines for tcIds 9001, 9002, 9101, 9102.
- **Diagnose:** each flag names the branch: `TruncatedTag` → `min_tag_length`; `TrailingBytes` → no length check; `NonCanonicalS` → `% L`.
- **Fix:** `solution_strict.py` requires a 12-byte IV and 16-byte tag (high-level `AESGCM`) and exactly 64-byte signatures with `S < L`. **You run** `python solution_strict.py`. **What you see:** `derived_vectors.json   5/5 pass`.
- **Proof:** before the fix, `BUILD_IMPL=wycheproof_check python -m unittest -v test_build_task` prints three `FAIL:` lines and `FAILED (failures=3)`; against the solution `Ran 3 tests in 0.024s`, `OK`. Full suite: `Ran 12 tests in 0.072s`, `OK`.
5. **Provenance.** Expected (not run here, needs network): `upstream_diff.py --upstream …` exits 1 if a vendored case is missing from a C2SP/wycheproof checkout.

## Common confusions
- **Q:** "The vendored subsets pass, so the wrapper is fine." — **A:** `5/5` and `11/11` passed while `derived_vectors.json 1/5` exposed four bugs.
- **Q:** "Timing leaks need nanosecond-precise attackers." — **A:** Attackers average many requests, as `timing_demo.py` takes medians; the ratio 2.57 is stable.
- **Q:** "An in-process nonce check prevents reuse." — **A:** `tripwire silent` across restarts; the offline scan found `[[0, 2], [1, 3]]`.
