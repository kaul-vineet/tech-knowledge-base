# Crypto agility: versioned envelopes, negotiation and dual signing — explained

## The intuition
Data encrypted today may be read in ten years, and by then some algorithm you chose will need replacing — Ed25519 because of quantum computers, an AEAD after an incident. If the algorithm is *implied by the code*, switching is a flag day: rewrite every record first, or make readers guess. Crypto agility means the data *says* which algorithm protected it, and one place in the code — a registry — decides what is allowed.

Three ideas carry the lab. An **envelope header** names the algorithm (`aead`) and key (`kid`) and is authenticated as AAD. A **registry** gives each identifier a status: active, deprecated (read only), disallowed. A **policy phase** (`classic → transition → pq-only`) tells the verifier which signatures are required. The injected bug lives there: if the *envelope* decides which signatures count, an attacker leaves out the one they cannot forge.

**Analogy:** library spine labels name a book's classification scheme; the catalogue (registry) says which schemes are current, legacy or withdrawn, and books are reshelved as borrowed. Where the analogy breaks: a book cannot lie about its label, an envelope can — hence AAD, and a policy-owned list of required signatures.

```
seal(ring, kid, data, ctx, signers):
   alg, key = ring.entries[kid]; header {v:2, aead: alg, kid, n, ctx}  ──AAD──▶ reg.aead(alg, key).encrypt
   sigs = [reg.sign(a, key, signed_bytes) for a in reg.signing_algorithms()]   (Ed25519 + ML-DSA-65)
open_(ring, env): reg.get(env.aead) status? disallowed ─▶ refuse | active/deprecated ─▶ decrypt
verify(env, pubkeys):   BUG: any(valid sig in env["sigs"])
                        FIX: all(valid sig for a in reg.required_signatures())   ← policy phase decides
agility_lint.py (CI): no primitive imports / algorithm names outside registry.py
```

**The one thing to remember:** the data names its algorithms, but the verifier's policy — never the data — decides which ones are acceptable and required.

## Walkthrough: what actually happens when you run it
1. **You run** `python agile_envelope.py`. **What happens inside:** `seal()` asks the keyring which algorithm `dk-1` is bound to, builds the v2 header, encrypts with the header as AAD, and signs with every algorithm the registry lists. **What you see:**
   ```
   1) sealed 3 docs | header: {'v': 2, 'aead': 'A256GCM', 'kid': 'dk-1'} | ct bytes: 37 | sigs: [('Ed25519', 64), ('ML-DSA-65', 3309)]
   2) default -> C20P1305 | opened: 4 of 4
   {"metric": "envelopes_by_aead", "A256GCM": 3, "C20P1305": 1}
   ```
   **What it means:** switching the default was a policy change; all four documents still open — no flag day.
2. **Negotiation and legacy.** **What you see:**
   ```
   3) negotiate: A256GCM | only A128CBC offered -> no common active algorithm in ['A128CBC']
   4) legacy v1 opens: invoice 0: amount=0 | migrate -> {'v': 2, 'aead': 'C20P1305', 'kid': 'dk-2'}
   ```
   **What happens inside:** `negotiate()` walks *our* preference list, active algorithms only, and raises rather than falling back. A v1 envelope opens through `LEGACY_V1_AEAD` and is re-sealed as v2.
3. **You run** `python try_it.py`. **What you see:**
   ```

   2) orders/storage.py:1: imports cryptography.hazmat.primitives.ciphers.aead
   ```

   **What it means:** disallowing is the real deletion step (like lesson 12's retire) — watch the metric reach 0 first. Line 2 is the fitness function catching a module that bypasses the registry.

## The decision
**Options measured** (`python measure_options.py`, 1,000 documents of 1 KiB):
```
{"option": "A one algorithm, no id", "header_bytes": 43, "swap_rewrites_before_switch": 1000, "trial_decryptions_per_read": 2.0, …}
{"option": "B per-algorithm ids + registry", "header_bytes": 74, "extra_header_bytes_vs_A": 31, "swap_rewrites_before_switch": 0, "old_docs_readable_after_switch": "1000/1000", "dual_signature_bytes": 3373}
{"option": "C suite ids", "ids_needed_for_suites": 6, "ids_needed_per_algorithm": 4, "after_adding_one_aead": 9}
{"per_algorithm": {… "ML-DSA-65": {"sig_bytes": 3309, "sign_us": 864.3, "verify_us": 195.4}}}
```
- **A**: smallest header, but a swap means 1,000 rewrites first, or 2.0 trial decryptions per read after.
- **B**: +31 header bytes, 0 rewrites, 1000/1000 old documents readable; real cost is 3,373 bytes of dual signatures.
- **C**: 6 suite ids today, 9 after one new AEAD — combinatorial growth (RFC 7696).

ADR-0017 chose **B**, with keys bound to one algorithm, policy-driven signatures and no negotiation fallback. Timings vary (ML-DSA-65 sign 864.3 µs here vs 1,380.1 µs in the README); sizes and counts match exactly.

### Failure lab: signature stripping
- **Inject:** the Ed25519 key leaked; a co-tenant edits document 4 (victim from `random.Random(17)`) and re-signs it with Ed25519 only.
- **Symptom:** `legit verify: True | forged doc-4 verify: True | sigs on forged: ['Ed25519']`.
- **Diagnose:** `verify()` returns `any(...)` over the envelope's own `sigs` list — the attacker chose the list.
- **Fix:** loop over `registry.required_signatures()` and require each. **You run** `python solution_agile.py`. **What you see:**
  ```
  phase: transition | required: ['Ed25519', 'ML-DSA-65']
  legit verify: True | stripped (Ed25519 only) verify: False
  phase: pq-only | legit verify: True | stripped verify: False
  ```
- **Proof:** `BUILD_TARGET=mine python -m unittest -v test_build_task` fails before (`FAIL: test_pq_only_envelope_needs_pq_only_phase`, `FAIL: test_stripped_envelope_rejected_in_transition`, `FAILED (failures=2)`); the solution gives `Ran 4 tests in 0.020s`, `OK`.

**Fitness function.** `python agility_lint.py` → `agility_lint: 0 violation(s)`; `test_fitness_agility.py` runs it in CI (threshold 0) so nobody re-hard-codes an algorithm outside `registry.py`. Full suite: `Ran 15 tests in 1.607s`, `OK`.

## Common confusions
- **Q:** "Agility means supporting many algorithms." — **A:** It means being able to *switch*; ADR-0017 warns every registry entry is a code path to test.
- **Q:** "A valid Ed25519 signature is enough during the transition." — **A:** The stripped envelope had exactly that and was forged; `required: ['Ed25519', 'ML-DSA-65']`.
- **Q:** "Negotiation should fall back to whatever the peer offers." — **A:** Step 2 refuses `A128CBC`; fallback is how downgrade attacks work.
