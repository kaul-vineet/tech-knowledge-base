# Threat modelling cryptographic systems: STRIDE, attack trees and tests — explained

## The intuition
A threat model answers "what can go wrong, and what stops it?" for each part of a system. Written once as a document, it drifts within weeks: a test is deleted, a log export appears, and the document still claims everything is handled. This lesson treats it as code: `model.json` next to the source, a checker that fails the build when model and code disagree, and controls that count only if their named tests exist and pass.

Two classic tools structure it. **STRIDE** (Spoofing, Tampering, Repudiation, Information disclosure, Denial of service, Elevation of privilege) is applied per element, producing candidate threats to judge. An **attack tree** puts the attacker's goal at the root; each leaf has a cost and is closed by a control. The cheapest open path says where to spend effort — and if a control's test disappears, that path should get cheaper *automatically*.

**Analogy:** a fire-safety plan lists extinguishers per floor; an inspector checks each exists and is charged. Where the analogy breaks: code changes daily and invisibly, so the inspector is a CI job on every change, not a yearly visit.

```
model.json: elements(zones) · flows · threats{element, STRIDE, controls|accepted-by ADR} · controls{tests: file::Class::method}
check(model) ─▶ problems: element without threat? boundary flow without T and I? control with missing test?
verified_controls(model) = controls whose tests exist (fitness: and pass)
cheapest(attack_tree, verified) ─▶ cost + path   (leaf closed only by a VERIFIED control)
agent_assist ─▶ judge(): CONFIRMED | GAP | REJECTED   (never auto-merged)
```

**The one thing to remember:** a control without a passing test is a hope, not a control.

## Walkthrough: what actually happens when you run it
1. **You run** `python threat_model.py`. **What happens inside:** `candidates()` applies STRIDE per element; `check()` runs coverage rules; `cheapest()` walks the attack tree. **What you see:**
   ```
   1) elements 11 (flows 5, crossing a boundary 4) | STRIDE-per-element candidates 41 | threats 18 | controls 12
   2) checker problems: [] | controls whose tests exist: 12/12
   3) cheapest open attack path: cost 9 via ['phish an authorised user']
   ```
   **What it means:** 41 candidates became 18 threats; every control names an existing test (C-NO-FALLBACK → lesson 18). With crypto controls in place, the cheapest attack is social.
2. **The fault.** **What you see:**
   ```
   --- fault: model drift (a test is deleted in a refactor; a SIEM export flow is added)
   control C-NO-FALLBACK now points at a missing test: True | checker problems: [] | new flow app-log->siem threats: []
   ```
   **What it means:** the unfixed checker sees nothing wrong — the exact drift the brief worries about.
3. **You run** `python try_it.py`. **What you see:**
   ```
   1) without T3: ['client->doc-api: boundary-crossing flow lacks T']
   2) C-NONEXPORT unverified -> cheapest path cost 6 via ['compromise the app host', 'read key bytes out of the token'] (was 9 via ['phish an authorised user'])
   ```
   **What it means:** "TLS handles that" means the threat names TLS as control, not that it disappears. Losing lesson 19's test makes key theft cheapest.
4. **You run** `python agent_assist.py` (fake model). **What you see:**
   ```
   signer R (nobody can prove which operator signed a) -> GAP - valid threat with no control: triage it (not added automatically)
   envelope-db I (database backups are readable by the bac) -> REJECTED - control C-QUANTUM-SHIELD does not exist
   verdicts {'CONFIRMED': 2, 'GAP': 1, 'REJECTED': 3}; …
   ```
   **What it means:** code caught an invented control; the GAP is the useful output for human triage.

## The decision
The options are complementary; ADR-0021 records what each contributes:
- **A, STRIDE per element:** `candidates 41 | threats 18` — the coverage backbone (checker rules).
- **B, attack tree over verified controls:** cost 9, then 8 after the drift — turns a deleted test into a visible change in risk.
- **C, agent brainstorming:** `CONFIRMED 2, GAP 1, REJECTED 3` — an aid only; half its proposals were wrong.

The core is rule 2: a control counts only if every test it names exists and passes.

### Failure lab: model drift
- **Inject:** `inject_drift()` (`random.Random(21)`) removes C-NO-FALLBACK's test and adds an unmodelled `app-log -> siem` flow to the internet zone.
- **Symptom:** step 2: `checker problems: []` despite both changes.
- **Diagnose:** the unfixed `check()` skips `test_exists()` and has no T/I rule for flows.
- **Fix:** `solution_verified.py`. **You run** `python solution_verified.py`. **What you see:**
  ```
  clean model problems: [] | verified controls: 12 of 12
  after drift:
    - C-NO-FALLBACK: test missing labs/L400/18-post-quantum/test_build_task.py::TestNoSilentFallback::test_removed_in_refactor
    - app-log->siem: boundary-crossing flow lacks T
    - app-log->siem: boundary-crossing flow lacks I
  cheapest open attack path with only VERIFIED controls: cost 8 via ['record traffic on path', 'client accepts classical-only share', 'wait for a quantum computer']
  ```
  The tree shows *which* deleted test matters: harvest-now-decrypt-later becomes cheapest.
- **Proof:** `BUILD_TARGET=mine python -m unittest -v test_build_task` before: three `FAIL:` lines, `FAILED (failures=3)`; the solution: `Ran 4 tests in 0.109s`, `OK` (README: 4.843s).

**Fitness function.** `test_fitness_threat_model.py` requires 0 checker problems and runs all 12 control tests. Full suite: `Ran 14 tests in 29.833s`, `OK` (README: 182.982s) — slow enough that ADR-0021 runs it in CI, not on every save.

## Common confusions
- **Q:** "STRIDE candidates are threats." — **A:** 41 candidates became 18 threats after review.
- **Q:** "Attack-tree costs are probabilities." — **A:** They are the lab's 1–10 scale for ranking paths (ADR-0021 consequences).
- **Q:** "An agent can keep the model up to date." — **A:** It proposed an invented control (`C-QUANTUM-SHIELD`); nothing merges automatically.
