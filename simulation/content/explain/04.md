# Time-stepped physics: a parcel dropped from a drone — explained

## The intuition

A falling parcel changes continuously, so there are no events to list — only *rates*: velocity changes height, gravity and drag change velocity. A time-stepped simulation takes a small step dt, applies the rates, and repeats.

Explicit Euler uses the start-of-step velocity; semi-implicit Euler uses the updated one; RK4 samples the slope four times and blends. No drag has an exact answer, so errors are measurable.

Analogy: dead reckoning — estimate position from last known speed, a little at a time.
Where the analogy breaks: the solver never corrects with landmarks, so errors accumulate.

```
(y, v) ──accel(v)──> stepper(y, v, dt) ──> (y', v')  × round(t_end/dt)
no drag: compare y(3 s) with exact 100 - 4.9·3² = 55.9
drag:    loop until y <= 0, compare v with sqrt(2mg / (Cd ρ A))
```

The one thing to remember: test the integrator on a known answer before trusting it on an unknown one.

## Walkthrough: what actually happens when you run it

1. **You run** `python falling.py`.
   **What happens inside:** `run(stepper, dt, 3.0, drag=False)` calls each stepper `round(3/dt)` times. Explicit Euler moves y with the old v and lags; semi-implicit uses the new v and leads by the same amount; RK4 is exact for constant acceleration.
   **What you see:**
   ```
       dt   explicit Euler err   semi-implicit err   RK4 err
      0.1            +1.470000           -1.470000   -1.4e-14
     0.01            +0.147000           -0.147000   +7.8e-14
    0.001            +0.014700           -0.014700   +9.1e-13
   With drag: terminal velocity = 18.40 m/s
   Time to fall 100 m: no drag 4.52 s (exact 4.52 s), with drag 6.74 s, impact 18.37 m/s
   ```
   **What it means:** Euler error ∝ dt (first order). RK4's error is round-off and *grows* with more steps. Drag adds 2.2 s.

2. **You run** `python try_it.py`.
   **What happens inside:** drag runs; then MASS=4.
   **What you see:**
   ```
   Euler dt=0.5: ground at 7.00 s, impact 18.40 m/s
   RK4 dt=0.001: ground at 6.74 s, impact 18.37 m/s
   4 kg parcel: terminal velocity 26.02 m/s (x1.41), ground at 5.65 s
   ```
   **What it means:** `time_to_ground` stops on step boundaries, so dt=0.5 answers in half-seconds. Terminal velocity ∝ sqrt(mass).

3. **SciPy version.** Expected (not run here): `falling_scipy.py` uses `solve_ivp` with a ground event and should agree with RK4's ground time; CI runs it.

## Common confusions

**Q:** RK4 at dt=0.001 should beat dt=0.1. — **A:** `+9.1e-13` vs `-1.4e-14`: with no truncation error left, more steps only add rounding.

**Q:** Semi-implicit is no better than explicit. — **A:** Same size here; on orbits it conserves energy far better.

**Q:** 6.74 s disagrees with 4.52 s. — **A:** 4.52 s is the no-drag exact; drag must be slower.
