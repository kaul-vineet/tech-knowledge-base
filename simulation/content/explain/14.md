# Global sensitivity: OAT vs Morris vs Sobol' — explained

## The intuition

Sensitivity analysis asks: which inputs drive the output, so you know what to measure carefully and what to freeze? The office-cooling model is a one-liner, `E = 150 + 4·dT + 1.0·(occupants − 40) + 24·window·dT + 3·(lights − 8)`, with dT = outdoor − 22 C. The trap is the `window × dT` term: an open window matters only when it is hotter or colder outside than inside.

**One-at-a-time (OAT)** swings each input with the others held at nominal. At the nominal point dT = 0, so the window looks irrelevant. OAT sees one point, not the space. **Morris** walks 20 random trajectories, changing one input per step, and records "elementary effects": mean |EE| (mu*) says how much an input matters on average; their spread (sigma) says the effect *depends on where you are* — the fingerprint of interaction or non-linearity. **Sobol'** splits the output variance: S1 is the share an input explains alone; ST is its share including every interaction. ST − S1 is pure interaction.

Analogy: profiling a service by toggling one feature flag at a time in staging — a slowdown that appears only when two flags are on together never shows up.
Where the analogy breaks: Sobol' indices assume independent inputs with known ranges; correlated real-world inputs need other methods.

```
OAT:    nominal ± one input        ── 8 runs    ──> local swing
Morris: 20 trajectories × 5 runs   ── 100 runs  ──> mu*, sigma
Sobol': A, B, AB_i (N = 8,192)     ── 49,152    ──> S1 (Saltelli), ST (Jansen)
screen(k=2): keep top 2, freeze rest ──> variance_kept() on 50,000 samples
```

The one thing to remember: rank inputs by a measure that includes interactions (ST), not by a local swing.

## Walkthrough: what actually happens when you run it

1. **You run** `python sensitivity.py`.
   **What happens inside:** `oat()`, `morris()` and `sobol()` share seed 14; Sobol' centres outputs before estimating (same indices, less noise).
   **What you see:**
   ```
   input         OAT swing   Morris mu*  sigma    Sobol S1    ST
   outdoor_C        192.0      240.0   112.3     0.804    0.971
   occupants         40.0       40.0     0.0     0.031    0.035
   window_open        0.0      100.8   107.4     0.005    0.155
   lights_h          12.0       12.0     0.0     0.004    0.003
   runs: OAT 8, Morris 100, Sobol 49152
   sum S1 = 0.844  (1 - sum S1 = variance from interactions)
   ```
   **What it means:** occupants and lights have sigma 0.0 — purely additive. The window's sigma exceeds its mu*: almost all of its effect is interaction (ST 0.155 vs S1 0.005). 15.6% of the variance lives in interactions that S1 cannot see.

## Failure lab: screen() by OAT

1. **Inject.** Shipped `screen()` keeps the top 2 inputs by OAT swing and freezes the rest at nominal.
2. **Symptom.** **What you see:** `screen() keeps ['outdoor_C', 'occupants']: the reduced model keeps 84.1% of the variance`. The window is frozen at 0.5 — and the window × temperature term goes with it. No warning.
3. **Diagnose.** **You run** `BUILD_TARGET=mine python -m unittest test_build_task -v`.
   **What you see:**
   ```
   - ['outdoor_C', 'occupants']
   + ['outdoor_C', 'window_open']
   Ran 2 tests in 0.310s
   FAILED (failures=2)
   ```
   **What it means:** both the expected inputs and the >95% variance test fail.
4. **Fix.** Rank by Sobol' ST.
5. **Proof.** **You run** `python solution/sensitivity.py`.
   **What you see:** `screen() keeps ['outdoor_C', 'window_open']: the reduced model keeps 96.1% of the variance`
   **What it means:** dropping occupants (ST 0.035) and lights costs under 4%; dropping the window cost 16%.

## Common confusions

**Q:** A 0.0 OAT swing means the input doesn't matter. — **A:** The window's ST is 0.155, second of four.

**Q:** S1 is enough. — **A:** Sum S1 = 0.844; the missing 0.156 is interaction only ST counts.

**Q:** Morris sigma is noise. — **A:** sigma 0.0 for additive inputs and 107.4 for the window: it measures dependence on the other inputs.
