# Is the model right? Verification vs validation — explained

## The intuition

"Is the model right?" hides two questions. **Verification**: does the code do what the model says (tests, invariants, reproducibility)? **Validation**: is the model close enough to reality *for this question*? That needs a reference (the M/M/1 formula) and an uncertainty.

Analogy: verification is unit tests; validation is checking production metrics against the SLO.
Where the analogy breaks: code can pass every test while the model is still wrong — tests cannot see a wrong assumption.

```
next_wait = max(0, w + s - g)   <── test_vv.py hand cases   (verification)
10 seeds ─> drop 5,000 warm-up ─> 10 means
means ─> mean ± 2.262·sd/sqrt(10) ─> contains 4.000?      (validation)
lam 0.5..0.9 ─> same ─> monotonic, near formula?          (sensitivity)
```

The one thing to remember: tests show the code matches the model; only a reference comparison shows the model fits the question.

## Walkthrough: what actually happens when you run it

1. **You run** `python vv.py`.
   **What happens inside:** `digest()` hashes 1,000 waits rounded to 9 decimals; `replicate(0.8)` runs seeds 1–10 of 50,000 customers.
   **What you see:**
   ```
   1. reproducibility: seed 1 -> ef34cf71198d, seed 1 again -> ef34cf71198d, seed 2 -> ac9c300ece80
   2. validation (lam=0.8): simulated 4.046 +/- 0.195 min vs formula 4.000 -> PASS
   …
      lam=0.9  simulated  8.952 +/- 0.730   formula  9.000
   ```
   **What it means:** PASS because the gap 0.046 < 0.195. The interval widens near lam = 1.

2. **You run** `python try_it.py`.
   **What happens inside:** a rule without `max(0, …)`; then 50 short runs, warm-up 0 vs 500.
   **What you see:**
   ```
   buggy rule: min wait -5168.4 min, mean wait -2619.9 min  (negative waits are impossible)
   warm-up   0: average of 50 short runs = 3.92 min (formula 4.00)
   warm-up 500: average of 50 short runs = 4.02 min (formula 4.00)
   ```
   **What it means:** the bug is a verification failure a "never negative" test catches; an empty start biases short runs low.

3. **You run** `python -m unittest -v test_vv` → **What you see:** `Ran 7 tests` … `OK (skipped=1)`; the skip is the SciPy check.

4. **You run** `python agent_assist.py --fake` → **What you see:** `rejected: 1.2: outside [0.05, 0.95]` and `UNVERIFIED (treat as the model's guess): 0.95, 19.0`. **What it means:** code decides what runs and which numbers are trusted.

## Common confusions

**Q:** Tests pass, so the model is valid. — **A:** Tests verify the rule; only the CI compares with a reference.

**Q:** One long run equals 10 replications. — **A:** Waits in one run are correlated; independent means make the t-interval valid.

**Q:** 4.046 ≠ 4.000 is a failure. — **A:** The criterion is "inside ± 0.195".
