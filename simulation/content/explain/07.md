# Input modelling: fit service times and check the fit — explained

## The intuition

"Service time is exponential" is a habit, not a fact. Input modelling means: fit several candidate distributions to measured data, check which matches — especially in the tail — and see whether the choice changes the answer.

Fitting is cheap: each candidate has a closed-form estimator (exponential rate = 1/mean; lognormal = mean and sd of log data). Checking is the work. The Kolmogorov–Smirnov distance D is the largest vertical gap between the data's step-shaped empirical CDF and the fitted CDF. Q-Q points show *where* a fit fails.

Analogy: a latency model for capacity planning that matches the mean but not the p99 tail plans the wrong number of servers.
Where the analogy breaks: with latency you usually have millions of samples; here 200, so a "good" D can still hide tail error.

```
service_times.csv (200) ─> fit_exponential / fit_normal / fit_lognormal
        │                         │
        └─ ks_statistic(x, cdf) ──┴─> rank by D ─> qq_points(best)
each fit.sample ─> queue_waits(lam = 0.85/mean) ─> mean / p95 wait vs resampled data
```

The one thing to remember: the distribution's *shape* changes queue answers even when the mean is identical.

## Walkthrough: what actually happens when you run it

1. **You run** `python fit_inputs.py`.
   **What happens inside:** `load()` reads 200 minutes values; `cv = sd/mean` is the first clue (an exponential has cv = 1).
   **What you see:** `data: n=200 mean=4.75 sd=3.46 cv=0.73 max=24.30 min`
   **What it means:** cv 0.73 already argues against "memoryless" service.

2. **You run** the same script; read the ranking. **What happens inside:** `ks_statistic()` sorts x and checks both sides of each ECDF step: `max(F - (i-1)/n, i/n - F)`.
   **What you see:**
   ```
   exponential  rate=0.211                   0.217
   normal       mu=4.749 sigma=3.463         0.132
   lognormal    mu=1.344 sigma=0.655         0.031
   smallest D: lognormal | Q-Q (p: fitted vs data): 0.10: 1.66 vs 1.75  0.50: 3.84 vs 3.93  0.90: 8.88 vs 8.49  0.99: 17.59 vs 18.17
   ```
   **What it means:** only lognormal is under the 0.096 reference and tracks the data to the 99th percentile. The reference assumes known parameters: D ranks, it is not a p-value.

3. **You run** the same script; read the queue block. **What happens inside:** same 85% load (`lam = 0.85 / mean`), each candidate as service time in a Lindley-rule queue, plus resampling the data itself.
   **What you see:**
   ```
     exponential       26.38 min /  85.51 min / 0.122
     normal            24.11 min /  76.41 min / 0.065
     lognormal         20.48 min /  67.56 min / 0.072
     data (resampled)  21.18 min /  71.91 min / 0.055
   ```
   **What it means:** the exponential habit overstates the mean wait by about a quarter; lognormal is close to the data.

4. **You run** `python try_it.py`.
   **What you see:**
   ```
   n=30: exponential D=0.326, normal D=0.175, lognormal D=0.098 | 1.36/sqrt(30)=0.248
   load 0.50: exponential input   4.67 min vs data   3.65 min -> 1.28x
   load 0.85: exponential input  26.38 min vs data  21.18 min -> 1.25x
   ```
   **What it means:** with 30 points the normal survives (0.175 < 0.248). The exponential error is a ratio, ~1.25–1.28x at every load.

5. **You run** `python agent_assist.py --fake`.
   **What you see:** `code decided: lognormal - the agent's pick (exponential) is overruled (rank 3 of 3)` and `UNVERIFIED (treat as the model's guess): 0.05, 99`.
   **What it means:** measured D beats the agent's "cv is close to 1"; invented numbers are flagged.

## Common confusions

**Q:** Lowest D means the distribution is "true". — **A:** It is the best of three candidates; the build task adds a shifted exponential, which ranks between them.

**Q:** At low load the input choice stops mattering. — **A:** Step 4: still 1.28x at load 0.50.

**Q:** Resampling the data is always best. — **A:** It never exceeds the observed max of 24.30, so rare long repairs vanish.
