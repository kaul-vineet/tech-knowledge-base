# Resources and queues: c desks, one line, Erlang C — explained

## The intuition

Lesson 3 had one server. Real systems have a pool: three reception desks, a thread pool of N workers, a call centre. The modelling question becomes: when does an arrival have to wait, and for how long, given c servers sharing one line?

The DES change is small: `busy` becomes a counter from 0 to c. An arrival takes a free desk if `busy < c`, otherwise joins the line; a departure hands its desk straight to the next in line. The new idea is *time-averaged* statistics: queue length and utilisation are areas under step curves divided by total time, accumulated at every event. Erlang C gives the exact M/M/c answers, so the simulation can be checked.

Analogy: a thread pool with one shared work queue versus per-thread queues.
Where the analogy breaks: real workers have different speeds and work stealing; Erlang C assumes identical servers and exponential service.

```
arrive ─ busy < c ? ─ yes ─> busy += 1, wait 0, push depart
                  └─ no ──> line.append(t)
depart ─ line ? ─ yes ─> wait = t - line.popleft(), push depart (desk stays busy)
               └─ no ──> busy -= 1
every event: area_line += len(line)·dt ; area_busy += busy·dt
```

The one thing to remember: pooled servers with one line beat the same servers with separate lines — by a lot at high load.

## Walkthrough: what actually happens when you run it

1. **You run** `python mmc_queue.py`.
   **What happens inside:** `simulate(200_000)` with lam 2.4, mu 1.0, c 3. Before handling each event it adds `len(line)·(t − last)` and `busy·(t − last)` to the areas. `erlang_c()` computes P(wait) and Wq = P(wait)/(cμ − λ).
   **What you see:**
   ```
   M/M/3: lam=2.4/min, mu=1.0/min per desk, utilisation 80%
   metric    simulated   Erlang C
   Wq            1.110      1.079
   Lq            2.665      2.589
   util          0.803      0.800
   P_wait        0.652      0.647
   ```
   **What it means:** all within ~3%. Little's law holds inside the simulation: 2.4 × 1.110 = 2.664 ≈ 2.665. Use that identity as a free verification check.

2. **You run** the same script; read the sizing table. **What happens inside:** `erlang_c(c)` for c = 3..6.
   **What you see:**
   ```
     c=4: P(wait)=0.287  Wq=0.179 min
     c=5: P(wait)=0.114  Wq=0.044 min
   ```
   **What it means:** the fourth desk cuts Wq six-fold; five desks are needed for P(wait) < 20%. Diminishing returns are visible immediately.

3. **You run** `python try_it.py`.
   **What happens inside:** three independent M/M/1 queues at lam/3, then lam +10%.
   **What you see:**
   ```
   3 separate lines: Wq=3.87 min | 1 shared line, 3 desks: Wq=1.11 min | formula 4.00 vs 1.08
   lam=2.64: utilisation 88%, simulated Wq=2.30 min, Erlang C Wq=2.17 min
   ```
   **What it means:** same capacity, 3.5x longer wait with separate lines — in a separate line you can wait while another desk is idle. +10% demand doubles the wait.

4. **SimPy version.** Expected (not run here): `simpy_mmc.py` uses `simpy.Resource(env, capacity=3)`; the lesson expects Wq near the Erlang C value in CI.

## Common confusions

**Q:** Lq is the average of the line length seen by arrivals. — **A:** It is a *time* average (`area_line / last`); Little's law connects it to Wq.

**Q:** 80% utilisation is the same for one or three desks. — **A:** Same utilisation, very different wait: 4.00 vs 1.08 by formula.

**Q:** Adding a desk always helps a little. — **A:** From 3 to 4 desks the formula Wq drops 1.079 → 0.179: a lot, then little.
