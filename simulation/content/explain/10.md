# Warm-up, replications and confidence — explained

## The intuition

A help desk opens Monday with 30 weekend tickets. The first hundred customers wait much longer than "normal". If your question is the *long-run* mean wait, those early waits are not wrong — they answer a different question — and averaging them in biases the result. That start-up period is the warm-up (initial transient).

Welch's method averages many replications at each customer index, smooths, and shows where the curve flattens; delete everything before. Then build a t-interval from one mean per independent replication — customers within one run are correlated.

Analogy: ignore the JVM's warm-up iterations before you benchmark — JIT and caches make the first calls unrepresentative.
Where the analogy breaks: a JVM warms toward one steady speed; a queue's steady state is itself random, so you need a statistical band, not a single "now it's stable" moment.

```
20 reps × 5,000 waits ─> mean per index ─> welch(window 50) ─> warmup_point (±5% band) = d
40 short runs: mean(r[0:]) vs mean(r[d:]) ─> CI ─> covers 4.0?
80 long runs: mean(r[d:]) ─> CI for n = 10, 20, 40, 80 ─> half-width ∝ 1/sqrt(n)
```

The one thing to remember: delete the warm-up, then build the CI from independent replication means — not from customers inside one run.

## Walkthrough: what actually happens when you run it

1. **You run** `python warmup.py` — section 1, Welch.
   **What happens inside:** `waits()` starts each run with the backlog (`w = sum of 30 service times`). `welch()` averages across 20 runs, uses short symmetric windows at the start and a cumulative-sum moving average of width 101 afterwards. `warmup_point()` returns the first index inside ±5% of the second-half level.
   **What you see:**
   ```
      0: 29.19  50: 16.24  100: 8.69  150: 5.34  200: 3.39  500: 3.95  2000: 3.62  4000: 3.15
      code proposes warm-up = 169 customers (enters 5% band around level 4.32)
   ```
   **What it means:** the curve reaches the 3–4 band within ~200 customers. Code *proposes*; you still look.

2. **You run** the same script — section 2, initial bias.
   **What you see:**
   ```
   2. 40 runs x 1,000 customers, delete first   0: 5.59 +/- 0.61 min (true 4.0)
   2. 40 runs x 1,000 customers, delete first 169: 3.71 +/- 0.53 min (true 4.0)
   ```
   **What it means:** without deletion the CI misses 4.0 — confidently wrong; after deletion it covers it.

3. **You run** the same script — section 3, replications.
   **What you see:**
   ```
      n=10: 3.89 +/- 0.50 min  (half-width x sqrt(n) = 1.58)
      n=20: 4.00 +/- 0.31 min  (half-width x sqrt(n) = 1.40)
      n=40: 4.18 +/- 0.25 min  (half-width x sqrt(n) = 1.59)
      n=80: 4.01 +/- 0.16 min  (half-width x sqrt(n) = 1.43)
   ```
   **What it means:** half-width × sqrt(n) is roughly constant, so precision costs quadratically: halving the CI needs 4x the replications. n=40 at 4.18 still covers 4.0.

4. **You run** `python try_it.py`.
   **What you see:**
   ```
   backlog  0, no deletion: 3.57 +/- 0.43 min (true 4.0)
   proposed warm-up for three new seed sets: [215, 195, 961]
   80 replications, delete first 961: 3.98 +/- 0.17 min
   ```
   **What it means:** an empty start biases *low*. The rule is noisy (961 once); over-deleting only costs data.

## Common confusions

**Q:** Warm-up deletion is cheating. — **A:** It removes the answer to a different question (Monday morning). If that *is* your question, keep it.

**Q:** 1,000 customers in one run give a CI with n = 1,000. — **A:** Consecutive waits are correlated; the lab's n is the number of replications.

**Q:** The proposed 169 is exact. — **A:** New seeds proposed 215, 195 and 961.

## Check your understanding

1. Why does no deletion give 5.59 while backlog 0 gives 3.57?
<details><summary>Answer</summary>The backlog starts the queue too full (bias up); an empty start is too empty (bias down).</details>

2. You need ±0.08 min. Roughly how many replications?
<details><summary>Answer</summary>Half-width × sqrt(n) ≈ 1.5, so n ≈ (1.5/0.08)² ≈ 350.</details>

3. Why does `ci()` use a t quantile rather than 1.96?
<details><summary>Answer</summary>With 10–20 replications the sd is itself uncertain; t widens the interval to keep 95% coverage.</details>
