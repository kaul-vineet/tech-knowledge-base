# Variance reduction: same precision, fewer runs — explained

## The intuition

Plain Monte Carlo pays for precision with runs: halving the error costs four times the evaluations. Variance reduction changes the *estimator* instead, so each evaluation carries more information. The model here — overtime when 12 exponential tasks overrun a 7-hour shift — has an exact answer (0.9196 h), so every trick can be checked for bias as well as speed.

Two tricks. **Antithetic pairs**: for every random vector u also evaluate 1 − u. Because overtime rises monotonically with every u, a high draw is paired with a low one and their errors partly cancel. **Control variate**: you also record total task time C, whose mean (12 × 0.6 = 7.2 h) you know exactly. When C came out high, overtime probably did too, so subtract β × (C − 7.2). The fitted β makes the correction optimal.

Both tricks depend on *correlation that you build on purpose*. That is also why they fail silently: break the link between u and 1 − u and you get an unbiased estimate with no gain and no error message.

Analogy: a control variate is like normalising a benchmark run by a reference workload measured on the same noisy machine — the shared noise cancels.
Where the analogy breaks: the reference must have a *known* mean; with an estimated one you are back to comparing two noisy numbers.

```
u ~ U(0,1)^12 ──┬─> overtime(u)      ─┐
                └─> overtime(1−u)    ─┴─ pair mean ─> SE from n/2 pair means  (antithetic)
u ──> (y, C) ──> y − β(C − 7.2), β = Cov(y,C)/Var(C)                       (control variate)
loop form: u from rng([2i,seed]), mirror from rng([2i+1,seed])  ── no link ──> rho ≈ 0
```

The one thing to remember: variance reduction works only through the correlation you engineer — measure rho or the ratio, never assume it.

## Walkthrough: what actually happens when you run it

1. **You run** `python variance_reduction.py`.
   **What happens inside:** each method gets 20,000 model evaluations. `summary()` reports `var_per_eval = se² × evals`, so the ratio column is cost-fair. `antithetic()` computes the SE from *pair* averages (the two halves are not independent).
   **What you see:**
   ```
   exact expected overtime: 0.9196 h per shift (Erlang formula)
     method              estimate   std.err   variance ratio vs plain
     plain Monte Carlo   0.9025    0.00990    1.00x
     antithetic          0.9208    0.00819    1.46x  rho=-0.32
     control variate     0.9203    0.00426    5.40x  beta=0.609
     antithetic (loop)   0.8999    0.00986    1.01x  rho=-0.00
   CRN recap, overtime saved by a 7.5 h shift: independent 0.2120 +/- 0.0259, common 0.2237 +/- 0.0033 h
   ```
   **What it means:** antithetic matches theory 1/(1 + rho) ≈ 1.47. The control variate is worth 5.4x the runs because overtime is almost a function of total time. The last row is the failure lab.

## Failure lab: reseeding inside the loop

1. **Inject.** The shipped `antithetic_loop()` mimics a simulator called once per run: each call creates `default_rng([2i, seed])` for f(u) and `default_rng([2i+1, seed])` for the "mirror" f(1 − u′). The mirror belongs to a different u.
2. **Symptom.** Row 4: `0.8999`, `rho=-0.00`, `1.01x`. Unbiased, no exception — the method silently does nothing.
3. **Diagnose.** **You run** `BUILD_TARGET=mine python -m unittest test_build_task -v`.
   **What you see:**
   ```
   AssertionError: -0.0012398657583570188 not less than -0.25
   AssertionError: 1.0085792208411501 not greater than 1.3
   Ran 3 tests in 5.318s
   FAILED (failures=2)
   ```
   **What it means:** the unbiasedness test passes; the correlation and ratio tests catch the fault. Unbiasedness alone would never find it.
4. **Fix.** One stream per *pair*: draw u once and evaluate both u and 1 − u.
5. **Proof.** **You run** `python solution/variance_reduction.py`.
   **What you see:** `antithetic (loop)   0.9091    0.00809    1.50x  rho=-0.33`
   **What it means:** the loop form now matches the vectorised one.

## Walkthrough continued

2. **You run** `python try_it.py`.
   **What you see:**
   ```
   symmetric model: rho=+1.00, variance ratio antithetic vs plain = 0.49x
   control variate beta=1.0: variance ratio 1.92x
   control variate beta=1.5: variance ratio 0.52x
   ```
   **What it means:** on y = (Σu − 6)², f(u) = f(1 − u) exactly, so each pair is one value counted twice — *worse* than plain. A wrong β can also make things worse than doing nothing.

## Common confusions

**Q:** An unbiased estimate means the method works. — **A:** Row 4 is unbiased and useless; check rho or the ratio.

**Q:** Antithetic always helps. — **A:** Only for monotone responses; the symmetric model gives 0.49x.

**Q:** β = 1 is the natural choice. — **A:** β = 1.0 gives 1.92x, the fitted 0.609 gives 5.40x, 1.5 gives 0.52x.

## Check your understanding

1. Why compute the antithetic SE from pair averages?
<details><summary>Answer</summary>The two halves of a pair are negatively correlated; treating 20,000 values as independent would misstate the SE.</details>

2. What makes total task time a good control variate here?
<details><summary>Answer</summary>Its mean is known exactly and overtime is strongly correlated with it (r ≈ 0.9).</details>

3. Your simulator must be called once per run. How do you keep antithetic pairs?
<details><summary>Answer</summary>Generate u for the pair outside, pass u to one call and 1 − u to the other — never a fresh stream per call.</details>
