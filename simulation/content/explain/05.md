# Agent-based modelling: Schelling's neighbourhood model — explained

## The intuition

Instead of equations for the whole city, each household gets one local rule: "if fewer than 30% of my neighbours are like me, move to a random empty cell". Nobody plans clusters. You run the rule and *measure* what the population does.

A mild preference produces strong segregation, because each move changes the neighbourhoods of the people left behind and of the new neighbours. That gap between rule and outcome — emergence — is why agent-based models exist.

Analogy: microservices each with a local retry policy — the fleet-wide retry storm is in no single service's code.
Where the analogy breaks: services have no spatial neighbours; here *who is next to whom* is the mechanism.

```
grid 30x30 (405 x, 405 o, 90 empty, shuffled)
loop:
  similarity()  ─ np.roll 8 neighbours ─> fraction same per agent
  unhappy = frac < 0.30 ─> shuffle ─> each moves to a random empty cell
  stop when % unhappy == 0
```

The one thing to remember: one ABM run is one sample — read the outcome across seeds.

## Walkthrough: what actually happens when you run it

1. **You run** `python schelling.py`.
   **What happens inside:** `make_grid()` shuffles agents; `neighbour_counts()` sums eight rolled masks (edges wrap); `step()` finds `frac < WANT`, shuffles that list and moves each agent.
   **What you see:**
   ```
   step  1: moved 160  % similar  62.2  % unhappy   8.1
   step  5: moved  16  % similar  73.9  % unhappy   1.0
   …
   step 17: moved   1  % similar  75.4  % unhappy   0.0
   start: % similar 50.2 -> end: 75.4 (each agent only wanted 30%)
   ```
   **What it means:** a random start is ~50% similar. Step 1 does most of the work; later moves trigger smaller cascades. The printed corner shows solid x blocks.

2. **You run** `python try_it.py`.
   **What happens inside:** `run()` with WANT 0.5, then seeds 1–5.
   **What you see:**
   ```
   want 50%: end % similar 87.6, % unhappy 0.0, steps 13
   seeds 1-5 end % similar: [72.3, 76.3, 75.1, 74.7, 73.1]
   ```
   **What it means:** stronger preference, more segregation, fewer steps. Seeds vary ~4 points.

3. **Mesa version.** Expected (not run here): `schelling_mesa.py` applies the same rule with Mesa's grid and `shuffle_do`; CI checks it ends well above 60%.

## Common confusions

**Q:** Agents must want segregation. — **A:** They want 30% and end at 75.4%.

**Q:** 75.4% is *the* answer. — **A:** Seeds 1–5 give 72.3–76.3.

**Q:** Movers pick good spots. — **A:** A random empty cell; nothing optimises.
