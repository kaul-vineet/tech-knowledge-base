# ODE solvers in practice: adaptive steps, tolerances, stiffness — explained

## The intuition

Lesson 4 used a fixed dt. Real solvers pick dt themselves. Each Dormand–Prince step computes a 5th-order answer *and* an embedded 4th-order one from the same slope samples; their difference estimates the error almost for free. Under tolerance, the step is kept and the next grows; otherwise it is retried smaller. You specify accuracy (`rtol`, `atol`), not a step.

That fails when a problem is *stiff*: a fast component (a 1 ms capacitor) that has long settled still caps an explicit solver's step, because larger steps make the method unstable. Implicit methods (backward Euler, Radau, BDF) solve an equation per step and stay stable with big steps.

Analogy: TCP congestion control — grow while acks are clean, shrink on loss.
Where the analogy breaks: a stiff ODE's limit is the method's own stability region, not the problem's difficulty.

```
solve(f, t, y):
  y5, err = dp_step(f, t, y, h)         # 7 slope samples, error = 5th − 4th
  e = rms(err / (atol + rtol·|y|))
  e <= 1 ? accept, t += h : rejected += 1
  h *= clip(0.9·e^(−1/5), 0.2, 10)      # error ~ h^5
```

The one thing to remember: tolerance controls accuracy; stiffness controls cost — and only an implicit method fixes the second.

## Walkthrough: what actually happens when you run it

1. **You run** `python adaptive_ode.py` — section 1, coffee cooling with a known exact answer.
   **What happens inside:** `solve(coffee, 0, [90], 30, rtol)` at three tolerances, `atol=1e-12`.
   **What you see:**
   ```
   1. coffee 90 C -> 30 min, room 20 C (exact 35.619111 C)
      rtol=1e-03:   5 steps, 0 rejected, error 1.3e-02 C
      rtol=1e-06:   9 steps, 0 rejected, error 8.2e-06 C
      rtol=1e-09:  26 steps, 0 rejected, error 7.9e-09 C
   ```
   **What it means:** a million times more accuracy costs 5x more steps — the payoff of a high-order method.

2. **You run** the same script — section 2, rabbits and foxes.
   **What happens inside:** `np.diff(ts)` gives every accepted step; the code reports the smallest and largest.
   **What you see:**
   ```
   2. rabbits/foxes 0-15: 204 steps, invariant drift 2.6e-05
      smallest step 0.0316 at t=12.72: rabbits 12.24, foxes  1.12
      largest step 0.1852 at t= 7.40: rabbits  3.04, foxes  0.02
   ```
   **What it means:** steps shrink in the rabbit boom and stretch when foxes nearly vanish. The invariant drift is the cost of a finite tolerance.

3. **You run** the same script — section 3, a stiff RC filter (tau 1 ms, 10 s).
   **What you see:**
   ```
      explicit RK45 rtol=1e-03:  3027 steps (110 rejected), v(10)=-0.83987
      explicit RK45 rtol=1e-06:  3586 steps ( 10 rejected), v(10)=-0.83961
      implicit backward Euler dt=0.01: 1000 steps, v(10)=-0.83961
   ```
   **What it means:** loosening rtol 1,000x saved only 16% of steps: stability, not accuracy, pins the step. Backward Euler is stable at 10x tau.

4. **You run** `python try_it.py`.
   **What you see:**

   **What it means:** 10x stiffer → 10x more explicit steps for the same answer: the signature of stiffness.

## Common confusions

**Q:** Tighter rtol always means many more steps. — **A:** Coffee: 1e-3 → 1e-9 went 5 → 26 steps.

**Q:** Lots of rejected steps means the solver is broken. — **A:** Rejection is the control loop working; the 110 at 1e-3 come from h probing past stability.

**Q:** Stiff means the solution changes fast. — **A:** v(t) follows cos(t) smoothly; the *fast mode* is hidden in the equation, and explicit methods must respect it.
