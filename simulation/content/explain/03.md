# Discrete-event simulation: a single-server queue — explained

## The intuition

In a coffee shop nothing happens between "a customer arrives" and "a coffee is handed over". A discrete-event simulation keeps a to-do list of future events sorted by time, pops the earliest, jumps the clock to it, and lets that event schedule the next ones. No ticks.

Analogy: an event loop with a timer heap, like asyncio — callbacks run in time order.
Where the analogy breaks: a real loop waits for wall-clock time; a DES jumps instantly, so 250,000 simulated minutes take seconds.

```
heap: (0.180 arrive 0)
pop arrive 0 ─> push arrive 1 @2.531, depart 0 @1.623
pop depart 0 ─> line empty, busy=False
pop arrive 1 ─> push arrive 2 @2.899, depart 1 @3.215
pop arrive 2 ─> busy, join line
pop depart 1 ─> start 2: wait = 3.215 - 2.899
```

The one thing to remember: the clock moves only when an event is popped; a wait is service start minus arrival.

## Walkthrough: what actually happens when you run it

1. **You run** `python des_queue.py`.
   **What happens inside:** `simulate(5, 1, trace=4)` prints early events, then `simulate(200_000, 1)` runs silently. Heap entries are `(time, seq, kind, cust)`; `seq` keeps ties FIFO. `mm1_wq()` = 0.8 / (1.0 × 0.2).
   **What you see:**
   ```
   t=  0.180  arrive  customer 0  queue=0 busy=False
   t=  1.623  depart  customer 0  queue=0
   t=  2.531  arrive  customer 1  queue=0 busy=False
   t=  2.899  arrive  customer 2  queue=0 busy=True
   t=  3.215  depart  customer 1  queue=1
   …
   simulated mean wait = 3.871 min | M/M/1 formula Wq = 4.000 min | diff -3.2%
   ```
   **What it means:** time only increases. −3.2% on one run is noise at 80% load; backwards times would mean an event pushed into the past.

2. **You run** `python try_it.py`.
   **What happens inside:** `simulate()` with `lam=0.88`, then 200-customer runs, seeds 1–3.
   **What you see:**
   ```
   lam=0.88: simulated Wq=7.08 min, formula Wq=7.33 min
   200 customers, seed 1: mean wait 4.19 min
   200 customers, seed 2: mean wait 2.31 min
   200 customers, seed 3: mean wait 7.71 min
   ```
   **What it means:** +10% arrivals → +83% wait. Short runs span 2.31–7.71: one short run tells you little.

3. **SimPy version.** Expected (not run here): `simpy_queue.py` uses `simpy.Resource(capacity=1)` and prints a mean wait near the formula, per the SimPy docs; CI runs it.

## Common confusions

**Q:** A smaller time step would be more accurate. — **A:** There is none; `clock` takes the popped event's time exactly.

**Q:** −3.2% proves bias. — **A:** Seeds 1–3 span 2.31–7.71; replicate first.

**Q:** 80% busy means a short line. — **A:** At 88% the formula wait is 7.33 min.
