# Monte Carlo: estimate a project's completion time — explained

## The intuition

Three tasks run in sequence, each with an uncertain duration (min, most likely, max). Adding the "most likely" values hides the real question: *how likely am I to finish by day 20?* Monte Carlo plays the project out many times with random durations and counts.

Each sample is one possible future. The average of many estimates the mean; the fraction finishing by day 20 estimates the probability. Each estimate is itself an average of random numbers, so its error shrinks like 1/sqrt(N).

Analogy: load-testing your plan — fire 100,000 synthetic runs at it and read the distribution, not one request.
Where the analogy breaks: Monte Carlo only reflects the input distributions you assumed.

```
design ~ Tri(2,4,8)  ┐
build  ~ Tri(5,8,14) ├─ sum ─> totals[N] ─> mean, 1.96·sd/sqrt(N), P(total <= 20)
test   ~ Tri(2,3,6)  ┘
```

The one thing to remember: report the estimate's CI and the tail you care about, not just the mean.

## Walkthrough: what actually happens when you run it

1. **You run** `python monte_carlo.py`.
   **What happens inside:** `exact_mean()` sums (min+mode+max)/3. For each N, `sample_totals(n, 42)` adds one `rng.triangular` array per task; `summarise()` returns mean, `1.96 * sd / sqrt(n)` and `(totals <= 20).mean()`.
   **What you see:**
   ```
   exact mean (from formula): 17.333 days
          N    mean   95% CI half-width   P(<= 20 days)
        100  17.196   +/- 0.436            0.890
       1000  17.376   +/- 0.150            0.849
      10000  17.346   +/- 0.047            0.855
     100000  17.334   +/- 0.015            0.857
   P50 / P90 completion (days): [17.23 20.56]
   ```
   **What it means:** each 10x in N narrows the half-width ~3.2x (sqrt 10). The exact 17.333 sits inside every interval. One project in ten overruns 20.56 days.

2. **You run** `python try_it.py`.
   **What happens inside:** seed 7, then build max 20.
   **What you see:**
   ```
   seed 42: N=100 mean 17.196 | N=100000 mean 17.334 +/- 0.015
   seed 7: N=100 mean 17.401 | N=100000 mean 17.338 +/- 0.015
   build max 20 d: mean 19.332 +/- 0.022, P(<= 20 days) 0.602
   ```
   **What it means:** at N=100 the seed moves the mean 0.2 days; at N=100,000 only 0.004. A fatter tail on one task drops on-time odds from 0.857 to 0.602.

## Common confusions

**Q:** ±0.015 means projects finish within ±0.015 days. — **A:** It is the uncertainty of the *mean estimate*; project spread is P50 17.23 to P90 20.56.

**Q:** More samples make the answer more correct. — **A:** More *precise*; wrong inputs converge to a wrong number.

**Q:** Different seeds giving different answers is a bug. — **A:** 17.401 vs 17.196 at N=100 is the noise the CI reports.

## Check your understanding

1. N=1,000 gives ±0.150. Which N gives about ±0.05?
<details><summary>Answer</summary>About 9,000: 3x narrower needs 9x more samples.</details>

2. Why is `P(<= 20 days)` also a mean?
<details><summary>Answer</summary>It averages an indicator (1 on time, else 0), so the same 1/sqrt(N) error applies.</details>

3. Why must each N draw fresh samples?
<details><summary>Answer</summary>Otherwise the rows are not independent and the convergence column misleads.</details>
