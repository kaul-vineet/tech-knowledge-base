# Calibration: fit to data, validate on data you did not fit — explained

## The intuition

Calibration means choosing a model's unknown parameters so its output matches measurements. Here a sensor logs an office cooling down overnight, every 10 minutes for 12 hours. Three candidate models are fitted by least squares: one exponential (3 parameters), two exponentials for air and walls (5), and a degree-6 polynomial (7) with no physics at all.

Least squares always rewards flexibility: more parameters can only lower the error on the data you fitted. So the error on fitted data is not evidence that a model *predicts*. The honest test is data the fit never saw — and for a forecast, that must be *later* data, because the future is what you will ask about.

Gauss–Newton with Levenberg–Marquardt damping is the engine: linearise with a finite-difference Jacobian J, solve (JᵀJ + λ·diag) step = −Jᵀr, accept if the cost fell, else shrink.

Analogy: a model that aces its training set and fails in production — overfitting in ML.
Where the analogy breaks: in ML you often shuffle and hold out at random; for time series a random holdout leaks the future (try_it shows the polynomial still wins that way).

```
readings 0–12 h (73) ─┬─ CAL: 0–8 h (49) ─> gauss_newton / lstsq ─> 3 fitted models
                      └─ ~CAL: 8–12 h (24) ─────────────────────────> score here (fixed)
select(): shipped scores on CAL  ─> picks poly-6   (fault)
          fixed  scores on ~CAL  ─> picks two-exp
```

The one thing to remember: score a calibrated model on data it did not see, ordered in time like the question you'll ask it.

## Walkthrough: what actually happens when you run it

1. **You run** `python calibrate.py`.
   **What happens inside:** `observed()` builds the synthetic truth 12 + 6e^(−t/1.5) + 4e^(−t/9) plus noise sd 0.15 (seed 13), so the right answer is known. `candidates()` fits each model on the first 8 h; `scores()` computes RMSE for any mask.
   **What you see:**
   ```
   73 readings, 49 for calibration (0-8 h), 24 held out (8-12 h); sensor noise sd 0.15
     model           RMSE on calibration data   RMSE on holdout   prediction at 12 h (measured 13.33)
     one-exp (3 p)        0.175 C                  0.434 C         13.65 C
     two-exp (5 p)        0.152 C                  0.161 C         13.10 C
     poly-6 (7 p)         0.148 C                 12.517 C        -19.60 C
   select() picks poly-6 (7 p); its holdout RMSE is 12.517 C
   ```
   **What it means:** on fitted data the ranking is "more parameters, smaller error" (0.175 → 0.152 → 0.148). On held-out data the physics model is at the noise floor (0.161 vs 0.15) while the polynomial forecasts a room at −19.6 C.

## Failure lab: validate on the same data

1. **Inject.** Shipped `select()` calls `scores(models, y, CAL)` — the same 0–8 h it fitted.
2. **Symptom.** `select() picks poly-6 (7 p)`: the smallest calibration error and an absurd forecast; nothing raises.
3. **Diagnose.** **You run** `BUILD_TARGET=mine python -m unittest test_build_task -v`.
   **What you see:**
   ```
   AssertionError: 'poly-6 (7 p)' != 'two-exp (5 p)'
   Ran 2 tests in 1.867s
   FAILED (failures=11)
   ```
   **What it means:** the second test repeats the pick for noise seeds 20–29 (10 subtests): the fault is structural, not unlucky.
4. **Fix.** Score on `~CAL`, the unseen 8–12 h.
5. **Proof.** **You run** `python solution/calibrate.py`.
   **What you see:** `select() picks two-exp (5 p); its holdout RMSE is 0.161 C`
   **What it means:** holdout error near the sensor noise — as good as the data allow.

## Walkthrough continued

2. **You run** `python try_it.py`.
   **What you see:**
   ```
   two-exp on 0-5 h: RMSE 0.170 C, T_inf=-71014 C, B=71029 C, tau_wall=326494 h
   random holdout RMSE: one-exp (3 p) 0.257, two-exp (5 p) 0.189, poly-6 (7 p) 0.178 -> picks poly-6 (7 p)
   ```
   **What it means:** with only 5 hours the slow wall mode is barely visible, so T_inf and B trade off against each other: a good fit with absurd parameters (non-identifiability — the stretch task measures it with cov = s²(JᵀJ)⁻¹). A random holdout sits *between* fitted points, where the polynomial interpolates well, so it still wins.

## Common confusions

**Q:** Lowest RMSE on my data = best model. — **A:** 0.148 C on fitted data, 12.517 C on the next four hours.

**Q:** A good fit means good parameters. — **A:** The 0–5 h fit has RMSE 0.170 and T_inf = −71014 C.

**Q:** Any holdout will do. — **A:** Every third reading still picks poly-6; forecasting needs a time-ordered split.
