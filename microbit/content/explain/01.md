# Set up your environment — explained

## The intuition
The same `main.py` lives three lives: in the browser simulator (real MicroPython compiled to WebAssembly), on a physical board, and on your PC under CPython with a hand-written stub of the `microbit` module. 

Logic sits in small functions (`hello()`, `step(count)`) that tests call one at a time; the endless `while True` loop only starts behind `if __name__ == "__main__":`, so importing the file is safe.

**Analogy:** a web handler tested with a fake request object. Where the analogy breaks: the stub has no real timing, fonts or sensors, so it proves logic, not MicroPython behaviour.

```
            main.py
   ┌───────────┼──────────────┐
simulator    board        CPython + labs/sim_stub
(serial      (USB         load_lab() imports as "lab_01_setup"
 panel)       serial)     → guard skips main() → tests call hello(), step()
```

The one thing to remember: keep logic in functions and the loop behind the `__main__` guard, so one file runs everywhere.

## Walkthrough: what actually happens when you run it
1. **You run** `python3 main.py` in `labs/L100/01-setup`.
   **What happens inside** CPython has no `microbit` module.
   **What you see**
   ```
   ModuleNotFoundError: No module named 'microbit'
   ```
   **What it means** On a PC you run the tests, which add `labs/sim_stub` to the path.

2. **You run** `python3 -m unittest -v`.
   **What happens inside** `load_lab()` resets the stub and imports `main.py` under a non-`__main__` name; `serial()` captures `print()`.
   **What you see**
   ```
   test_hello_shows_image_and_prints (test_main.SetupLab.test_hello_shows_image_and_prints) ... ok
   test_step_counts_up (test_main.SetupLab.test_step_counts_up) ... ok
   …
   Ran 4 tests in 3.702s
   ```
   **What it means** The README says 0.009s; 3.702s here is the slow storage mount.

3. **You run** a peek: `hello()`, `step(0)`, `sleep(1000)`, `step(1)` against the stub.
   **What happens inside** `sleep` only moves a virtual clock.
   **What you see**
   ```
   'hello from micro:bit\ntick 1\ntick 2\n'
   image: Image('00000:09090:00000:90009:09990:') is HAPPY: True
   running_time(): 1000
   ```
   **What it means** No real second passed; the stub owns time.

4. **You run** `python3 try_it.py`.
   **What you see**
   ```
   try 1: 'hello from micro:bit\ntick 1\ntick 2\ntick 3\ntick 4\n', running_time()=1000 ms
   try 2: import returned=False, serial='hello from micro:bit\ntick 1\ntick 2\ntick 3\n'
   ```
   **What it means** Without the guard, the import starts the loop and never returns; the runner stopped it after 3 sleeps.

Expected (not run here): the python.microbit.org simulator shows a happy face and prints `tick` once per real second.

## Common confusions
**Q:** The stub passing means it works on the board. — **A:** It proves logic only; `Image('00000:09090:…')` is an illustrative bitmap, not the real font.

**Q:** `sleep(1000)` makes tests slow. — **A:** `running_time(): 1000` appears instantly; the stub clock is virtual.

**Q:** The guard is boilerplate. — **A:** Try 2: `import returned=False`.
