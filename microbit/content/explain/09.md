# Pins and PWM on the edge connector — explained

## The intuition
A pin is a wire the program can drive or read. Driven **digitally** it is either 0 V or 3.3 V — on or off. A real LED or motor wants "a bit on", and a digital pin cannot output 1.6 V. **PWM** (pulse-width modulation) fakes it: switch the pin on and off quickly and choose what fraction of each period it stays on. `pin2.write_analog(511)` means "on for 511/1023 of every 20 ms period"; anything slow enough (an eye, a motor) sees the average, about half power.

Inputs use the same idea of *level vs edge* as buttons. `pin_logo.is_touched()` is a level: true for every poll while your finger is there. A toggle must react to the **edge** — the moment touch starts — so the lab remembers `logo_was` and toggles only on a False→True change.

**Analogy:** a dimmer made from a light switch flicked very fast. Where the analogy breaks: the "average" only exists for slow loads; a fast sensor or a scope sees a square wave, not a steady voltage.

```
pin_logo.is_touched() ─► edge detect (logo_was) ─► state.on
button A/B ─► level 0..4 ─► duty_for(level) = level*1023//4
pin0 touched ─► boost: duty = 1023
          state ─► pin1.write_digital(on)        0 V / 3.3 V
                └► pin2.write_analog(duty)       ┌┐_┌┐_┌┐_  period 20 ms
                                                 average ≈ duty/1023 × 3.3 V
```

The one thing to remember: PWM sets a fraction of time on, and a toggle needs an edge, not a level.

## Walkthrough: what actually happens when you run it
1. **You run** a peek that prints the duty table and the PWM period.
   **What happens inside** `duty_for` uses integer division; `set_analog_period(20)` is stored in microseconds.
   **What you see**
   ```
   duty_for(0..4): [0, 255, 511, 767, 1023]
   pin2 period us: 20000
   ```
   **What it means** Five evenly spaced steps; 20 ms = 50 Hz.

2. **You run** a sequence: one idle step, logo held for 3 polls, released, A clicked, pin 0 touched, released.
   **What happens inside** the first held poll sees the edge and toggles `on`; the next two see `logo_was=True` and do nothing; `report != state["last"]` suppresses repeated lines.
   **What you see**
   ```
   on=0,level=2,duty=0
   on=1,level=2,duty=511
   on=1,level=3,duty=767
   on=1,level=3,duty=1023
   on=1,level=3,duty=767
   pin1 history: [('digital', 1), ('digital', 1), ('digital', 1)] pin2 last: ('analog', 767)
   avg volts at 767: 2.47
   ```
   **What it means** Holding for 3 polls toggled once. Boost forces 1023 only while touched. 767/1023 × 3.3 V ≈ 2.47 V average.

3. **You run** `write_analog(1024)` in the same peek.
   **What you see**
   ```
   ValueError: value must be between 0 and 1023
   ```
   **What it means** The 10-bit range is enforced, as on the device.

4. **You run** `python3 try_it.py`.
   **What you see**
   ```
   try 1: on=1,level=2,duty=511 | on=0,level=2,duty=0 | on=1,level=2,duty=511
   try 2: on=1,level=2,duty=682 | duty_for(0..3) = [0, 341, 682, 1023]
   ```
   **What it means** Without the edge check, a held finger flickers the light every poll. With 3 levels, level 2 is 682, not 511.

5. **You run** the unit tests and the build-task check on `solution.py`.
   **What you see**
   ```
   Ran 10 tests in 0.891s
   Ran 2 tests in 0.520s
   ```
   **What it means** The build task maps `pin0.read_analog()` (0–1023) straight to duty — same scale both ways.

Expected (not run here): the simulator's pins accept only touch 0/1, so the potentiometer mode can only be checked on the stub; on a real board pin 2 to an LED needs a series resistor.

## Common confusions
**Q:** `write_analog` outputs a voltage. — **A:** It outputs a square wave; the 2.47 V is an average.

**Q:** Toggling on `is_touched()` is fine. — **A:** Try 1 shows it toggling every poll.

**Q:** Duty can be a percentage. — **A:** It is 0–1023; 1024 raises `ValueError`.
