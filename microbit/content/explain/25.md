## The big picture
**Pins and PWM on the edge connector** gave you an actuator (duty 0–1023) and **Sensing temperature and light** a sensor; put a heater between them and you have a control loop, which raises the question *how much gain is safe, and why does a P-controller never quite reach the set-point?* **Non-blocking firmware structure** gave each task a period and a budget; *when are all deadlines guaranteed?* (Liu & Layland's bound). **A reliable radio protocol** and **A serial gateway to the PC** trusted CRC-16 to catch damage; *which errors is it guaranteed to catch?* — and, via linearity, why **Securing constrained devices: authenticated radio frames** needed a MAC on top. `labs/L500/25-control-realtime/foundations3.py` checks all three.

### Closed-loop stability and steady-state error of a first-order plant
**In plain words** A heated room behaves like x[k+1] = a·x[k] + b·u[k]. Proportional control u = Kp·(r − x) is stable only below a maximum gain, and always leaves an error r/(1 + K·Kp). Adding an integral term (PI) removes the error, even with an unknown constant disturbance.

**Why it is true (intuition)** Feedback turns the system into one first-order recurrence whose "pole" p = a − b·Kp decides everything: |p| < 1 settles, otherwise it oscillates or diverges. P-control needs a non-zero error to produce non-zero heating, so some error must remain. An integrator keeps changing while any error exists, so it can only rest at zero error.
1. Substitute u: x[k+1] = (a − b·Kp)·x[k] + b·Kp·r.
2. Stable iff −1 < a − b·Kp < 1 ⇒ Kp < (1 + a)/b.
3. Fixed point: x* = K·Kp·r/(1 + K·Kp), so e* = r/(1 + K·Kp), with K = b/(1 − a).
4. PI: at equilibrium the integrator sum is constant, so its increment e* = 0, whatever the disturbance.
5. Caveat: saturation (duty pinned at 0 or 1023) makes the loop nonlinear; the integrator can wind up.

**See it in numbers** `python3 foundations3.py`:
```

```
a = e^(−1/60); the boundary 6.000 is sharp. With a real gain of 16 instead of 20, open loop is off by 1 °C, P by 0.1515 °C, PI by 0; pole radii below 1 confirm PI is stable.

### Rate-monotonic utilisation bound (Liu & Layland 1973)
**In plain words** Give shorter-period tasks higher priority. If total CPU utilisation U = ΣCᵢ/Tᵢ ≤ n(2^(1/n) − 1), every deadline is met — guaranteed, for preemptive, independent periodic tasks. The bound falls toward ln 2 ≈ 0.69 as n grows; above it, the test is simply inconclusive.

**Why it is true (intuition)** The worst moment is when all higher-priority tasks release together (the *critical instant*). Find the barely-fitting task set with the *least* utilisation; anything below it must fit.
1. Synchronous release maximises interference: check first jobs only.
2. For n = 2, a "full" set (any longer C misses) has U = r + 2/r − 2 with r = T₂/T₁.
3. Minimise: r = √2 gives U = 2(√2 − 1) = 0.8284.
4. For n tasks the same construction gives rᵢ = 2^(1/n) and U = n(2^(1/n) − 1).
5. Scaling a non-full set up to full only increases U, so below the minimum all fit.

**See it in numbers**
```
OK   T2 RM bound: n(2^(1/n)-1) = 0.8284, 0.7798, 0.7568 (n=2,3,4) -> ln 2 = 0.6931; 2985 random sets under the bound all meet deadlines; tight set U=0.8284 meets, +1 ms misses; harmonic U=1 meets, (2,4),(5,10) U=1 misses; lesson 13 U=0.37 <= 0.7798, but non-preemptive blocking gives the 20 ms button task a 24 ms response
```
All 2,985 random sets under the bound passed; the tight set fails with 1 ms more. Harmonic periods can reach U = 1 — the bound is sufficient, not necessary. Lesson 13's U = 0.37 passes the bound, yet its *cooperative* scheduler cannot preempt, so the button can wait 19 ms behind the sensor: 24 ms > 20 ms.

**Where it shows up in practice** Lesson 13's task budgets.

### CRC detects all bursts of length <= r (polynomial division over GF(2))
**In plain words** A CRC with a degree-r generator G (with G(0) = 1) catches every burst error of length ≤ r. If (x + 1) divides G, it also catches every odd number of flipped bits. CRC-16/CCITT has both properties.

**Why it is true (intuition)** The CRC is a remainder after polynomial division, and remainders are linear: an error E slips through only if G divides E. A short burst is a polynomial of degree below G's — too "small" to be a multiple of G.
1. Linearity: CRC(M + E) differs from CRC(M) by E·xʳ mod G, so undetected iff G | E.
2. A burst at bit i is xⁱ·B(x); G shares no factor with xⁱ, so G | E iff G | B.
3. Length ≤ r ⇒ deg B < r ⇒ G cannot divide B.
4. Length r + 1 ⇒ only B = G slips: 1 in 2^(r−1).
5. Odd weight ⇒ E(1) = 1, but G(1) = 0, so G ∤ E.

**See it in numbers**
```
OK   T3 CRC-16/CCITT-FALSE: matches lab 12 crc16, check("123456789") = 0x29B1, register = M(x)x^16 mod G; linear over GF(2) (3000 random patterns); 64-bit message: all bursts of length 1-16 detected, length 17: 48 undetected in 48 positions (1 in 2^15 each); all 41664 3-bit errors detected (x+1 | G)
```
The 48 undetected length-17 bursts are B = G at each position — the one pattern in 2¹⁵ the theorem allows. 41,664 = C(64, 3), all caught.

**Where it shows up in practice** Lab 12's `crc16`. Linearity also makes it useless against attackers: anyone can compute the CRC change for a chosen payload change.

## Common confusions
**Q:** More gain always means less error. — **A:** Past Kp = 6.000 the loop diverges.

**Q:** U > bound means missed deadlines. — **A:** Harmonic U = 1 meets them.

**Q:** CRC stops tampering. — **A:** It is linear and keyless; lesson 19 added SipHash.
