# Motion and gestures — explained

## The intuition
The accelerometer measures acceleration on three axes in milli-g. Lying still, it mostly measures gravity: about 1000 mg pointing down, split across x, y and z depending on how the board is tilted. Tilt is therefore just "how much of gravity has moved onto the x axis".

Gestures ("shake", "face down") are a layer above: the runtime watches the stream of samples and names patterns. Like buttons, you can ask *is it happening now?* (`is_gesture`) or *did it happen since I last asked?* (`was_gesture`, cleared on read).

**Analogy:** a spirit level plus a motion-alarm log. Where the analogy breaks: real gestures are recognised from noisy motion and only while you keep polling; the stub just sets a name.

```
accelerometer ─► get_values() ─► (x, y, z) ─► tilt(x): >300 right, <-300 left, else flat
              └► gesture engine ─► current_gesture()  (level)
                                 └► was_gesture("shake") (event, cleared on read)
```

The one thing to remember: tilt is a threshold on gravity; a gesture event is consumed once.

## Walkthrough: what actually happens when you run it
1. **You run** a peek: one `step()` with the stub's resting values, then the vector strength.
   **What happens inside** the stub starts face up, all gravity on z.
   **What you see**
   ```
   x=0,y=0,z=-1024,tilt=flat,gesture=
   strength: 1024
   ```
   **What it means** 1024 mg ≈ 1 g, the gravity vector's length.

2. **You run** x = 800 mg, then x = −300 mg.
   **What happens inside** `tilt()` uses strict `>` and `<` against `TILT_MG = 300`.
   **What you see**
   ```
   x=800,y=0,z=-600,tilt=right,gesture=
   x=-300,y=0,z=-600,tilt=flat,gesture=
   ```
   **What it means** Exactly −300 is still flat: the boundary is exclusive.

3. **You run** `inject_gesture('shake')` then two more `step()` calls.
   **What happens inside** the first `was_gesture("shake")` returns True and clears the event; `current_gesture()` still reports the level.
   **What you see**
   ```
   x=-300,y=0,z=-600,tilt=flat,gesture=shake
   shake!
   x=-300,y=0,z=-600,tilt=flat,gesture=shake
   ```
   **What it means** One shake, one `shake!`. The stub keeps `gesture=shake` until changed; Expected (not run here): on hardware or in the simulator the current gesture fades after the motion stops.

4. **You run** `python3 try_it.py` and `python3 -m unittest -v`.
   **What you see**
   ```
   try 1: x=200,y=0,z=-1024,tilt=right,gesture=
   try 2: 'shake!' printed 3 time(s) in 3 polls
   Ran 6 tests in 0.077s
   ```
   **What it means** A 100 mg threshold makes small tilts count; `is_gesture` fires on every poll while the gesture is current.

## Common confusions
**Q:** Values are in g. — **A:** They are milli-g; `strength: 1024` is one g.

**Q:** `current_gesture()` and `was_gesture()` are the same. — **A:** Step 3: both lines show `gesture=shake`, but `shake!` prints once.

**Q:** The stub tests gesture recognition. — **A:** It injects names; recognition only happens in the runtime.
