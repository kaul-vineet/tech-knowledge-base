# Sensing temperature and light — explained

## The intuition
Sensor labs have three beats: **sample**, **classify** (numbers → named state), **act** (log and show). `classify(temp_c, light)` is a pure function, so it can be tested with any numbers.

`temperature()` is the processor's own die temperature in whole degrees, so it reads a little above the room. `display.read_light_level()` (0–255) works by running the LED matrix backwards as light sensors.

**Analogy:** a feature flag evaluated by a pure function of request attributes. Where the analogy breaks: sensor values drift and jitter; a single threshold will flicker around its edge (hysteresis is the L200 fix).

```
temperature() ─┐
               ├─► classify(t, light) ─► "dark" | "hot" | "ok"
read_light_level() ┘     (dark checked first)        │
                                 print("temp=..,light=..,state=..") + display
```

The one thing to remember: the order of `if` checks is a priority rule, and the thresholds are inclusive or exclusive on purpose.

## Walkthrough: what actually happens when you run it
1. **You run** a peek: inject four (temperature, light) pairs into the stub and call `step()` for each.
   **What happens inside** `HOT_C = 26` is tested with `>=`; `DARK_LEVEL = 40` with `<`; dark is checked before hot.
   **What you see**
   ```
   temp=25,light=128,state=ok
   temp=26,light=128,state=hot
   temp=30,light=39,state=dark
   temp=30,light=40,state=hot
   ```
   **What it means** 26 is already hot (inclusive). Light 39 is dark but 40 is not (exclusive). At 30 °C and light 39 both rules fire; dark wins.

2. **You run** `python3 try_it.py`.
   **What you see**
   ```
   try 1: temp=27,light=128,state=ok
   try 2: temp=30,light=10,state=hot
   ```
   **What it means** Raising `HOT_C` to 28 makes 27 normal; moving the hot check first flips the priority.

3. **You run** `python3 agent_assist.py --fake`.
   **What happens inside** code classifies the five telemetry lines first; a fake local model writes an explanation; `check_explanation()` rejects any number not in the telemetry or thresholds.
   **What you see**
   ```
   code decision (authoritative): 5 readings, alarms: #3 hot (temp=27, light=110), #4 dark (temp=30, light=35)
   …
   check: PASS (numbers all from telemetry; alarm states named)
   ```
   **What it means** The model explains; the code decides. A `REJECTED` would mean it invented a number.

4. **You run** `python3 -m unittest -v`.
   **What you see**
   ```
   Ran 12 tests in 1.323s
   ```

Expected (not run here): in the simulator, sliders feed these values.

## Common confusions
**Q:** `temperature()` is room temperature. — **A:** It is the chip's estimate; the agent text says it "can read a little above the room".

**Q:** At 30 °C and light 39 the board shows H. — **A:** It shows the sleeping face: `state=dark`.

**Q:** The model decides the alarms. — **A:** `code decision (authoritative)` is printed before the model speaks.
