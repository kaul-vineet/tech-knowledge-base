# Sound — explained

## The intuition
`music` plays notes (a melody is a list like `"c4:2"`); `audio` plays built-in sounds or a `SoundEffect` you design. Both drive pin 0 and, on a V2, a built-in speaker you can switch off.

The key behaviour is **blocking**: `music.play(TUNE)` does not return until the tune is over. While it plays, your loop is not polling buttons.

**Analogy:** a synchronous HTTP call inside a request handler. Where the analogy breaks: `wait=False` plays in the background, and note length depends on tempo state carried between notes.

```
A pressed ─► music.play(TUNE)  ──► pin 0 ─┬─► speaker (if speaker.on)
                 blocks 2.5 s              └─► headphones on pin 0/GND
logo touched ─► audio.play(SWEEP)
B pressed ─► speaker.off()/on()   (closes one tap only)
```

The one thing to remember: a blocking tune is time your loop is not listening.

## Walkthrough: what actually happens when you run it
1. **You run** a peek: `start()`, click B, `step()`, click A, `step()`, then print the stub's `sound_log`.
   **What happens inside** each call records `(source, what, speaker_on)`.
   **What you see**
   ```
   sound ready
   speaker off
   tune played
   ('audio', 'hello', True)
   ('music', ('pitch', (440, 200)), True)
   ('music', ('play', ['c4:2', 'e', 'g', 'c5:4', 'r:2', 'g4:2', 'c5:6']), False)
   clock: 0
   ```
   **What it means** The tune is still played with the speaker off — pin 0 still gets it. `clock: 0` shows the stub does not model the 2.5 s block; a real board would.

2. **You run** `python3 try_it.py`.
   **What happens inside** the runner applies the note rules: octave and ticks carry over. `c4:2, e, g` are 2 ticks each, `c5:4` is 4, `r:2` and `g4:2` are 2, `c5:6` is 6 — 20 ticks × 125 ms.
   **What you see**
   ```
   try 1: variant 16 ticks = 2000 ms (original 20 ticks = 2500 ms)
   try 2: serial='speaker off\ntune played\n', music.play calls=1, speaker_on during play=False
   ```
   **What it means** Dropping `:6` makes the last `c5` reuse the previous 2 ticks, saving 500 ms of blocked loop.

3. **You run** `python3 -m unittest -v`.
   **What you see**
   ```
   Ran 7 tests in 0.048s
   ```
   **What it means** Tests assert what was requested, not heard.

Expected (not run here): the simulator plays audio only after you click the page. Whether `speaker.off()` is audible there was not verified.

## Common confusions
**Q:** `speaker.off()` mutes everything. — **A:** The log line ending in `False` shows the tune still played, to pin 0.

**Q:** Each note without `:n` is one tick. — **A:** It reuses the last duration; try 1 shows 16, not 15, ticks.

**Q:** The stub proves timing. — **A:** `clock: 0` — it proves calls, not durations.
