# The LED display — explained

## The intuition
The 5×5 display is a tiny framebuffer: 25 numbers, each a brightness from 0 (off) to 9 (brightest). Every `display.show(...)` replaces the whole buffer, which a driver scans onto the LEDs. A custom `Image("00900:09590:…")` is just those 25 digits typed row by row, `:` ending each row.

Built-in images such as `Image.HEART` are read-only constants. To change one, `copy()` it first.

**Analogy:** a 5×5 spreadsheet whose cell values set the light. Where the analogy breaks: brightness is perceptual and rendered differently by the simulator and real LEDs; 9 is not "nine times" 1.

```
DIAMOND string ──Image()──► 25 ints ──display.show()──► buffer ──scan──► LEDs
level ──level_image()──► fill(level) ──show()──► buffer   (stub: history list)
```

The one thing to remember: the display is state you replace, not pixels you draw over time.

## Walkthrough: what actually happens when you run it
1. **You run** `intro()` against the stub and print `display.history`.
   **What happens inside** `scroll("Hi")` is recorded, `show(Image.HEART)` and `show(DIAMOND)` each copy an image into the buffer; the two `sleep(500)` calls move the virtual clock.
   **What you see**
   ```
   [('scroll', 'Hi'), ('show', "Image('09090:99999:99999:09990:00900:')"), ('show', "Image('00900:09590:95159:09590:00900:')")]
   clock after intro: 1000 ms
   ```
   **What it means** The stub's scroll takes no time; only the sleeps count. Expected (not run here): in the simulator "Hi" scrolls for roughly a second before the heart, because `scroll` blocks.

2. **You run** the same peek for pixel data.
   **What happens inside** `level_image(4)` makes a blank image and `fill(4)`s it; the diamond's digits are summed.
   **What you see**
   ```
   DIAMOND sum: 93
   level_image(4): Image('44444:44444:44444:44444:44444:')
   TypeError: image cannot be modified (try copying first)
   ```
   **What it means** The error comes from `Image.HEART.set_pixel(...)`: built-ins are read-only, as on the device.

3. **You run** `python3 -m unittest -v`.
   **What you see**
   ```
   test_builtin_images_are_read_only … ok
   …
   Ran 6 tests in 0.076s
   ```
   **What it means** Tests compare buffers and history, never the scrolling animation.

4. **You run** `python3 try_it.py`.
   **What you see**
   ```
   try 1: lit=13, sum=101, centre=9
   try 2: 0 1 2 3 4 0 1
   ```
   **What it means** Changing the centre 1 to 9 adds 8 (93 → 101) but keeps 13 lit LEDs. With `% 5` the ramp wraps after 4.

## Common confusions
**Q:** Brightness goes 0–255 like MakeCode. — **A:** MicroPython uses 0–9; `fill(level)` raises `ValueError` outside that range.

**Q:** `show()` draws on top of what is there. — **A:** It replaces the buffer; history shows three whole images.

**Q:** I can tweak `Image.HEART` directly. — **A:** The `TypeError` line says copy first.
