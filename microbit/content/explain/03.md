# Buttons — explained

## The intuition
A button answers three different questions:
- `is_pressed()` — *is it held down right now?* (a level)
- `was_pressed()` — *has it been pressed since I last asked?* (a yes/no flag, cleared when read)
- `get_presses()` — *how many times since I last asked?* (a counter, reset when read)

Your loop polls every 100 ms. Presses during the sleep wait in the runtime until you ask.

**Analogy:** an unread-message badge. `get_presses()` reads the number and marks all read; `was_pressed()` only says it was non-zero. Where the analogy breaks: real buttons bounce electrically; the stub has no bounce and no timing at all.

```
click ─► runtime: _down, _was=True, _presses+=1
loop every 100 ms ─► step(count)
     count += button_a.get_presses()   (read + reset)
     if button_b.was_pressed(): count = 0
     if changed: print + display.show(count % 10)
```

The one thing to remember: reading `was_pressed` or `get_presses` consumes the event.

## Walkthrough: what actually happens when you run it
1. **You run** a peek: `button_a.click(3)` before one `step(0)`.
   **What happens inside** each click sets `_was` and bumps `_presses`.
   **What you see**
   ```
   pending presses: 3 was flag: True
   count 3
   ```
   **What it means** All three presses arrived in one poll, as with `sleep(3000)` in step 4 of the lesson.

2. **You run** `step()` again with no clicks, then click B, then hold A and B together.
   **What happens inside** the second call reads 0 presses (already consumed), so nothing prints. B's flag resets to 0. With both held, A adds 1, B's fresh flag resets to 0, so the count is unchanged and only the level check fires.
   **What you see**
   ```
   count 0
   both held
   display last_text: 0
   ```
   **What it means** The `count 1` you might expect never prints: the B reset happened in the same step.

3. **You run** `python3 -m unittest -v` and `python3 try_it.py`.
   **What you see**
   ```
   Ran 7 tests in 0.034s
   try 1: count=1, serial='count 1\n'
   try 2: after 3 clicks: count=0 serial=''; held for 3 polls: count=3 serial='count 1\ncount 2\ncount 3\n'
   ```
   **What it means** `was_pressed()` collapses three clicks to 1; `is_pressed()` misses quick clicks entirely and counts a hold once per poll.

## Common confusions
**Q:** `is_pressed()` is enough for counting. — **A:** Try 2 shows `count=0` after three clicks.

**Q:** I can call `was_pressed()` twice to check. — **A:** The second call returns False; the first read cleared it.

**Q:** A slow loop loses presses. — **A:** `pending presses: 3` shows they wait for `get_presses()`.

## Check your understanding
