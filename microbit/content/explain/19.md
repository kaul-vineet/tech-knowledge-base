# Securing constrained devices: authenticated radio frames — explained

## The intuition
Lab 12's CRC answers "was this frame damaged by noise?" It cannot answer "did one of *my* boards send it?" — anyone can compute a CRC. In a classroom the attacker is a student with a second micro:bit on the same group who can **record and replay** frames and **forge** new ones (a fake 45 °C reading that trips a false alarm).

Two separate properties are needed:
- **Authenticity** — a **MAC** (message authentication code): a tag computed from the frame *and a secret key* that only the device and gateway share. Without the key you cannot produce a valid tag. The lab uses **SipHash-2-4**, a small keyed hash for short inputs, in pure Python (micro:bit MicroPython documents no `hashlib`).
- **Freshness** — a per-device **counter** in every frame plus a **sliding window** at the gateway (64 counters, like IPsec's anti-replay window). Newer than the highest → accept and slide; inside the window and unseen → accept (the radio reorders); seen or too old → reject.

The order of checks matters: format → known device → MAC → replay window. Only a frame that passed the MAC may move the window; otherwise a forger could push the window forward with junk and make genuine frames look "old".

**Analogy:** a signed JWT with a nonce check — signature first, then "seen this ID?". Where the analogy breaks: the key sits in the board's flash, so physical access defeats the scheme.

```
device: body = "n1:7:21.5" → tag = SipHash24(key_n1, body) → "n1:7:21.5:67dc8be19df0c9cc"
gateway check(text):
   split → dev known? → compare_digest(tag, SipHash(key_dev, body))? → fresh(dev, ctr)? → accept
           reject:unknown_device      reject:mac                     reject:replay
```

The one thing to remember: CRC is for noise, a MAC is for people; check the MAC before letting a frame touch any state.

## Walkthrough: what actually happens when you run it
1. **You run** a peek: seal one frame, then feed the `solution.py` verifier a genuine frame, its replay, a forged frame, a tampered copy, an older in-window frame and an unknown device.
   **What you see**
   ```
   sealed frame: n1:7:21.5:67dc8be19df0c9cc | tag bytes on air: 17
   genuine           -> ('n1', 7, '21.5')
   replay            -> None
   forged            -> None
   tampered          -> None
   older, in window  -> ('n1', 5, '21.0')
   unknown dev       -> None
   ```
   **What it means** The tag is 64 bits = 16 hex chars + `:` = 17 bytes. The tampered copy reuses a valid tag on a different body and fails the MAC; counter 5 after 7 is accepted because it is inside the window and unseen.

### The decision: three options under the same attack
2. **You run** `python3 attacks.py` (seed 19: 3 boards × 60 frames over loss 10 %, dup 5 %, reorder 10 %, corrupt 2 %; Eve replays 20 and forges 20).
   **What you see**
   ```
   {"verifier": "verifier.py", "mode": "crc", … "genuine_intact": 158, "genuine_accepted": 158, "forged_accepted": 20, "replays_accepted": 18, …}
   {"verifier": "solution.py", "mode": "toy", … "genuine_intact": 158, "genuine_accepted": 140, "forged_accepted": 19, "replays_accepted": 0, "toy_state_recovered": true, …}
   {"verifier": "solution.py", "mode": "siphash", … "genuine_intact": 160, "genuine_accepted": 160, "forged_accepted": 0, "replays_accepted": 0, …}
   ```
   **What it means**
   - **A, CRC only:** every forgery and 18 of 20 replays get in (2 were lost on air).
   - **B, toy keyed checksum** (CRC-16 seeded with the key): Eve brute-forces the 16-bit state from 2 frames (65,536 guesses) and forges 19. Worse, her forged counters *moved the window*: only 140 of 158 genuine frames accepted. Labelled NOT cryptographically secure.
   - **C, SipHash + window:** 0 forged, 0 replays, all intact genuine accepted.

3. **You run** `python3 cost.py`.
   **What you see**
   ```
   {"mode": "siphash", "tag_bytes_on_air": 17, "cpython_us_per_tag": 152.4, "rounds": 10, "ops64": 140}
   {"counter_flash_writes_per_1000_frames": 10}
   ```
   **What it means** 140 64-bit operations per frame; 10 flash writes per 1,000 frames. CPython microseconds say nothing about micro:bit speed.

### Failure lab: inject → symptom → diagnose → fix → proof
4. **Inject / symptom:** option A's row. **Diagnose:** `verifier.py` checks only the CRC — there is no secret. **Fix:** `solution.py`. **Proof:**
   **What you see**
   ```
   AssertionError: 0 != 160
   AssertionError: None is not true
   AssertionError: Lists differ: [False, False, False, False] != [True, True, True, True]
   FAILED (failures=3)
   Ran 4 tests in 16.206s
   ```
   **What it means** Before: no genuine frame accepted, forgeries move the window, no reordering tolerance. After: 4 tests OK.

### Why the ADR chose C, and how it stays true
5. ADR 0019: SipHash-2-4, per-device random 128-bit key, counter persisted every 100 frames, check order format → device → MAC (constant-time) → window, verified at the gateway, the trust boundary. Admitted consequences: no confidentiality, keys readable with physical access, MicroPython 64-bit speed unmeasured.
6. **You run** `python3 -m unittest test_fitness`.
   **What you see**
   ```
   Ran 1 test in 44.512s
   ```
   **What it means** Seeds 1–5: `forged_accepted == 0`, `replays_accepted == 0`, `genuine_accepted == genuine_intact`.

7. **You run** `python3 try_it.py`.
   **What you see**
   ```
   try 1: genuine accepted 159 of 160 intact, forged accepted 0, replays accepted 0
   try 2: genuine accepted 143 of 160 intact, forged accepted 0, replays accepted 0
   ```
   **What it means** `WINDOW = 1` rejects one reordered genuine frame. Checking replay before the MAC still blocks every forgery — but forged frames now slide the window, and 17 genuine frames are lost: a denial of service.

## Common confusions
**Q:** A keyed CRC is a MAC. — **A:** `toy_state_recovered: true`; 19 forgeries accepted.

**Q:** Check order does not matter. — **A:** Try 2: 143 of 160 genuine.

**Q:** Authentication hides the readings. — **A:** `21.5` is in clear text; there is no confidentiality.
