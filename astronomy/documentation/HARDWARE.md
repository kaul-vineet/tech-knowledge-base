# Hardware — Astronomy L100-L400 + capstone (Mac mini + Windows PC, no telescope)

**No telescope or camera needed.** Stellarium simulates the sky; labs use seeded synthetic star fields, light curves and catalogues, plus small official tables (JPL orbital elements, the IERS leap-second list). Installs: `../../shared/WORKSTATION-SETUP.md`; GUI tools: `LEARNING-TOOLS.md`.

**What runs where.** Every lab runs on both machines: single-threaded Python + numpy on the CPU, no GPU. Stellarium needs OpenGL 3.3 (2.1 minimum), 4 GiB RAM recommended; stellarium.org lists a universal macOS 11+ build and Windows x86_64 and ARM64 builds. DS9, TOPCAT (Java) and AstroImageJ ship Apple-silicon and Windows x64 packages (see LEARNING-TOOLS.md). Optional agent assist (lessons 2, 10, 18, capstone): Ollama uses Metal on Apple silicon; on Windows NVIDIA/AMD GPUs or CPU (per WORKSTATION-SETUP). `qwen2.5:1.5b` is about 1 GB.

**Wheels.** PyPI lists macOS 11+ ARM64 and Windows x86-64 wheels for astropy 8.0.2 and photutils 3.1.1; skyfield 1.55 is a pure-Python wheel. REBOUND 5.2.2's wheel list was not retrieved; CI installs it without `--only-binary`, so it may compile (needs a C compiler on the runner). L300/L400: astroplan 0.10.1 is an sdist only (pure Python); healpy 1.20.1 has no Windows wheels (use WSL2 or skip lesson 19's equivalent); astrometry.net (lesson 14 tool) is Homebrew on the Mac and WSL2-only on Windows.

**RAM and time.** The largest allocation is lesson 10's periodogram: 1104 points × 1438 frequencies, peak 36.4 MiB (tracemalloc, Linux). Lesson 10's bootstrap solution (300 periodograms) took about 25 s wall-clock in the sandbox; everything else takes a few seconds. 8 GB RAM is plenty. Lessons 17 and 19 measure throughput and cone-search time; their numbers come from a 1-CPU Linux sandbox and will differ on a multi-core Mac mini or Windows PC (the READMEs give ranges; lesson 17's process pool uses spawn on macOS and Windows).

**Floating point.** IEEE arithmetic gives the same bits on Apple silicon and x64 for + − × ÷ and sqrt; `sin`, `log`, `exp` come from the platform's maths library and may differ in the last bit. The READMEs print rounded values, and `labs/L100/cross_platform` … `labs/L400/cross_platform` check them on all three CI runners. Lesson 9's Poisson noise uses numpy's generator; tiny libm differences could in principle change one draw (checked by the L200 fingerprint).
