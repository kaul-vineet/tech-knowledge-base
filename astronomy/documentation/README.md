# Astronomy & Astrophysics (applied) — L100 "Run it", L200 "Build it", L300 "Harden it", L400 "Design it" + capstone, L500 "Theory & Rigour"

**Status: all 27 lessons (L100-L400, capstone, L500 theory) validated locally on Linux; not yet run on macOS or Windows; CI matrix (`.github/workflows/labs.yml`) pending.**

Start here. This topic teaches software engineers to compute, simulate and analyse the sky with code: coordinates and time scales, units and magnitudes, orbits, spectra, catalogues, FITS images, photometry, light curves and N-body simulation, then observation planning, calibration, pipelines and an exoplanet capstone. Civilian and scientific only. No telescope or camera is needed: Stellarium is the sky simulator, and the labs use seeded synthetic data or small tables from official sources (JPL, IERS, USNO); real Gaia/TESS data paths are optional and pending-ci. Default observer: Gurgaon, India (28.46 N, 77.03 E); every lab also takes any other location.

## How to run the labs
```bash
python --version                                   # 3.12 or newer
python -c "import numpy; print(numpy.__version__)" # 2.5.3 used for validation
cd labs/L100/02-coordinates
python sky.py                                      # compare with "Expected output" in the lab README
python try_it.py                                   # the two tryIt experiments
python -m unittest -v                              # the lab's tests
```
- Main labs need only Python 3.12 and numpy. Inputs are fixed or seeded, so outputs match the READMEs exactly.
- Library equivalents (`*_astropy.py`, `kepler_skyfield.py`, `photometry_photutils.py`, `nbody_rebound.py`, `plan_astroplan.py`, `calibrate_ccdproc.py`, `fit_emcee.py`, `cache_joblib.py`, `alert_avro.py`, `healpix_check.py`, `pyvo_query.py`, `bessel_scipy.py`, `validate_external.py`, `fetch_tess.py`) need `python -m pip install -r labs/L100/01-setup-workbench/requirements.txt` (L200/L300/L400: `labs/L<level>/requirements.txt`, each including the level below). Locally their tests are **skipped**, not passed.
- Build tasks (L200-L400): each lab ships the UNFINISHED or faulty feature; the reference lives in `solution/`. L400 labs also have `test_fitness.py` (architecture fitness functions); the capstone has milestone tests and a scorecard (`python run_capstone.py`). `python -m unittest test_build_task -v` checks the solution; `BUILD_TARGET=mine` (PowerShell: `$env:BUILD_TARGET = "mine"`) checks your edited file and fails on the shipped one.
- CI: `.github/workflows/labs.yml` runs every demo, tryIt, solution, equivalent and test suite on `ubuntu-latest`, `macos-latest` (Apple silicon) and `windows-latest`. GitHub only runs workflows from the repository root (see `../CI.md`).
