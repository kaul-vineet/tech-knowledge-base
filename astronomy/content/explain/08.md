# FITS images and WCS: a minimal reader and a TAN projection — explained

## The intuition
A telescope image is a grid of numbers plus a recipe for where each pixel points on the sky. FITS stores both: a text header of 80-character cards (keyword = value), then raw big-endian pixels, each part padded to 2880-byte blocks. That simplicity is why a 60-line reader works.

The recipe is the World Coordinate System. A camera projects the curved sky onto a flat chip, like a plane touching the sphere — the gnomonic (TAN) projection. The header names a reference pixel (CRPIX), the sky position it sees (CRVAL) and a CD matrix of degrees per pixel (scale, rotation, flip).

**Analogy:** a georeferenced map tile: the header says where the reference pixel is and how far each pixel spans.
Where the analogy breaks: you do the projection maths yourself, and RA increases to the left (negative CD1_1).

```
array --write_fits()--> 80-char cards + pad 2880 | big-endian data + pad
file --read_fits()--> header dict + array (NAXIS2, NAXIS1)
pixel (x, y) - CRPIX --CD--> (xi, eta) --inverse TAN at CRVAL--> (RA, Dec)
```

The one thing to remember: FITS pixel (x, y) is numpy [y − 1, x − 1], and every sky position goes through CRPIX, CD and the projection.

## Walkthrough: what actually happens when you run it
### Step 1 — write and read back
**You run** `python fitslite.py`

**What happens inside** `write_fits()` builds cards with `card()` (keyword columns 1–8, value right-aligned to column 30), adds END, pads the header with spaces and the data with zeros; `read_fits()` parses blocks until END and reads `>f4`.

**What you see**
```
wrote star_field.fits (20160 bytes = 7 blocks of 2880); header cards: 17 incl. END
read back: shape (64, 64), dtype float32, identical: True
```

**What it means / what would look wrong** One header block plus six data blocks (16384 bytes). A size not divisible by 2880 makes other readers reject the file.

### Step 2 — pixel to sky
**You run** the same command (pixel lines).

**What happens inside** `pixel_to_sky()` subtracts CRPIX, multiplies by CD, then applies the inverse gnomonic formulas around CRVAL.

**What you see**
```
pixel (32.5, 32.5) -> RA 83.822100 Dec -5.391100
pixel (   1,    1) -> RA 83.830889 Dec -5.399850
brightest pixel: numpy [row 45, col 51] = FITS pixel (52, 46)
```

**What it means / what would look wrong** CRPIX maps to CRVAL; pixel (1, 1) has larger RA (east left); 31.5 pixels span 31.5 arcsec of Dec. Swapping row and column would point at the wrong pixel without any error message.

### Step 3 — the build task: sky to pixel
**You run** `BUILD_TARGET=mine python -m unittest test_build_task -v`, then `python solution/fitslite.py`.

**What happens inside** Shipped `sky_to_pixel()` raises `NotImplementedError`. The solution projects onto the tangent plane (dividing by cos c, the distance from the tangent point) and inverts CD with `np.linalg.solve`.

**What you see**
```
FAILED (errors=3)
pixel (   1,    1) -> RA 83.830889 Dec -5.399850 -> back to pixel (1.000000, 1.000000)
```

**What it means / what would look wrong** The round trip is exact to six decimals. Suite: `Ran 10 tests ... OK (skipped=1)`; Astropy reads the same file in CI.

## Common confusions
- **Q:** "NAXIS1 is the number of rows." — **A:** NAXIS1 is the fastest axis (x, columns); numpy shape is (NAXIS2, NAXIS1).
- **Q:** "Pixel (1, 1) is the image corner." — **A:** it is the centre of the first pixel; 32.5 is the centre of 64 pixels.
- **Q:** "Add pixel offsets × 1 arcsec to CRVAL." — **A:** only near the centre; TAN curves away from it and RA steps scale with 1/cos Dec.
