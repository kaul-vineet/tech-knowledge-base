# Time systems: UTC, TAI, TT, Julian Date and sidereal time — explained

## The intuition
Astronomy keeps several clocks. TAI is a smooth atomic count; UTC is TAI with leap seconds so it follows Earth's rotation; TT = TAI + 32.184 s is the uniform time for orbits. A Julian Date (JD) turns any instant into one decimal day count, so date differences are subtraction. Sidereal time measures rotation against the stars and gains about 4 minutes per day.

**Analogy:** Unix time versus wall-clock time with daylight saving.
Where the analogy breaks: leap seconds are announced by the IERS, not computed, so the table expires.

```
UTC --jd_utc()--> JD --(-2400000.5)--> MJD --tai_minus_utc(LEAPS)--> TAI-UTC
TAI + 32.184 s = TT ;  JD(UT1~UTC) --gmst_hours()/era_hours()--> sidereal time
```

The one thing to remember: the leap-second offset is data, not maths, and data expires.

## Walkthrough: what actually happens when you run it
### Step 1 — the scales
**You run** `python timescales.py`

**What happens inside** `scales()` computes JD from Unix seconds; `tai_minus_utc()` takes the last LEAPS row at or before the MJD (57754 → 37 s).

**What you see**
```
JD(UTC)    2461343.145833
TAI-UTC s  37
TT-UTC s   69.184000
J2000.0 in UTC: 2000-01-01T11:58:55.816+00:00
```

**What it means / what would look wrong** J2000.0 is 12:00 TT, so UTC is 64.184 s earlier (32 leap seconds then). A naive datetime shifts JD by your time zone.

### Step 2 — published checks
**You run** the same command (last lines).

**What happens inside** `era_hours()` is IERS eq. 5.14; `gast_hours()` adds USNO's short nutation terms; both meet the Wallace & Capitaine (2006) worked example.

**What you see**
```
... ERA 05h05m03.70s (published 05h05m03.70s) | GAST 05h05m22.19s (published 05h05m22.21s, diff -0.023 s)
GMST short vs USNO full formula: 18h01m54.55s (diff -0.010 s)
```

**What it means / what would look wrong** ERA matches; 0.023 s is the short nutation series. Seconds of error would suggest swapped UT1 and TT.

### Step 3 — another date
**You run** `python timescales.py --utc 2027-01-01T00:00 --lon -0.0015`

**What happens inside** Same lookup, later MJD.

**What you see**
```
TAI-UTC s  37
```

**What it means / what would look wrong** No leap second at the end of 2026. Tests: `Ran 11 tests ... OK (skipped=1)`; the freshness test fails after 2027-06-28.

## Common confusions
- **Q:** "TT − UTC is 32.184 s." — **A:** that is TT − TAI; TT − UTC is 69.184 s.
- **Q:** "Sidereal time is solar time elsewhere." — **A:** GMST is 18h01m at 15:30 UTC: a different clock.
- **Q:** "Leap seconds follow a formula." — **A:** LEAPS is a table with an expiry date.
