# Fitting with honest uncertainty: least squares, bootstrap and MCMC for a transit — explained

## The intuition
A transit fit gives best values and error bars. The values are the easy part; the error bars depend on how noisy you believe the data are. Least squares turns the reported per-point flux_err into parameter errors via the curvature of χ²; if flux_err is too small, so are the error bars.

Three checks keep you honest: reduced χ² (about 1 if flux_err is right), a bootstrap that refits resampled residuals, and coverage — over 200 simulations with known truth, ±1σ should contain the truth about 68 % of the time. MCMC can also fit the noise scale.

**Analogy:** a forecaster's "70 % chance of rain", checked by counting how often it rained on such days.
Where the analogy breaks: you can only count coverage with simulated data whose truth you know; on real data you rely on χ² and the bootstrap.

```
make_data(): trapezoid transit + noise 0.0020 (flux_err says 0.0010)
fit_lm() --> p ; jacobian(p) --> cov = (J^T J / sigma^2)^-1 --> sigma_formal
bootstrap(): best model + resampled residuals --> 300 refits --> sigma_bootstrap
coverage(): 200 seeded datasets --> fraction |fit - truth| <= sigma
```

The one thing to remember: an error bar is a claim you can test — by χ², by bootstrap and by coverage.

## Walkthrough: what actually happens when you run it
### Step 1 — fit, formal errors, bootstrap
**You run** `python transit_fit.py`

**What happens inside** `fit_lm()` is Levenberg–Marquardt on 240 points; `uncertainty()` inverts JᵀJ/σ² with σ = 0.0010; `bootstrap()` refits 300 resampled datasets.

**What you see**
```
{"param": "t0_h", "true": 0.12, "fit": 0.15667, "sigma_formal": 0.00601, "sigma_bootstrap": 0.0128}
reduced chi^2 with the reported flux_err: 4.13
1-sigma coverage over 200 seeded datasets: {'t0_h': 0.36, 'depth': 0.335, 'T14_h': 0.275, 'T12_h': 0.22}
```

**What it means / what would look wrong** The fit is 6σ_formal from the truth. χ²_red of 4.13 says the scatter is √4.13 ≈ 2 times flux_err.

### Failure lab 1/4 — inject and symptom
**You run** the shipped file: the injected fault is `uncertainty()` trusting `SIGMA_REPORTED = 0.0010` while the data scatter by 0.0020.

**What happens inside** Covariance scales with σ², so error bars come out half their true size.

**What you see**
```
1-sigma coverage over 200 seeded datasets: {'t0_h': 0.36, 'depth': 0.335, 'T14_h': 0.275, 'T12_h': 0.22}
```

**What it means / what would look wrong** About 22–36 % coverage instead of 68 %: most published intervals would miss the truth.

### Failure lab 2/4 — diagnose
**You run** `BUILD_TARGET=mine python -m unittest test_build_task`

**What happens inside** The test compares formal with bootstrap errors and checks coverage.

**What you see**
```
AssertionError: np.False_ is not true : [0.36  0.335 0.275 0.22 ]
AssertionError: np.False_ is not true : [0.45460682 0.4750136 ]
FAILED (failures=2)
```

**What it means / what would look wrong** Formal errors are about 0.45–0.48 of the bootstrap: the same factor 2 as √χ²_red.

### Failure lab 3/4 — fix
**You run** `python solution/transit_fit.py`

**What happens inside** `uncertainty()` multiplies the covariance by max(χ²_red, 1).

**What you see**
```
{"param": "t0_h", "true": 0.12, "fit": 0.15667, "sigma_formal": 0.01222, "sigma_bootstrap": 0.0128}
1-sigma coverage over 200 seeded datasets: {'t0_h': 0.73, 'depth': 0.615, 'T14_h': 0.555, 'T12_h': 0.56}
```

**What it means / what would look wrong** Formal now matches bootstrap. Durations stay under 68 % because their likelihood is not Gaussian. Depth near 0.33 would mean no rescaling.

### Failure lab 4/4 — proof
**You run** `python -m unittest test_build_task -v`

**What happens inside** Same tests, solution file.

**What you see**
```
Ran 2 tests in 5.833s
OK
```

**What it means / what would look wrong** `TestFailureLab` in test_transit_fit.py pins the shipped coverage so the fault stays reproducible.

### Step 2 — MCMC with a free noise scale
**You run** `python mcmc.py`, then `python solution/report.py`

**What happens inside** Metropolis samples the four parameters plus ln s, the noise scale; it reports percentiles, acceptance and autocorrelation time τ. `report.py` flags asymmetric intervals.

**What you see**
```
{"param": "noise_scale_s", "median": 2.03536, "minus": 0.09109, "plus": 0.09312}
acceptance 0.270; autocorrelation time 35 steps; effective samples 430
{"param": "T14_h", "median": 2.36204, "plus": 0.07084, "minus": 0.08882, "gaussian": false}
```

**What it means / what would look wrong** The data recover s ≈ 2 on their own. 430 effective samples, not 15 000. Expected (not run here): fit_emcee.py repeats this with emcee in CI.

## Common confusions
- **Q:** "The fit is off, so the model is wrong." — **A:** the values are fine; the error bars were wrong.
- **Q:** "Bootstrap and formal errors always agree." — **A:** only if flux_err is right: 0.0128 vs 0.00601.
- **Q:** "More MCMC steps = more samples." — **A:** divide by τ: 430 effective samples.
