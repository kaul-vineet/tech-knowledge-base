# Open data and science software practice: VO standards, licences, citation and validation — explained

## The intuition
Publishing a derived catalogue is a software release with legal and scientific obligations. Other tools must read it (VOTable with units and UCDs), people must be able to cite it (CITATION.cff), its files must be verifiable (a SHA-256 manifest), and its licence must honour every input's terms. A reviewer who only checks "are the files there?" will pass a release that breaks all of these.

The licence rule is the subtle one. Gaia DR3 data are CC BY-NC 3.0 IGO: NonCommercial. A catalogue derived from Gaia cannot simply be CC-BY-4.0, which allows commercial use. Restrictions propagate: the release must keep NC (and SA, if an input has it). If two restrictions cannot both be kept — NC and ShareAlike — no licence fits, and a person must decide.

**Analogy:** dependency licence checking in a software build: one GPL dependency constrains how you ship the whole product, however small it is.
Where the analogy breaks: data licences (CC, IGO variants, public-domain mission data with acknowledgement requests) have their own families, and credit lines must be quoted verbatim, not paraphrased. This lab encodes conservative defaults, not legal advice.

```
inputs.py: gaia_dr3_astrometry (CC-BY-NC-3.0-IGO), TESS/MAST (public, acknowledge), own photometry (CC-BY-4.0)
build(): catalogue.vot, CITATION.cff, ACKNOWLEDGEMENTS.md, metadata.json, LICENSE.txt, MANIFEST.json
release_licence(inputs) --> keep every NC/SA ; NC+SA --> ValueError("needs human review")
check(folder): manifest hashes, CFF keys, SPDX id, restrictions, verbatim credit, VOTable structure --> problems
```

The one thing to remember: a release gate must check content and terms, not the presence of files.

## Walkthrough: what actually happens when you run it
### Step 1 — the shipped release
**You run** `python release.py`

**What happens inside** `build()` writes six files into release/; `check()` re-reads them and lists every problem a reviewer would raise.

**What you see**
```
release licence: CC-BY-4.0
 "problems": [
  "licence: release CC-BY-4.0 drops the NC condition of input gaia_dr3_astrometry (LicenseRef-CC-BY-NC-3.0-IGO)"
```

**What it means / what would look wrong** All six files are present and well formed; the one problem is legal, not technical.

### Failure lab 1/4 — inject and symptom
**You run** the shipped `release_licence()`, which always answers CC-BY-4.0.

**What happens inside** The input families are never read.

**What you see**
```
release licence: CC-BY-4.0
```

**What it means / what would look wrong** A "files present" review passes this release. Published, it would invite commercial reuse that ESA's licence forbids.

### Failure lab 2/4 — diagnose
**You run** `BUILD_TARGET=mine python -m unittest test_build_task test_fitness`

**What happens inside** Tests feed an NC input, an NC + SA conflict, and the real release through the gate.

**What you see**
```
AssertionError: ValueError not raised
AssertionError: 'CC-BY-4.0' != 'CC-BY-NC-4.0'
FAILED (failures=3)
```

**What it means / what would look wrong** Two separate faults: NC is dropped, and a conflict is silently resolved instead of escalated.

### Failure lab 3/4 — fix
**You run** `python solution/release.py`

**What happens inside** `release_licence()` keeps every restriction found in the input families and raises `ValueError` for NC + SA.

**What you see**
```
release licence: CC-BY-NC-4.0
 "problems": []
```

**What it means / what would look wrong** Stricter than our own CC-BY-4.0 parts, as it must be. CC-BY-NC-SA-4.0 for an NC + SA mix would be wrong: a BY-SA adaptation must stay BY-SA, which allows commercial use.

### Failure lab 4/4 — proof
**You run** `python -m unittest test_build_task test_fitness -v`, then `python try_it.py`.

**What happens inside** The gate passes the fixed release; try_it adds a CC BY-SA input, then removes Gaia.

**What you see**
```
Ran 5 tests in 0.214s
OK
1. + BY-SA input -> ValueError: NonCommercial and ShareAlike inputs conflict: needs human review
2. without Gaia -> CC-BY-4.0 | problems: []
```

**What it means / what would look wrong** The licence follows the inputs both ways: without Gaia, CC-BY-4.0 is correct.

### The decision
**You run** `python defects.py` and read decisions/0001-release-gate.md.

**What happens inside** Six realistic defects are injected into a good release; for five of them the "maintainer" re-hashes the manifest, so hashes alone cannot catch them. Option A is a files-present review; B is `check()`.

**What you see**
```
{"defect": "Gaia credit paraphrased", "A_files_present": false, "B_check": true, "B_says": ["credit: verbatim acknowledgement for gaia_dr3_astrometry missing"]}
{"defect": "row with a missing TD", "A_files_present": false, "B_check": true, "B_says": ["votable: row 3 has 5 TD for 6 FIELD"]}
caught: A 0/6, B 6/6
```

**What it means / what would look wrong** Each B message names the file and the rule. The ADR chose B as a blocking CI gate, with option C — external validators (astropy.io.votable, cffconvert, STILTS votlint) and a DOI deposit — as a second opinion. Expected (not run here): validate_external.py runs those validators in CI; they were not measured. A person approves any release whose inputs carry non-open terms. My numbers match the ADR. The fitness function `test_fitness.py` requires `check() == []` for the published release and every seeded defect caught.

## Common confusions
- **Q:** "The data are free to download, so they are free to relicense." — **A:** Gaia is CC BY-NC 3.0 IGO; the release must keep NC.
- **Q:** "A correct manifest proves the release is fine." — **A:** five defects were re-hashed; only content checks caught them.
- **Q:** "Paraphrasing the credit is friendlier." — **A:** providers ask for verbatim text; check() rejects a paraphrase.
