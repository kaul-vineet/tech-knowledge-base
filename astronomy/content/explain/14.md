# Plate solving (astrometry-lite): match star triangles, fit a WCS, check residuals — explained

## The intuition
Plate solving finds the WCS — pointing, scale, rotation — mapping detected pixel positions onto catalogue positions. Shapes survive scale and rotation: a triangle's side ratios are the same in pixels and on the sky, so detection triangles are matched to catalogue triangles by these invariants, and matches vote for star pairs.

Votes can be wrong, so RANSAC tries every three voted pairs as an affine map and keeps the one most pairs agree with; a least-squares refit and its residuals follow.

The catch: the catalogue must be projected onto a plane the way a camera does it (TAN). Raw (ΔRA, ΔDec) offsets stretch RA by 1/cos Dec, and far from the equator the triangles no longer match.

**Analogy:** recognising a constellation in a rotated, zoomed photo by its shape rather than its position.
Where the analogy breaks: the sky is curved; shapes are preserved only after the correct projection.

```
detections (x, y) --12 brightest--> triangles --> invariants (L2/L1, L1/L0)
catalogue near hint --to_plane()--> (xi, eta) --40 brightest--> triangles
invariants within TOL 0.8 % --> votes --consensus() RANSAC--> inlier pairs
fit_affine() x5 refine --> CD, CRVAL --from_plane()--> WCS ; residuals
```

The one thing to remember: match invariants only after projecting the catalogue the way the camera does.

## Walkthrough: what actually happens when you run it
### Step 1 — the shipped solver
**You run** `python platesolve.py`

**What happens inside** `run()` calls `solve()` from an offset hint, then again at the first solution; `check()` compares with the truth.

**What you see**
```
{"field": "orion", "solved": true, "n_matched": 32, "rms_arcsec": 0.373, "pointing_error_arcsec": 0.07, "scale_arcsec_px": 2.0045, "rotation_deg": 11.991}
{"field": "cassiopeia", "solved": false}
```

**What it means / what would look wrong** Orion solves, slightly wrong in scale (2.0045 instead of 2.0). Cassiopeia does not solve at all.

### Failure lab 1/4 — inject and symptom
**You run** the shipped file: `to_plane()` returns `ra - ra0, dec - dec0`.

**What happens inside** At Dec −5.4, cos Dec ≈ 0.996, so flat offsets are nearly right; at Dec +62.1, a degree of RA spans only 0.47 degree on the sky.

**What you see**
```
{"field": "cassiopeia", "solved": false}
```

**What it means / what would look wrong** Silent failure: no exception, just no solution — and a 0.2 % scale error at Orion nobody would notice.

### Failure lab 2/4 — diagnose
**You run** `python try_it.py`

**What happens inside** One sky triangle per field: invariants with flat offsets vs TAN.

**What you see**
```
1. orion      Dec -5.4: invariants flat [1.049 1.083] vs TAN [1.051 1.078] (max relative difference 0.004; match tolerance 0.008)
1. cassiopeia Dec +62.1: invariants flat [1.049 1.083] vs TAN [1.097 1.685] (max relative difference 0.357; match tolerance 0.008)
```

**What it means / what would look wrong** 0.4 % is inside the 0.8 % tolerance; 36 % is not. The geometry, not the voting, is broken.

### Failure lab 3/4 — fix
**You run** `python solution/platesolve.py`

**What happens inside** `to_plane()`/`from_plane()` call `fields.tan_project` / `tan_deproject`.

**What you see**
```
{"field": "orion", "solved": true, "n_matched": 32, "rms_arcsec": 0.359, "pointing_error_arcsec": 0.07, "scale_arcsec_px": 2.0001, "rotation_deg": 11.99}
{"field": "cassiopeia", "solved": true, "n_matched": 23, "rms_arcsec": 0.503, "pointing_error_arcsec": 0.05, "scale_arcsec_px": 2.0002, "rotation_deg": -32.999}
```

**What it means / what would look wrong** Both fields solve with sub-arcsecond residuals; Orion's scale is now 2.0001.

### Failure lab 4/4 — proof
**You run** `BUILD_TARGET=mine python -m unittest test_build_task`, then without `BUILD_TARGET`.

**What happens inside** The tests require both fields to solve and the scale to be 2.0 ± 0.001 arcsec/px.

**What you see**
```
AssertionError: 2.0045 != 2.0 within 0.001 delta (0.0045000000000001705 difference)
FAILED (failures=3)
Ran 2 tests in 14.710s
OK
```

**What it means / what would look wrong** The scale test also catches Orion's subtle error.

### Step 2 — a bad hint
**You run** `python solution/search.py`

**What happens inside** If the hint is 0.8° off, the catalogue window misses the field; the search retries hints on rings 0.4° apart.

**What you see**
```
plain solve, hint 0.8 deg off: {"field": "orion", "solved": false}
search (5 hints tried): {"field": "orion", "solved": true, "n_matched": 32, "rms_arcsec": 0.359, "pointing_error_arcsec": 0.07, "scale_arcsec_px": 2.0001, "rotation_deg": 11.99}
```

**What it means / what would look wrong** Blind solvers (astrometry.net) generalise this with sky-wide quad indexes.

## Common confusions
- **Q:** "A looser tolerance would rescue Cassiopeia." — **A:** try_it 2: TOL 0.05 gives 12 votes but only 3 agree with the geometry.
- **Q:** "Orion solved, so the projection is fine." — **A:** its scale 2.0045 is 0.2 % off.
- **Q:** "RANSAC makes the votes unnecessary." — **A:** RANSAC tests every trio of voted pairs; votes keep that set small.
