# Light curves and periods: Lomb-Scargle, transits vs variable stars — explained

## The intuition
A light curve is brightness over time, sampled on clear nights. Lomb-Scargle tries many frequencies, fits a sine at each (uneven sampling is fine), and the highest peak is the best frequency.

Two traps: night-only sampling creates aliases (a signal at f also fits at f ± 1 cycle/day), and a transit — a short flat dip every few days — is not sine-shaped, so Lomb-Scargle can miss it.

**Analogy:** a strobe on a spinning wheel makes it seem to turn at another speed.
Where the analogy breaks: clouds make the sampling irregular, which weakens aliases but never removes the 1-day one.

```
sample_times() --> t ; variable_star(t), transit_star(t) --> y
frequency_grid(oversample=10) --> f --lomb_scargle(t, y, f)--> power
argmax --> best ; next distinct peak ; skewness(y)
bootstrap_fap(): shuffle y, max power x n --> false-alarm probability
```

The one thing to remember: a periodogram peak is a hypothesis to check for aliases and for the right signal shape.

## Walkthrough: what actually happens when you run it
### Step 1 — sampling and the variable
**You run** `python periods.py`

**What happens inside** `sample_times(seed=10)` keeps nights whose draw exceeds 0.3, 48 stamps 10 minutes apart. `analyse()` grids frequencies at 1/(10 × baseline), computes normalised power and finds the next peak more than 5 % away.

**What you see**
```
1104 points over 29.3 d (23 clear nights)
variable true P 0.5671 d | LS best 0.5669 d (power 0.770) | next peak 1.3074 d | skew +0.01
1-day alias of the variable: 1 / (1/0.5671 - 1) = 1.3100 d
```

**What it means / what would look wrong** The runner-up is the 1-day alias. A coarse grid (oversample 1) would shift the best peak.

### Step 2 — the transit star
**You run** the same command (line 3).

**What happens inside** The same `analyse()` on `transit_star()`: a 1 % box dip lasting 0.1 d.

**What you see**
```
transit  true P 3.2127 d | LS best 0.3211 d (power 0.032) | next peak 1.5998 d | skew +0.82
```

**What it means / what would look wrong** Near-noise power, wrong period. The +0.82 skew hints at transits; the capstone uses box least squares.

### Step 3 — the build task: bootstrap FAP
**You run** `BUILD_TARGET=mine python -m unittest test_build_task -v` (shipped raises), then `python solution/periods.py`.

**What happens inside** Shuffling magnitudes keeps noise and sampling but destroys periodicity; 100 shuffles give a null distribution of maximum power; FAP = (hits + 1)/(n + 1).

**What you see**
```
variable   bootstrap FAP (100 shuffles) = 0.010
transit    bootstrap FAP (100 shuffles) = 0.010
pure noise bootstrap FAP (100 shuffles) = 0.386
```

**What it means / what would look wrong** 0.010 = 1/101 is the floor for 100 shuffles. The transit also scores 0.010: "something periodic" is not "the right period".

### Step 4 — agent assist
**You run** `python agent_assist.py --fake`

**What happens inside** Code tests whether the agent's and code's frequencies differ by one cycle/day, then checks every quoted number.

**What you see**
```
2. code decided: class='pulsating variable' (agent agrees), period=0.5669 d -> agent period overruled: 1-day alias of the code's period
4. code checked 3 quoted numbers: 2 match; UNVERIFIED (treat as the model's guess): 0.001
```

**What it means / what would look wrong** The model picked the alias and invented "0.001%". `Ran 13 tests ... OK (skipped=1)`.

## Common confusions
- **Q:** "The highest peak is the period." — **A:** check aliases: 0.5669 d and 1.3074 d are one signal.
- **Q:** "Low FAP means the period is right." — **A:** the transit gets 0.010 with 0.3211 d instead of 3.2127 d.
- **Q:** "A finer grid only costs time." — **A:** too coarse a grid misses narrow peaks.
