# Model comparison: a galaxy rotation curve with and without a dark-matter halo — explained

## The intuition
A rotation curve is orbital speed versus radius. A stellar disk alone predicts a curve that peaks and falls; real curves stay flat. A dark-matter halo fixes the fit — but so would any flexible curve. The question is which model the data justify.

χ² always rewards flexibility. BIC = χ² + k ln n charges every parameter ln 40 ≈ 3.7 here. A runs test then asks whether the winner left structure in its residuals (long same-sign stretches).

**Analogy:** a degree-10 polynomial beats a line on training error and generalises worse.
Where the analogy breaks: these parameters are physical; an absurd halo density is wrong even if it predicts well.

```
40 radii, V(R) +/- 2-6 km/s (synthetic, NGC 3198-like)
models: disk (k=1) | disk+cored halo (3) | disk+NFW (3) | disk+halo+wiggles (6)
fit() each (LM) --> chi2, BIC = chi2 + k ln n, AIC, runs_z(residuals)
select(): min chi2 (shipped) | min BIC (fix) --> published model ; |runs Z| < 1.96 ?
```

The one thing to remember: a better fit is not a better model; make every parameter pay for itself, then check the residuals.

## Walkthrough: what actually happens when you run it
### Step 1 — four fits on one curve
**You run** `python compare.py`

**What happens inside** `galaxy.py` builds a Freeman disk (Bessel functions), a cored halo, an NFW halo and a cubic "wiggle" term; `fit()` runs Levenberg–Marquardt for each.

**What you see**
```
{"model": "disk only", "k": 1, "chi2": 3267.95, "bic": 3271.64, "aic": 3269.95, "runs_z": -6.05, "params": [2.118]}
{"model": "disk + cored halo", "k": 3, "chi2": 43.24, "bic": 54.3, "aic": 49.24, "runs_z": -1.27, "params": [1.087, 2.109, 4.57]}
{"model": "disk + halo + wiggles", "k": 6, "chi2": 40.63, "bic": 62.76, "aic": 52.63, "runs_z": 0.64, "params": [0.421, 16.35, 1.715, -6.637, 5.243, -2.308]}
select() picks: disk + halo + wiggles
```

**What it means / what would look wrong** The disk alone is hopeless (χ² 3268, runs Z −6.05). The wiggles win by only 2.6 in χ² — with three extra parameters.

### Failure lab 1/4 — inject and symptom
**You run** the shipped `select()`: `min(rows, key=lambda row: row["chi2"])`.

**What happens inside** The most flexible model always reaches the lowest χ², so it is always published.

**What you see**
```
{"option": "A chi2", "picks_over_50_datasets": {"disk + halo + wiggles": 50}}
```

**What it means / what would look wrong** Wiggles win 50 of 50 galaxies, with a halo of ρ₀ 16.35 × 10⁷ M☉/kpc³ and a 1.7 kpc core — unphysical, but χ² cannot know.

### Failure lab 2/4 — diagnose
**You run** `BUILD_TARGET=mine python -m unittest test_build_task test_fitness`

**What happens inside** Tests require a 3-parameter halo model on the published curve and on ten more seeded galaxies.

**What you see**
```
AssertionError: 'disk + halo + wiggles' != 'disk + cored halo'
AssertionError: 0.0 not greater than or equal to 0.95
FAILED (failures=12)
```

**What it means / what would look wrong** A rule that fails on every galaxy is a rule problem, not a data problem.

### Failure lab 3/4 — fix
**You run** `python solution/compare.py`

**What happens inside** `select()` takes the minimum BIC instead.

**What you see**
```
select() picks: disk + cored halo
{"option": "B BIC", "picks_over_50_datasets": {"disk + cored halo": 50}}
```

**What it means / what would look wrong** BIC 54.3 beats the wiggles' 62.76: three extra parameters cost 3 × 3.7 = 11.1 but bought only 2.6.

### Failure lab 4/4 — proof
**You run** `python -m unittest test_build_task test_fitness -v`

**What happens inside** Same tests on the solution; `TestFailureLab` in test_compare.py keeps the fault reproducible.

**What you see**
```
Ran 4 tests in 22.418s
OK
```

**What it means / what would look wrong** The fix holds on all seeded galaxies, not just the published one.

### The decision
**You run** `python try_it.py` and read decisions/0001-model-selection.md.

**What happens inside** The brief: pick a physical, minimal model; do not reward flexibility; be reproducible from the data; flag structured residuals.

**What you see**
```
1. NFW truth -> BIC picks disk + NFW halo {'disk only': 4281.27, 'disk + cored halo': 74.95, 'disk + NFW halo': 47.84, 'disk + halo + wiggles': 64.97}
2. R <= 8 kpc -> disk + cored halo {'disk only': (92.21, 1.504), 'disk + cored halo': (12.5, 1.19)} (bic, mass-to-light)
```

**What it means / what would look wrong** BIC is not biased towards the cored halo: with NFW truth it switches (47.84 vs 74.95). With only the optical curve a halo still wins, but the disk mass-to-light ratio moves from 1.087 to 1.19 — the disk–halo degeneracy. Hold-out option C (43 cored, 5 NFW, 2 wiggles) depends on where the cut falls. The ADR chose B, BIC with AIC beside it, plus the runs test: the cored halo passes (Z −1.27), the disk alone fails (Z −6.05). My numbers match the ADR exactly. The fitness function `test_fitness.py` requires a halo model in ≥ 95 % of 50 galaxies, never the wiggles, |Z| < 1.96 for the published fit and the disk alone rejected.

## Common confusions
- **Q:** "Lowest χ² is the most accurate model." — **A:** 40.63 vs 43.24 bought three unphysical parameters.
- **Q:** "BIC and the runs test do the same job." — **A:** BIC ranks models; the runs test audits the winner.
- **Q:** "The data are NGC 3198." — **A:** synthetic, NGC 3198-shaped; the SPARC file has no stated licence, so it is not vendored.
