# Error mitigation: readout correction and zero-noise extrapolation — explained

## The intuition

Error *mitigation* does not fix the quantum computer. It runs extra experiments, learns how the noise distorts results, and then undoes that distortion in classical post-processing. You pay in shots and in variance; you gain a less biased estimate.

**Readout correction** is the simplest case. Prepare each basis state (`00, 01, 10, 11`), measure it many times, and write down how often each is misread. That table is the calibration matrix `M`: observed = `M` · true. Solve the linear system and you get an estimate of the true distribution. The catch: `M` is itself estimated from finite shots, so the solution can contain small *negative* "probabilities".

**Zero-noise extrapolation (ZNE)** handles gate noise. You cannot turn noise down, but you can turn it *up* on purpose: replace each CX by CX·CX·CX (logically the same, three times the noise). Measure at noise scales 1, 3, 5, fit a curve, and read off its value at scale 0.

**Analogy:** calibrating a bathroom scale with known weights, then correcting your reading.
Where the analogy breaks: the "correction" can produce impossible readings (negative probabilities), and the extrapolated value has more variance than any single measurement.

```text
readout:  calibrate(): prep |j>, measure -> column j of M
          p_noisy --solve(M, .)--> quasi-probs (may be < 0) --> constrained fit -> valid p
ZNE:      fold CX x1, x3, x5 -> P000 = 0.9039, 0.7474, 0.6234
          fit line / Richardson polynomial -> value at scale 0 (~1.0 ideal)
```

The one thing to remember: mitigation trades variance and shots for less bias, and its raw output may not be a valid probability distribution.

## Walkthrough: what actually happens when you run it

1. **You run** `python mitigation_lab.py`.
   **What happens inside:** with `rng(11)`, `calibrate(4000)` builds `M` column by column; `measure()` samples a Bell pair through `p01 = 0.03`, `p10 = 0.06`; `mitigate()` calls `np.linalg.solve`; `tvd()` measures distance to the true `[0.5, 0, 0, 0.5]`. Then the mirror circuit (GHZ-3 then its inverse, ideal `P(000) = 1`) is run with every CX folded 1×, 3×, 5×.
   **What you see:**
   ```text
   {"cal_shots": 4000, "shots": 4000, "raw": [0.4768, 0.0422, 0.0398, 0.4412], "mitigated": [0.5038, 0.0003, -0.0105, 0.5064], "min": -0.0105, "tvd_raw": 0.082, "tvd_mitigated": 0.0105}
     downstream sampling failed: Probabilities are not non-negative
   …
   {"scale": 1, "cx_count": 4, "P000": 0.9039}
   {"scale": 3, "cx_count": 12, "P000": 0.7474}
   {"scale": 5, "cx_count": 20, "P000": 0.6234}
   ideal 1.0 | raw 0.9039 | linear ZNE 0.9687 | Richardson ZNE 0.9944
   ```
   **What it means:** readout correction cut the distance from 0.082 to 0.0105, but even with 4000 shots one entry is −0.0105 and `rng.choice` refuses it. ZNE: a line through three points recovers 0.9687; the exact quadratic through them (Richardson) gets 0.9944. The curve is not linear, so the line under-corrects.

2. **You run** `python try_it.py`.
   **What you see:**
   ```text
   zne_shot_noise       {'raw_mean': 0.9041, 'raw_std': 0.0069, 'richardson_mean': 0.9942, 'richardson_std': 0.017}

   ```
   **What it means:** over 200 seeds at 2000 shots, Richardson is far closer on average but its spread is about 2.5× wider: extrapolation amplifies shot noise. Clipping negatives is nearly as good as a proper constrained fit here, but not the closest valid distribution.

## Failure lab: mitigation that outputs impossible probabilities

1. **Inject:** the second budget in `mitigation_lab.py`: 100 calibration shots per basis state, 200 run shots.
2. **Symptom:**
   ```text
   {"cal_shots": 100, "shots": 200, "raw": [0.46, 0.04, 0.04, 0.46], "mitigated": [0.5072, -0.0241, -0.0126, 0.5294], "min": -0.0241, "tvd_raw": 0.08, "tvd_mitigated": 0.0367}
     downstream sampling failed: Probabilities are not non-negative
   ```
3. **Diagnose:** the true `P(01)` is 0. A noisy `M⁻¹` pushes the estimate either side of 0; with few shots the swing is −0.0241. Any consumer that samples, takes logs or computes entropy breaks.
4. **Fix:** `solution_constrained.py` solves `min ‖M·p − p_noisy‖²` with `p ≥ 0`, `Σp = 1` (projected gradient on the simplex), and the lesson recommends at least 4000 shots for calibration and runs.
5. **Proof:**
   ```text
   $ BUILD_TASK_MODULE=mitigation_lab python -m unittest test_build_task
   FAIL: test_always_a_probability_distribution (…)
   AssertionError: np.float64(-0.008180304680361005) not greater than or equal to 0.0 : (100, 200)
   FAILED (failures=1)
   $ python -m unittest test_build_task
   Ran 3 tests in 3.718s
   OK
   ```
   The tests also require it to be no worse than the plain inverse on average.

## Common confusions

- **Q:** Mitigation makes results exact. — **A:** Richardson's std 0.017 vs raw 0.0069: less bias, more variance.
- **Q:** 4000 shots make the inverse safe. — **A:** The 4000-shot line still has `min` −0.0105.
- **Q:** Folding changes the circuit's logic. — **A:** CX·CX·CX = CX; only the noise triples (`cx_count` 4 → 12).
