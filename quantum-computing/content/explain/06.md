# Same circuit, two frameworks — explained

## The intuition

Qiskit and Cirq can run the identical physics and still print different strings. The difference is bookkeeping: Qiskit writes qubit 0 as the rightmost character (little-endian); Cirq writes the first measured qubit as the leftmost (big-endian). Flip one convention and the results agree.

So "compare two frameworks" really means: pick one convention, convert everything into it, then compare distributions. Counts will still differ shot by shot, because each framework has its own random generator even with the same seed.

**Analogy:** byte order between two CPUs: the same integer, stored in opposite directions.
Where the analogy breaks: in Cirq the order is not fixed by the machine; it is whatever order you list qubits in `cirq.measure(...)`.

```text
          X on q0
 Qiskit:  meas -> '01'  (q1 q0)              ---------------> '01'
 Cirq:    measure(q0, q1) -> int 2 -> '10'  -- to_qiskit_order (reverse) --> '01'
 compare in ONE convention (Qiskit's), as distributions, within 5 sigma
```

The one thing to remember: normalise bit order explicitly before comparing results across tools.

## Walkthrough: what actually happens when you run it

1. **You run** `python crosscheck_numpy.py`.
   **What happens inside:** numpy computes each state once, then prints the bitstrings in both conventions.
   **What you see:**
   ```text
   bell     qiskit-order {'00': 0.5, '11': 0.5}  cirq-order {'00': 0.5, '11': 0.5}
   x_on_q0  qiskit-order {'01': 1.0}  cirq-order {'10': 1.0}
   ```
   **What it means:** the Bell pair hides the problem (symmetric strings); `x_on_q0` exposes it.

2. **You run** `python two_frameworks_lab.py`.
   **What you see** here: `ModuleNotFoundError: No module named 'cirq'`.
   Expected (not run here): for `x_on_q0`, Qiskit `{'01': 1000}`, Cirq raw `{'10': 1000}`, Cirq normalised `{'01': 1000}`; for `bell`, all three rows only `'00'`/`'11'`, near half each.
   **What it means:** raw rows look different but describe the same physical result.

3. **You run** `python try_it.py`.
   **What happens inside:** try 1 extends to three qubits; try 2 changes `cirq.measure(q0, q1)` to `measure(q1, q0)`.
   **What you see:**
   ```text
   try 1 numpy {'qiskit': '001', 'cirq_raw': '100', 'cirq_in_qiskit_order': '001'}
   try 2 numpy {'qiskit': '01', 'cirq_raw': '01', 'cirq_in_qiskit_order': '10'}
   ```
   **What it means:** in try 2 the raw strings now match by accident, and the "normaliser" breaks them. Measurement order sets bit order; the normaliser must know it.

4. **You run** `python -m unittest` → `Ran 9 tests` … `OK (skipped=4)`.

## Common confusions

- **Q:** Matching raw strings means agreement. — **A:** Try 2: raw `'01'` = `'01'`, yet normalised they disagree.
- **Q:** Same seed, same counts across frameworks. — **A:** Separate RNGs; compare within tolerance.
- **Q:** Bell tests prove the conversion is right. — **A:** `'00'`/`'11'` read the same both ways; use an asymmetric circuit.
