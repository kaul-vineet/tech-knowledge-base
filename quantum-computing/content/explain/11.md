# Transpiling to a device layout — explained

## The intuition

A circuit as you write it is an idealised program: any gate, between any two qubits. A real chip supports a handful of native gates (here `rz`, `sx`, `x`, `cx`) and lets two-qubit gates act only between physically wired neighbours (the *coupling map*). The transpiler is the compiler that bridges the two.

It runs in stages. **Layout** picks which physical qubit holds each logical qubit. **Routing** inserts SWAPs (three CX each) when two qubits that must interact are not neighbours. **Basis translation** rewrites every gate into native ones (an `H` becomes `rz·sx·rz`). **Optimisation** cancels and merges what it can; higher levels try harder.

The cost that matters is two-qubit gates: on hardware they are much noisier than single-qubit ones. A 5-qubit GHZ written as a "star" (qubit 0 talks to everyone) is free on an all-to-all device and expensive on a line.

**Analogy:** compiling for a CPU without some instructions, and with data that must be moved between registers before every operation.
Where the analogy breaks: every extra "move" (SWAP) adds noise that changes the answer, not just runtime.

```text
logical: q0 -CX-> q1,q2,q3,q4   (star)
line map: 0-1-2-3-4    pairs (0,2),(0,3),(0,4) not adjacent -> SWAPs
transpile: layout -> routing -> basis(rz,sx,x,cx) -> optimisation(level 0..3)
check: depth, 2q count, 2q depth; outcomes still only 00000/11111
```

The one thing to remember: the transpiled two-qubit count, not the source circuit, predicts how noisy the result will be.

## Walkthrough: what actually happens when you run it

1. **You run** `python crosscheck_numpy.py`.
   **What happens inside:** numpy multiplies basis-gate matrices to confirm the rewrites, then checks each star CX pair against edge lists for three maps, builds a heavy-hex graph, and simulates the GHZ state.
   **What you see:**
   ```text
   {'H == RZ.SX.RZ (global phase)': True, 'X == SX.SX': True, 'SWAP == 3 CX': True}
   star CX pairs not on the ring map: [(0, 2), (0, 3)]
   star CX pairs not on the line map: [(0, 2), (0, 3), (0, 4)]
   heavy-hex distance 3 has 19 qubits
   star GHZ probabilities: {'00000': 0.5, '11111': 0.5}
   ```
   **What it means:** three of four CX gates need routing on a line, and each SWAP costs three CX.

2. **You run** `python transpile_lab.py`.
   **What happens inside:** `GenericBackendV2` builds offline fake devices; `generate_preset_pass_manager(level, backend, seed_transpiler=7)` runs the pipeline for levels 0–3; `stats()` reports depth, 2q count and 2q depth; `same_outcomes()` re-runs the circuit.
   Expected (not run here): `before:` with 4 two-qubit gates; basis `['cx', 'delay', 'id', 'measure', 'reset', 'rz', 'sx', 'x']`; all-to-all keeps 4 CX; line at level 0 has more than 4; higher levels usually fewer; `GHZ outcomes only: True` everywhere.
   **What would look wrong:** a CX between unconnected qubits (layout bug) or any outcome other than all-0/all-1.

3. **You run** `python try_it.py`.
   **What you see:**
   ```text
   ring_vs_line  local {'all-to-all': 0, 'ring': 2, 'line': 3}
   h_in_basis    local {'gates': ['rz', 'sx', 'rz'], 'equals_H_up_to_phase': True, 'global_phase_turns': -0.125}
   ```
   **What it means:** closing the line into a ring makes (0, 4) adjacent, saving one routed pair. The `H` rewrite differs by a global phase, which no measurement sees.

4. **You run** `python solution_chain.py` (build task: rewrite the GHZ to fit the map).
   **What you see:**
   ```text
   chain vs star (numpy): {'same_state_as_star': True, 'non_adjacent_on_line': []}
   ```
   **What it means:** a chain `cx(0,1), cx(1,2), …` makes the same state using only neighbours. Changing the algorithm to fit the hardware beats asking the router to fix it.

## Common confusions

- **Q:** Higher optimisation level is always better. — **A:** Usually fewer 2q gates, but it costs compile time and can vary with the seed; measure it.
- **Q:** Depth is the number to minimise. — **A:** Two-qubit count and two-qubit depth predict noise better.
- **Q:** Basis translation changes results. — **A:** `equals_H_up_to_phase: True`; only routing and noise do.
