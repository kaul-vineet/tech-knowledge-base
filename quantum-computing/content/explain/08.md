# Small Grover search — explained

## The intuition

Grover searches `N = 2^n` candidates for the ones a predicate marks. From an equal superposition it repeats two steps: the **oracle** multiplies marked amplitudes by −1, and **diffusion** reflects every amplitude about the average, turning that hidden dip into a bump. Each repetition rotates the state a fixed angle toward the marked items.

Because it is a rotation, more is not better. There is an optimal count `k ≈ (π/4)·√(N/M)`; past it the state rotates away again. And when half or more of the space is marked there is nothing to amplify.

**Analogy:** tuning a radio dial: each click moves you toward the station, and clicking past it loses the signal.
Where the analogy breaks: you cannot listen while turning: measuring mid-way collapses the state, so you must compute `k` in advance.

```text
H^n --> [ oracle: flip sign of marked | diffusion: reflect about mean ] x k --> measure
         amplitude of '101' over k:  0.125  0.7812  0.9453  0.3301  0.0122   (probabilities)
                                      k=0    k=1     k=2     k=3     k=4
```

The one thing to remember: Grover is a rotation by a fixed angle, so the iteration count must be computed, not maximised.

## Walkthrough: what actually happens when you run it

1. **You run** `python crosscheck_numpy.py`.
   **What happens inside:** numpy builds the oracle as a diagonal of ±1, the diffusion as `2|s⟩⟨s| − I`, applies them `k` times, and compares with the closed form `sin²((2k+1)θ)`, `θ = asin(√(M/N))`.
   **What you see:**
   ```text
   marked ['101']: oracle diagonal [1, 1, 1, 1, 1, -1, 1, 1]
     optimal k=2  P by k {0: 0.125, 1: 0.7812, 2: 0.9453, 3: 0.3301, 4: 0.0122}  matches sin^2 formula: True
   marked ['011', '100']: oracle diagonal [1, 1, 1, -1, -1, 1, 1, 1]
     optimal k=1  P by k {0: 0.25, 1: 1.0, 2: 0.25, 3: 0.25, 4: 1.0}  matches sin^2 formula: True
   ```
   **What it means:** the −1 at index 5 is `'101'`. For one marked of 8 the peak is 0.9453 at k=2, not 1.0. Two marked of 8 is the lucky case: `θ = 30°`, so k=1 lands exactly on 1.0.

2. **You run** `python grover_lab.py`.
   **What happens inside:** `grover_oracle` wraps a multi-controlled Z in X gates on the `'0'` bits ("open controls"); `grover_operator(...).power(k)` repeats oracle plus diffusion.
   Expected (not run here): 2 qubits k=1 gives 1.0; 3 qubits k=2 gives 0.9453 and `'101'` tops the seeded counts.

3. **You run** `python try_it.py`.
   **What you see:**
   ```text
   overshoot      numpy {'k': 3, 'P': 0.3301, 'optimal_k': 2, 'P_at_optimal': 0.9453}
   two_marked_k2  numpy {'k': 2, 'P': 0.25, 'optimal_k': 1, 'P_at_optimal': 1.0}
   ```
   **What it means:** one extra iteration drops success to 0.3301. Adding a marked item changes the optimal `k`: a hard-coded `k` is a latent bug.

4. **You run** `python solution_search.py` (build task: search by predicate).
   **What you see:**
   ```text
   x == 5:      (['101'], 2, 0.9453)
   x % 3 == 0:  (['000', '011', '110'], 1, 0.8437)
   ```
   **What it means:** marked strings and `k` both derive from the predicate.

5. **You run** `python agent_assist.py --fake`.
   **What you see:**
   ```text
   single REJECT  marks ['110'] but spec needs ['011']
   pair   ACCEPT  oracle ok; k=2 gives P=0.25, code uses k=1: P=1.0
   even   REJECT  oracle ok, but best P(success)=0.5 at k=0: no amplification (M/N=2/4)
   ```
   **What it means:** code computes the draft's oracle diagonal, catching a bit-order slip; `k` comes from code, not the model.

## Common confusions

- **Q:** More iterations always help. — **A:** `overshoot`: k=3 gives 0.3301.
- **Q:** Grover finds the answer with certainty. — **A:** Usually not: 0.9453 at best for `'101'`; verify the result classically.
- **Q:** Marking more items is always easier. — **A:** `even`: with M/N = 2/4 the best is 0.5 at k=0, no gain.

## Check your understanding

1. Why does the oracle need `X` gates around the multi-controlled Z?
<details><summary>Answer</summary>MCZ flips only `|1…1⟩`; X on the `'0'` bits maps the target onto `|1…1⟩` and back.</details>

2. What is the optimal `k` for one marked item out of 4?
<details><summary>Answer</summary>1, with P = 1.0 (the `['11']` row).</details>

3. Why is the speed-up only quadratic?
<details><summary>Answer</summary>Each iteration rotates by about `2/√N`, so about `√N` iterations are needed (lesson 25 proves this is optimal).</details>
