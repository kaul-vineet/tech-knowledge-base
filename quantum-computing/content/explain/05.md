# Portable circuits with OpenQASM — explained

## The intuition

A `QuantumCircuit` lives inside one SDK. OpenQASM is plain text any tool can read: header, gates (`h q[0];`), measurements. It is a neutral artifact you can diff, review and hand to another toolchain.

Text equality is not the test: files can differ by one token and do something else. So the lab compares behaviour: the unitary (`Operator.equiv`) and the outcome probabilities from an independent parser.

**Analogy:** OpenAPI for circuits: a spec file both sides read.
Where the analogy breaks: each tool supports a different subset of the language, so "valid OpenQASM" does not mean "every tool accepts it".

```text
QuantumCircuit --qasm3.dumps--> bell.qasm (text) --qasm3.loads--> QuantumCircuit'
       |                              |                                |
   Operator  ===== equiv? =====  crosscheck parser (h, x, cx) ===  Operator'
                                      -> numpy probabilities
agent_assist: model drafts text -> same parser judges -> ACCEPT / REJECT
```

The one thing to remember: judge portable circuits by what they compute, never by what the text looks like.

## Walkthrough: what actually happens when you run it

1. **You run** `python crosscheck_qasm_numpy.py`.
   **What happens inside:** a tiny regex parser reads both reference files, applies `h`/`x`/`cx` as numpy matrices, squares amplitudes.
   **What you see:**
   ```text
   reference_bell_qasm3.qasm: {'00': 0.5, '11': 0.5}
   reference_bell_qasm2.qasm: {'00': 0.5, '11': 0.5}
   ```
   **What it means:** two syntaxes, one behaviour.

2. **You run** `python qasm_lab.py`.
   Expected (not run here): OpenQASM 3 text starting `OPENQASM 3.0;` with `include "stdgates.inc";`, then OpenQASM 2 text, both `same unitary: True`, and identical seeded counts before and after the round-trip.

3. **You run** `python try_it.py`.
   **What you see:**
   ```text
   swap_control parser {'00': 0.5, '01': 0.5}
   add_s_gate   parser ValueError: unsupported statement: 's q[0]'
   ```
   **What it means:** one swapped token (`cx q[1], q[0]`) silently destroys the Bell pair. And a valid standard gate (`s`) is outside this parser's subset: tools implement subsets.

4. **You run** `python agent_assist.py --fake`.
   **What happens inside:** a fake local-model server returns drafts; `check()` extracts the program, runs `cc.probabilities`, compares with the spec in `TASKS`.
   **What you see:**
   ```text
   bell   ACCEPT  matches spec  counts(1000, seed 7) {'00': 502, '11': 498}
   ghz3   REJECT  outcomes {'000': 0.5, '011': 0.5} != spec {'000': 0.5, '111': 0.5}
   phase  REJECT  parser: unsupported statement: 'rz(pi/2) q[0]'
   ```
   **What it means:** the model proposes, code decides. "Cannot verify" is treated as reject.

5. **You run** `python -m unittest` → `Ran 18 tests` … `OK (skipped=7)`.

## Common confusions

- **Q:** Same text means same circuit. — **A:** `swap_control` differs by one token; compare probabilities.
- **Q:** If Qiskit accepts it, every tool will. — **A:** `add_s_gate` shows a subset parser rejecting a standard gate.
- **Q:** The `phase` draft was wrong. — **A:** Unknown, and that is the point: unverifiable is rejected.
