# Parameterized circuits and sweeps — explained

## The intuition

Most useful quantum programs are a *template* with knobs: rotation angles an outer loop tunes. Qiskit models a knob as a `Parameter`; the circuit is built once with the symbol, and each run binds numbers.

Sweeping a knob checks the template. For `RY(θ)` on `|0⟩`, theory says `⟨Z⟩ = cos θ` and `⟨X⟩ = sin θ`. The lab fits `a·cos θ + b·sin θ + c` to the measured curve: the fit should return `[1, 0, 0]` for Z and `[0, 1, 0]` for X. Fitting a known shape also filters noise: 21 points pin down three numbers.

There are two ways to get an expectation value. The **Estimator** computes `⟨Z⟩` directly (exactly, on a statevector simulator). The **Sampler** gives counts, and you compute `⟨Z⟩ = (n0 − n1)/shots`, which carries shot noise.

**Analogy:** a prepared SQL statement executed with many argument sets.
Where the analogy breaks: each execution returns a random sample, never the exact value.

```text
template: |0> --RY(theta)--          (Parameter, unbound)
  bind 21 thetas in ONE pub: (qc, [[Z],[X]], thetas.reshape(-1,1))
      Estimator -> evs shape (2, 21), exact
      Sampler   -> 21 count dicts -> (n0-n1)/shots, noisy
  lstsq fit a*cos + b*sin + c  ->  [1, 0, 0] for Z
```

The one thing to remember: build the template once, bind many values in one call, and fit the known curve to average out shot noise.

## Walkthrough: what actually happens when you run it

1. **You run** `python crosscheck_numpy.py`.
   **What happens inside:** numpy computes exact `⟨Z⟩`/`⟨X⟩` for 21 angles, draws 400 binomial shots per angle (seed 7) and runs the same `fit_cos_sin`.
   **What you see:**
   ```text
   exact <Z> at theta = 0, pi/2, pi: [1.0, 0.0, -1.0]
   fit exact <Z> [a, b, c]: [1.0, 0.0, 0.0]
   fit exact <X> [a, b, c]: [0.0, 1.0, 0.0]
   fit sampled <Z>, 400 shots, numpy seed 7: [0.987, -0.004, -0.005]
   ```
   **What it means:** the sampled fit is 0.013 off at worst; the SE of a single 400-shot point is up to 0.05, so the fit beat any single point.

2. **You run** `python param_lab.py`.
   **What happens inside:** `assign_parameters` returns a bound copy; the template keeps its symbol. One PUB with observables shaped `(2, 1)` and 21 bindings gives `evs` shaped `(2, 21)`.
   Expected (not run here): `free parameters: [Parameter(theta)]`, `after binding pi/3: 0 free; 1 free in the template`, the same exact values as step 1, and a sampled fit within 0.05 of `[1, 0, 0]` (its own RNG).
   **What would look wrong:** a shape error from a missing `reshape(-1, 1)`.

3. **You run** `python try_it.py`.
   **What you see:**
   ```text
   rx_instead_of_ry numpy {'fit_Z': [1.0, 0.0, 0.0], 'fit_X': [0.0, 0.0, 0.0]}
   fewer_shots      numpy {25: {'fit': [0.969, 0.069, -0.044], 'worst_error': 0.069}, 400: {'fit': [0.987, -0.004, -0.005], 'worst_error': 0.013}}
   ```
   **What it means:** `RX` gives the same `⟨Z⟩` curve, so a Z-only test cannot tell RX from RY; the X fit of zero exposes it (RX rotates toward Y). Sixteen times fewer shots made the worst error about five times larger, roughly the `√16 = 4` that shot noise predicts.

4. **You run** `python solution_offset.py` (build task: add an offset parameter φ).
   **What you see:**
   ```text
   exact, phi = 0.3: 0.3
   400 shots, phi = 0.3: 0.311
   ```
   **What it means:** with `RY(θ + φ)`, the fitted curve shifts; recovering φ from the fit (`atan2`) works exactly and within 0.05 from samples.

## Common confusions

- **Q:** Binding modifies the template. — **A:** It returns a copy: "0 free; 1 free in the template".
- **Q:** One measurement observable is enough to test a rotation. — **A:** `rx_instead_of_ry` passes the Z check and fails the X check.
- **Q:** 0.987 instead of 1.0 means a bug. — **A:** It is shot noise at 400 shots; the exact fit is 1.0.
