# A hybrid variational loop (VQE) under shot noise — explained

## The intuition

VQE finds the lowest energy of a *Hamiltonian*, here a weighted sum of Pauli terms like `0.39·ZI + 0.18·XX`. The quantum side prepares a trial state from a few angles and estimates its energy; a classical optimiser changes the angles and asks again. That is the *hybrid loop*.

The energy is never read directly. Terms that only contain `Z` and `I` come from one histogram measured in the normal basis; the `XX` term needs a second histogram after `H` on both qubits. Each histogram costs shots, so every energy value has shot noise of roughly `1/√shots`.

That noise breaks a finite-difference gradient `(f(x+h) − f(x−h)) / 2h` with `h = 0.001`: the true difference is tiny, the shot noise is not, and dividing by `0.002` amplifies it. SPSA perturbs all parameters at once by a larger, shrinking step and tolerates noisy evaluations.

**Analogy:** tuning a thermostat by reading a jittery thermometer: comparing two readings 0.001° apart tells you nothing.
Where the analogy breaks: you pay per reading (shots), and noise can even make a reading look *better* than physically possible.

```text
laptop: optimiser(theta) --theta--> QPU/sim: ansatz RY,RY,CX,RY,RY
        ^                                measure Z basis  -> II, ZI, IZ, ZZ
        |                                measure X basis  -> XX
        +---- energy_est (noisy) <------ sum of terms
log: one JSON line per iteration (energy_est, grad_norm, evals) -> summarize() -> diagnose
```

The one thing to remember: in a hybrid loop, choose the optimiser for the noise you have, and grade the result against an exact reference, never against the noisy estimates.

## Walkthrough: what actually happens when you run it

1. **You run** `python vqe_lab.py`.
   **What happens inside:** `E0` comes from `eigvalsh(H)` (the referee, not the optimiser). `vqe(None)` runs exact gradient descent; `vqe(1000)` uses `energy(t, 1000, rng)`, which samples two multinomial histograms. Each run writes `logs/vqe_gd_<shots>.jsonl` and `summarize()` reads the tail.
   **What you see:**
   ```text
   exact ground energy E0 = -1.8405
   {"optimizer": "gd", "shots": null, "error": 0.0, … "tail_energy_std": 0.0001, "tail_grad_norm_median": 0.007}
   {"optimizer": "gd", "shots": 1000, "error": 1.5645, … "best_energy_est": -1.77348, "final_energy_est": -0.27276, "evals": 900, "tail_energy_std": 0.3912, "tail_grad_norm_median": 15.5125}
   ```
   **What it means:** same code, same start; the only change is shot noise. Near a minimum the true gradient shrinks (0.007), but under noise its median is 15.5: the signature of noise-dominated gradients.

2. **You run** `head -3 logs/vqe_gd_1000.jsonl`.
   **What you see:**
   ```text
   {"optimizer": "gd", "shots": 1000, "iter": 0, "energy_est": -1.03512, "grad_norm": 9.907, "evals": 9}
   {"optimizer": "gd", "shots": 1000, "iter": 1, "energy_est": -1.5862, "grad_norm": 26.537, "evals": 18}
   ```
   **What it means:** observability. Nine evaluations per step (2 per parameter + 1 logged); energy jumps instead of falling.

3. **You run** `python try_it.py`.
   **What you see:**
   ```text
   more_shots_same_optimizer {1000: {'error': 1.5645, …}, 100000: {'error': 0.9195, …}, 1000000: {'error': 0.0076, 'total_shots': 1800000000}}
   spsa_cost (for comparison) {'error': 0.0064, 'total_shots': 900000}
   below_the_ground_energy   {'E0': -1.8405, 'best_energy_est': -1.84964, 'rows_below_E0': 8, 'rows': 150}
   ```
   **What it means:** "just add shots" works at a million per group but costs 2000× SPSA's budget. And 8 noisy estimates fall *below* the true minimum: never report the best noisy value.

## Failure lab: the loop that never converges

1. **Inject:** 1000 shots per group into finite-difference descent (`h = 1e-3`, `lr = 0.4`), seed 0.
2. **Symptom:** error 1.5645 versus 0.0 exactly; log tail std 0.3912, gradient median 15.5125 (step 1).
3. **Diagnose:** a large gradient that does not shrink, with jittery energy, means the gradient is measuring noise. The agent-assist check encodes this as a code rule:
   ```text
   diagnose ACCEPT  code ran spsa @ 1000 shots: error 0.0064
   report   REJECT  best_energy -1.8405 is not in the log (log min -1.77348); diagnosis 'learning_rate_too_high' != code rule 'shot_noise'; …
   costly   REJECT  proposal needs 1,800,000,000 shots > budget 2,000,000 (not run)
   ```
4. **Fix:** `solution_spsa.py`: SPSA, 150 iterations, 3 evaluations each.
   ```text
   {"optimizer": "spsa", "shots": 1000, "error": 0.0064, … "evals": 450, …}
   errors over seeds 0-5: [0.0064, 0.0154, 0.0123, 0.0033, 0.0114, 0.0188]
   ```
5. **Proof:**
   ```text
   $ BUILD_TASK_MODULE=vqe_lab python -m unittest test_build_task
   AssertionError: 1.5645 not less than 0.03 : seed 0
   FAILED (failures=1)
   $ python -m unittest test_build_task
   Ran 2 tests in 3.229s
   OK
   ```

## Common confusions

- **Q:** The best logged energy is the answer. — **A:** `-1.84964` is below `E0 = -1.8405`; noise produced it.
- **Q:** A smaller `h` gives a more accurate gradient. — **A:** Under shots it divides the same noise by a smaller number.
- **Q:** SPSA is magic. — **A:** It still has seed-dependent error (0.0033 to 0.0188); the test sets a 0.03 bound across seeds.

## Check your understanding

1. Why does `XX` need a separate measurement?
<details><summary>Answer</summary>`X` does not commute with `Z`; you rotate with `H⊗H` and measure again.</details>

2. Which log field told you the problem was noise, not learning rate?
<details><summary>Answer</summary>`tail_grad_norm_median` stayed around 15 while energy jittered (std 0.39).</details>

3. How should the final energy be reported?
<details><summary>Answer</summary>Re-estimate at the final parameters with many shots (or exactly in a test), with an error bar.</details>
