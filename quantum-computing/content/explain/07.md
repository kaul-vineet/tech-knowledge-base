# Bernstein–Vazirani as a pattern — explained

## The intuition

Someone hides a bit-string `s` inside a black-box function `f(x) = s·x mod 2` (the parity of the bits of `x` that `s` selects). Classically you learn one bit of `s` per call: ask with `1000`, then `0100`, and so on, so `n` calls for `n` bits. Bernstein–Vazirani asks once.

Two tricks. The answer qubit (ancilla) starts in `|−⟩`; when the oracle "flips" it, a minus sign lands on the input branch instead (phase kickback). And the inputs are in a superposition of all `2^n` strings, so one query stamps the sign pattern `(−1)^(s·x)` on every branch. A final `H` layer turns that pattern back into `s` with certainty.

The value is the *pattern*, not the puzzle: "H everything → query once → H → measure" reappears in Deutsch–Jozsa, Simon and phase estimation.

**Analogy:** one batch request whose checksum decodes every field.
Where the analogy breaks: you cannot read individual replies; only interference makes one certain answer.

```text
q0..q(n-1): |0> --H--+--------+--H--> measure -> s
                     | oracle |
ancilla:    |0> -X-H-+ CX from each q_i with s_i = 1 +   (|−⟩: flips become signs)
                    ONE query
```

The one thing to remember: phase kickback turns "the oracle flipped a bit" into "the oracle stamped a sign", and `H` reads signs back as bits.

## Walkthrough: what actually happens when you run it

1. **You run** `python crosscheck_numpy.py`.
   **What happens inside:** numpy builds the `(n+1)`-qubit statevector gate by gate and squares the input-bit amplitudes, for all 16 four-bit secrets.
   **What you see:**
   ```text
   secret 1011: {'1011': 1.0}
   secret 110101: {'110101': 1.0}
   all 16 four-bit secrets recovered with probability 1: True
   ```
   **What it means:** probability 1.0, not "high": any other string means a construction bug.

2. **You run** `python bv_lab.py`.
   **What happens inside:** `bv_oracle("1011")` walks `reversed(secret)` because the string is written q3…q0, adding CX from q0, q1, q3 to the ancilla q4; `bv_circuit` wraps any oracle in the pattern; `classical_queries` counts one call per bit.
   Expected (not run here): `{'1011': 100}` with 1 query versus 4 classical queries (6 for `110101`), and a drawing with three CX gates and none from q2.
   **What it means:** the count of queries, not wall-clock time, is the speed-up being claimed.

3. **You run** `python try_it.py`.
   **What happens inside:** try 1 removes `qc.x(n)`, so the ancilla is `|+⟩`; try 2 walks `secret` instead of `reversed(secret)`.
   **What you see:**
   ```text
   no_kickback  numpy {'0000': 1.0}
   unreversed   numpy {'1101': 1.0}
   ```
   **What it means:** without `|−⟩` the flip changes nothing, so no sign is kicked back: all zeros. The second bug returns `1011` reversed, a plausible-looking answer, so tests must check the exact string.

4. **You run** `python solution_bias.py` (the build-task reference for `f(x) = s·x ⊕ b`).
   **What you see:**
   ```text
   secret 1011 bias 0: numpy {'1011': 1.0}
   secret 1011 bias 1: numpy {'1011': 1.0}
   ```
   **What it means:** a constant bias `b` adds an `X` on the ancilla, a global sign on every branch, which no measurement can see. BV recovers `s` but can never learn `b`.

5. **You run** `python -m unittest` → `Ran 10 tests` … `OK (skipped=5)`; the skips need Qiskit.

## Common confusions

- **Q:** BV is exponentially faster. — **A:** It saves `n − 1` queries (4 → 1 for `1011`); a classical machine still reads `s` in linear time. It teaches a pattern, not an advantage.
- **Q:** The ancilla result matters. — **A:** It is never measured; the answer lives in the input qubits after the second `H`.
- **Q:** `{'1101': 1.0}` means the algorithm is unreliable. — **A:** It is deterministic; `unreversed` shows a bit-order bug, not noise.
