# Noise models: how Bell and GHZ results degrade — explained

## The intuition

Up to lesson 11 every simulator was perfect, so a Bell pair gave only `00` and `11`. Real devices leak in three ways: gates are slightly wrong (modelled as *depolarizing* noise: with probability `p` the qubits get randomised), excited qubits relax toward `|0⟩` (*amplitude damping*, the T1 process), and the readout electronics sometimes report the wrong bit (*readout error*, `p01`/`p10`). A noise model is a list of these "channels" attached after each gate.

A statevector cannot describe "randomised with probability p", so the lab switches to a *density matrix* `ρ`, a `2^n × 2^n` matrix that holds both quantum amplitudes and classical uncertainty. Gates act as `UρU†`; noise acts as a weighted sum `ΣKρK†`. Readout is purely classical: a matrix of flip probabilities applied to the final distribution.

**Fidelity** compares `ρ` with the ideal state (before readout); **success** is `P(all 0) + P(all 1)` after readout, what a user sees.

**Analogy:** packet loss on a network path: each hop (gate) loses a little, and long paths lose more.
Where the analogy breaks: damping is biased toward `0`, so errors are not symmetric "drops"; they skew results in one direction.

```text
H -> depol(p1) -> damp | CX -> depol(p2) -> damp(q0), damp(q1)     (noisy_steps)
        rho = dm.run(...)            -> fidelity vs ideal GHZ
        readout_matrix(p01,p10) @ diag(rho) -> probs -> seeded counts
        metrics() -> one JSON line per (n, p2)
```

The one thing to remember: on a noisy device "impossible" outcomes are expected, so a test must compare against the model's prediction, not against perfection.

## Walkthrough: what actually happens when you run it

1. **You run** `python noise_lab.py`.
   **What happens inside:** `noisy_steps` inserts a depolarizing channel (`p1` or `p2` by gate size) and damping after every gate; `dm.run` evolves `ρ`; `readout_matrix` applies `p01 = 0.02`, `p10 = 0.04`; `counts` samples 2000 shots with seed 7.
   **What you see:**
   ```text
   ideal Bell counts: {'00': 998, '11': 1002}
   noisy Bell counts: {'00': 962, '01': 82, '10': 70, '11': 886}
   {"n": 2, "p2": 0.02, "fidelity": 0.9719, "success": 0.925, "p_all0": 0.4818, "p_all1": 0.4433}
   {"n": 4, "p2": 0.0, "fidelity": 0.9673, "success": 0.8622, "p_all0": 0.466, "p_all1": 0.3962}
   {"n": 4, "p2": 0.1, "fidelity": 0.7473, "success": 0.7073, "p_all0": 0.383, "p_all1": 0.3242}
   ```
   **What it means:** about 7.6% of noisy Bell shots are `01`/`10`. Success is below fidelity because readout errors come after the state is prepared. `p_all0 > p_all1` on every line: damping pulls toward `0` and `p10 > p01`. Even at `p2 = 0.0`, GHZ-4 success is only 0.8622: readout and damping alone cost that much.

2. **You run** `python try_it.py`.
   **What you see:**
   ```text
   symmetric_noise       {'p_all0': 0.4454, 'p_all1': 0.4454}
   readout_vs_gate_noise {'readout_only': 0.8145, 'cx_only': 0.9037}
   ```
   **What it means:** remove damping and make readout symmetric, and the skew disappears, which confirms its cause. For a shallow GHZ-4, 5% readout flips (`0.95⁴ = 0.8145`) hurt more than 5% CX noise. Measure before deciding what to mitigate (lesson 13).

## Failure lab: a correct circuit reported broken

1. **Inject:** run the L100-style check, `bell_check` ("only all-0/all-1 may appear"), on counts from the seeded noisy device.
2. **Symptom:** the last lines of `noise_lab.py`:
   ```text
   naive bell_check on ideal counts: True
   naive bell_check on noisy counts: False <- the fault: a correct circuit fails
   ```
3. **Diagnose:** the circuit is correct (ideal counts pass). The 82 + 70 off-pattern shots match the model's prediction (success 0.925 → about 150 of 2000). The test encodes a perfect-device assumption.
4. **Fix:** `solution_tolerant_check.py` makes two statistical checks: observed success must not fall more than `Z = 4` binomial standard errors below `metrics()["success"]` (catches a missing CX), and the all-1 share must match the model (catches a missing `H`, which gives `00` only and success 1.0).
5. **Proof:** the shared build-task test against the naive module, then against the fix:
   ```text
   $ BUILD_TASK_MODULE=noise_lab python -m unittest test_build_task
   AssertionError: False is not true : n=2 seed=0
   FAILED (failures=1)
   $ python -m unittest test_build_task
   Ran 5 tests in 3.428s
   OK
   $ python solution_tolerant_check.py
   …
   GHZ-3, 200 seeds on the noisy model: 200/200 pass
   ```
   The same tests include broken circuits that must still fail, so the fix did not just loosen the test.

## Common confusions

- **Q:** Seeing `01` means the CNOT is broken. — **A:** The model predicts about 7.5% such shots; compare with `success`, not with zero.
- **Q:** Fidelity is what you measure. — **A:** You measure counts; fidelity needs `ρ`, which only a simulator (or tomography) gives. `success` is the observable proxy.
- **Q:** Noise is symmetric. — **A:** `p_all0 0.4818` vs `p_all1 0.4433`: damping and readout skew toward `0`.
